# InterSidera: plan and durable memory

## 1. Status

- Milestone: **M4 User interface and features done 2026-09-09** (M3 done 2026-09-06, M2 done 2026-09-06, M1 done 2026-09-03, M0 done 2026-09-02); next: M5 (plan mode first, per brief l.504).
- Next: M5 "Augmented reality": sensor mode (rear camera video, `deviceorientationabsolute` / `webkitCompassHeading`, `DeviceOrientationEvent.requestPermission()` from a tap, calibration drag and compass accuracy), WebXR mode [S] through Babylon's default XR helper, field-of-view matching, graceful degradation, `sky/math/orientation.ts` with fixture tests, the AR button only in a secure context on Earth with a rear camera and orientation sensors, a time-offset badge, `docs/dev-wsl2.md` phone procedure and the manual checklist in `docs/testing.md`; AR code in lazy chunks and the e2e suite still green. What M5 consumes: `createEngine` already threads `xrCompatible`; the top bar (`ui/shell/TopBar.tsx`) and the `ui` slice take the AR button and its states; `CameraController` owns the gestures the calibration drag must share; `#sky-stage` is the only place a video background may live; the ENU camera basis is `frames.ts::cameraBasis`; every sky mesh keeps ENU geometry under P (ADR-0009), so the XR camera must be parented or followed, never the meshes.
- Specification: `docs/brief.xml` v1.2 (587 lines). Precedence when sections conflict (brief l.11): legal and licensing > security and privacy > api_contract > architecture > [M] functional > non-functional budgets > [S] > style.

How to use this file (brief l.507: it is the durable memory across sessions):

- At the start of every session read sections 1, 6 and 12, then the sections a task touches (3 and 7 before changing a pin, 5 before touching a data URL, 4 and 10 before deviating from the brief).
- Tick checkboxes in section 6 and append one line to section 12 in the same commit as the change. Never rewrite past entries.
- Decide-and-continue for non-blocking questions: record the decision in section 10; questions that need the maintainer go to section 11. Ask the human only for the four blocking cases of brief l.513.
- Every deviation from the brief also gets a row in `docs/backlog.md`; every notable decision an ADR in `docs/decisions/`.

## 11. Questions for the maintainer

1. **Nominatim policy tension.** The brief (l.193, l.318) mandates browser-direct calls that are "never cached or proxied by the API". The OSMF usage policy (<https://operations.osmfoundation.org/policies/nominatim/>) says "If at all possible, set up a proxy and also enable caching of requests", forbids client-side autocomplete (the brief already agrees: submit-only), requires an identifying Referer or User-Agent, and states that the public API may only be used "where the application developer has made a deliberate, informed decision to use it and is directly responsible for complying with this policy" (its "Usage in LLMs" section). Please confirm that browser-direct use is your deliberate decision, or approve a small caching proxy under `/api/v1/geocode` for M4. Until answered: browser-direct, submit-only, <= 1 req/s, Referer meta, attribution, disable toggle. Update 2026-09-09 (M4, verbatim from the policy page): "absolute maximum of 1 request per second"; "Provide a valid HTTP Referer or User-Agent identifying the application"; "If at all possible, set up a proxy and also enable caching of requests"; "Auto-complete search ... you must not implement such a service on the client side using the API"; "LLMs may only suggest this service, if they prominently point to this usage policy and explain the restrictions of use to the user"; the API "must not be built into, offered through, suggested by, or automatically generated by no-code, low-code, or vibe-coding platforms as a generic geocoding ... service". This project was assembled with an LLM under your direction: please read the policy and confirm the deliberate decision (browser-direct as the brief mandates, or the `/api/v1/geocode` proxy) before production use. M4 implements the brief (D97).
2. **HYG version.** The brief pins v4.2; the repository now serves v4.4 at `data/hyg/CURRENT/` (v4.2 remains at `data/hyg/OLDER/`). v4.4 merged duplicated Gliese-Jahreiss stars and relabelled two stars, which can change the HIP-to-name crosswalk row count. Default: v4.4 with the attribution naming it.
3. **Stellarium figure set.** The brief chooses `modern`; Skyfield 1.55's `parse_constellations_json` docstring names `modern_st` (Sky & Telescope figures). Both parse identically. Default: `modern`, with a code comment so nobody "fixes" it.

Update 2026-09-06: a sudo-free alternative works: the Debian packages extracted into `~/.local/pw-libs` and exported through `LD_LIBRARY_PATH`/`FONTCONFIG_PATH` (docs/dev-wsl2.md) ran the suite locally (8/8 on `chromium-desktop` and `chromium-mobile`); `install-deps` stays the supported path (B-24).
