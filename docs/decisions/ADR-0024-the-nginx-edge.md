# ADR-0024: The nginx edge

- Status: Accepted
- Date: 2026-09-28 (M7)

## Context

The brief puts nginx in front of the API and the SPA (l.20: 80/443 in compose; l.96: TLS by nginx with mounted certificates or by an external proxy, both documented; l.370: `frontend/nginx.conf`; l.489: SPA fallback, immutable cache headers for hashed assets, `/api` proxy, security headers, optional TLS), assigns the security headers to nginx (l.274), forbids query strings and coordinates in logs (l.275), and lists the pitfalls (l.556: `index.html` `no-cache`, hashed assets `immutable`, gzip for JSON and the binary catalog). M6 handed over a precise list (ADR-0018 "Consequences"; `docs/architecture.md` l.209 before this milestone): the header set of `frontend/security-headers.ts` byte for byte with `add_header ... always` "at server level", `connect-src 'self' ${SKY_GEOCODER_ORIGIN}`, `upgrade-insecure-requests` and HSTS in the TLS block, `Cache-Control` per asset class, the dotfile and Swagger 404s, `proxy_hide_header Server` and `server_tokens off`, the `ETag` passed through, the SKYS uncompressed, the API's own two headers left as the second policy, a check script diffing the template against the module.

nginx facts verified against the 1.30 sources and documentation (2026-09-27): `add_header` directives are inherited from the previous level "if and only if there are no add_header directives on the current level", so a location that adds `Cache-Control` loses every security header; `ngx_http_add_header` skips an empty value; the stock gzip filter weakens the `ETag` and clears `Accept-Ranges`, and `gzip_static` serves only files nginx owns (never a proxied response); `server ... resolve` inside `upstream` exists since 1.27.3 and needs a `resolver` and a `zone`; the image entrypoint renders `/etc/nginx/templates/*.template` with `envsubst` restricted to the defined variable names matching `NGINX_ENVSUBST_FILTER` whenever the first argument is `nginx`, so `docker run --rm <web> nginx -t` renders and tests; envsubst has no conditionals; OSS nginx cannot omit the `Server` header (`server_tokens off` hides the version only) and never passes an upstream `Server`; `return 301 https://$host$request_uri` drops a non-standard port; request lines above the default `large_client_header_buffers` (8 kB) answer 414; nginx 1.30.4 fixed CVE-2026-42533 (a `map` regex with a non-cacheable variable), and the slim image carries 1.30.5. The e2e contract nginx must satisfy: `csp.spec.ts` asserts the exact seven-header set on `/`, the entry asset, `/manifest.webmanifest`, `/favicon.svg` and the SPA fallback; `url-state.spec.ts` asserts a 304 per catalog on reload with a `transferSize` Chromium reports as the constant 300 for a validated response; every spec asserts zero CSP violations. The seven headers weigh 781 B on the wire.

## Options considered

1. Where the headers live: `add_header` in every `server` and `location` that needs one (the M6 hand-off's "server level"; rejected: a per-class `Cache-Control` in a location would drop the seven there, and duplicating nine directives per scope is the drift the check script exists to prevent), the third-party `headers-more` module (rejected: not in the stock image), `add_header_inherit` (rejected: a newer directive the check refuses on purpose), the nine directives once at http level in a rendered `conf.d/00-headers.conf` with `map` variables for the per-class `Cache-Control` and the TLS-only HSTS (chosen: an empty map value adds no header, so one declaration serves every scope of both modes).
2. Compression: `gzip on` with `gzip_types` for JSON and the binary catalog (the literal reading of l.556; rejected: the API already gzips its JSON (l.105, B-46), on-the-fly gzip weakens the `ETag` and clears `Accept-Ranges` on the SKYS, whose Range 206 and strong `ETag` the client relies on), no compression (rejected: 2.9 MB of text assets), `gzip off` everywhere with `gzip_static on` over the `.gz` siblings the image build writes plus the API's gzip passed through untouched (chosen, backlog B-99); a stored gzip of the SKYS is an API-side change (R115) left as "could, post-M7" (B-84, maintainer question 29).
3. `upgrade-insecure-requests` (the hand-off's wording): kept in the TLS block (rejected: it breaks byte identity with `cspHeader()`, which `csp.spec.ts` and the check script assert; the application issues only relative URLs and an https geocoder; it does not replace HSTS), dropped (chosen, D181).
4. HSTS: in the TLS server block (rejected: a second `add_header` scope), from a `map $https $sky_hsts` at http level (chosen: `max-age=31536000; includeSubDomains` on TLS connections only, an empty value otherwise, never `preload`; behind an external TLS proxy the proxy owns HSTS; maintainer question 39).
5. TLS termination: nginx with mounted certificates (`SKY_WEB_MODE=tls`, `compose.tls.yaml`: a :80 server answering `/healthz` 204 and redirecting everything else, a :443 server with `http2 on`, `fullchain.pem`/`privkey.pem`, `TLSv1.2 TLSv1.3`, the Mozilla intermediate ECDHE list, `ssl_prefer_server_ciphers off`, `ssl_session_timeout 1d`, `ssl_session_cache shared:SkyTLS:10m`, `ssl_session_tickets off`, no `ssl_dhparam`, no stapling, no `ssl_early_data`) and an external proxy (http mode, `web` narrowed to loopback through `compose.override.yaml`, the proxy's address appended to `FORWARDED_ALLOW_IPS` when it is off the compose network): both documented as l.96 asks (chosen, backlog B-101, B-102). The mode switch: two images or two nginx.conf files (rejected), `include /etc/nginx/sky/mode-${SKY_WEB_MODE}.conf` from a rendered template (chosen: envsubst has no conditionals, and the two modes share one `app.conf` body).
6. Upstream: `proxy_pass http://api:8000` (rejected: parse-time resolution, so `nginx -t` fails without the network and a re-created `api` container keeps its old address until `web` restarts), `upstream skyapi { zone skyapi 64k; server api:8000 resolve; resolver 127.0.0.11 valid=10s ipv6=off; resolver_timeout 5s; keepalive 16; keepalive_timeout 4s; }` (chosen: no parse-time DNS, a re-created `api` is picked up within 10 s, `web` never needs a restart); `proxy_intercept_errors on` (rejected: the API's 503 body with `detail` and `Retry-After` drives the splash and the client's retry).
7. Logging: nginx's `combined` format (rejected: the request line with its query string and the client address, l.275), `log_format sky escape=json` with `$time_iso8601 $status $request_method $uri $body_bytes_sent $request_time $upstream_response_time $upstream_http_x_request_id` only (chosen: no `$request`, `$args`, `$request_uri`, referer, user agent, `$remote_addr` or `$http_x_forwarded_for`), `error_log warn` in main and `error_log crit` at http level (request-bound error lines carry the client address and the query string; maintainer question 43 may lower it to `error` for the first weeks), `log_not_found off`, `location = /healthz { access_log off; return 204; }`.
8. Locations: `try_files $uri /index.html` (200 on deep links), `location ~ /\. { return 404; }` (the `dist/.vite/manifest.json` `vite preview` serves today; it also blocks HTTP-01 under `/.well-known/`, R133, maintainer question 41), `location = /api/v1/docs { return 404; }` and `location = /api/v1/docs/ { return 404; }` (the API answers the slash form 307; backlog B-95), `location ^~ /api/` (skips the dotfile regex), `types { application/manifest+json webmanifest; }` (nginx 1.30's `mime.types` has none), `server_tokens off`, `client_max_body_size 16k`, `sendfile on; tcp_nopush on; keepalive_timeout 65s; worker_processes auto`; request lines above 8 kB answer 414 at the edge with the default buffers.
9. The check: an nginx container run inside `make check` (rejected: not hermetic), a hand-maintained comparison in the docs (rejected: the M3/M4 chunk regression showed what an unchecked invariant does), `scripts/check_nginx_headers.mjs` (chosen, backlog B-105): Node built-ins, the module imported through type stripping, envsubst emulated for the two modes and three origins, a tokenizer mirroring `ngx_conf_read_token`, eleven assertion groups and a 19-mutation self-test on every run, run by `make check-delivery` and the CI frontend job.
10. The web-tier set on `/api/*`: strip the seven there (rejected: "every web-tier response carries the seven" is the invariant `check_images.mjs` (e) proves, and a per-location exception is exactly the inheritance trap of option 1), keep them (chosen, D193): the API's `nosniff` and deny policy form the second policy and browsers intersect the two; +781 B per API response (a 304 grows from about 0.3 to about 1.1 kB, a 100-body frame +1.3 %), `url-state.spec.ts` unaffected (the constant 300), `Server: uvicorn` never reaches the client and `Server: nginx` remains (maintainer question 42).

## Decision

Records plan rows D179-D186 and D193 (with backlog B-99, B-100, B-105, B-110 and risks R129-R138).

### D179 Headers once, at http level

`frontend/nginx/templates/00-headers.conf.template` renders into `conf.d/00-headers.conf`: the seven `add_header ... always` with the values of `securityHeaders()` verbatim and `${SKY_GEOCODER_ORIGIN}` in `connect-src`, plus `add_header Cache-Control $sky_cache_control always` and `add_header Strict-Transport-Security $sky_hsts always`; the `$uri` map is `volatile` with non-capturing groups: `/index.html` -> `no-cache`, `~^/assets/` -> `public, max-age=31536000, immutable`, `/favicon.svg`, `/manifest.webmanifest`, `/apple-touch-icon.png`, `~^/icon-(?:192|512)(?:-maskable)?\.png$` -> `public, max-age=3600`, default empty (the API's own `Cache-Control` passes through); no `add_header` below http, no `add_header_inherit`. Backlog B-100 records the template and `sky/` files beside `frontend/nginx.conf`.

### D180 Compression

`gzip off` everywhere; `gzip_static on; gzip_vary on;` in the app server for the build-time `.gz` siblings; the API's gzipped JSON passes through; the SKYS stays uncompressed with its strong content-hash `ETag`, `Accept-Ranges: bytes` and Range 206 through nginx (B-46, B-84, B-99).

### D181 No `upgrade-insecure-requests`; HSTS by map

Byte identity with `cspHeader()`; `map $https $sky_hsts { default ""; on "max-age=31536000; includeSubDomains"; }`, never `preload`; behind an external TLS proxy the proxy owns HSTS (ADR-0018 amendment).

### D182 TLS

`SKY_WEB_MODE=http|tls` selects `include /etc/nginx/sky/mode-${SKY_WEB_MODE}.conf` (`10-site.conf.template`); `mode-http.conf` is one `listen 80 default_server` server including `app.conf`; `mode-tls.conf` is the :80 redirect server (`/healthz` 204, `return 301 https://$host$request_uri`) and the :443 server of option 5 including `app.conf`; the external-proxy variant is http mode with the override and the `FORWARDED_ALLOW_IPS` rule; `$host` drops a non-standard port (R132).

### D183 Upstream and proxy set

The `upstream skyapi` block of option 6 in `nginx.conf`; `location ^~ /api/ { proxy_pass http://skyapi; proxy_http_version 1.1; proxy_set_header Connection ""; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; proxy_hide_header Server; proxy_connect_timeout 5s; proxy_read_timeout 60s; proxy_max_temp_file_size 16m; }`; no `proxy_intercept_errors`; `proxy_hide_header Server` is a statement of intent (nginx never passes an upstream `Server`). The 4 s / 5 s keepalive race with uvicorn is GET-only and retried (R137).

### D184 Privacy logging

The `sky` JSON format of option 7 as the only access log format, `error_log warn` in main and `crit` at http level, `log_not_found off`, `/healthz` without an access record; compose json-file logging `max-size 10m`, `max-file 3` on both services (ADR-0025).

### D185 Locations and tuning

`root /usr/share/nginx/html; index index.html; charset utf-8;` and the locations of option 8 in `frontend/nginx/sky/app.conf`; `/api` without a slash answers 301 `Location: /api/` (nginx's redirect for a proxied prefix location, measured on the stack) and then the API's 404 problem document (plan Q94, whose SPA-fallback premise the measurement corrected); a direct `/assets/x.js.gz` request is served as `application/octet-stream` without `Cache-Control` (Q95); while the API is down nginx answers 504 once (the upstream resolver entry, valid for 10 s, still names the stopped container and `proxy_connect_timeout` 5 s runs out) and then 502 until the new address resolves, both its inline HTML with the seven headers, which the client already retries (`retryOnStatus` 429/502/503/504, `pollHealth`; measured 3.0-3.9 s to the first 200 after `start`, `up -d --force-recreate api` and `restart api` on 2026-09-28); the bare `fastapi run` answers 200 to a 9,035-byte and to a 17,035-byte request line (uvicorn with httptools accepts them; measured 2026-09-28, probe 18), so the 414 above 8 kB exists at the edge only, with the seven headers and `Connection: close`; `docs/api.md` states it.

### D186 `scripts/check_nginx_headers.mjs`

Usage `node scripts/check_nginx_headers.mjs [--root <dir>] [--origin <origin>] [--no-self-test]`; exit 0 with one summary line, 1 with one finding per line (`file:line directive: message`), 2 on a usage error; the rendering model, the tokenizer, the eleven assertion groups (the nine http-level `add_header`, the two maps evaluated on a URI table, the servers per mode, the application locations, no `gzip on`, the tuning directives, the upstream, the log format's forbidden variables, the `webmanifest` type, the rendering checks, the Dockerfile's `ENV SKY_GEOCODER_ORIGIN=` equal to `CSP_GEOCODER_ORIGIN_DEFAULT`) and the 19 mutations are the contract of `.claude/rules/deploy.md`; run by `make check-delivery` (listed in `check`) and the CI frontend job.

### D193 The web-tier set applies to `/api/*` too

Option 10: two policies on `/api` (nginx's seven plus the API's two; browsers intersect), +781 B per API response, `Server: nginx` remains, `Server: uvicorn` never reaches the client; the M6 hand-off sentence "Server hidden by nginx" is corrected to "the upstream `Server` never reaches the client and `Server: nginx` remains" (R134).

## Consequences

- One header declaration serves both modes and every location; adding a header or a cache class is a template edit plus the check script's table, never a `location` edit.
- A change to `frontend/security-headers.ts` fails `make check` until `00-headers.conf.template` mirrors it byte for byte (the script imports the module, so the comparison is against the code, not a copy).
- The SPA fallback answers 200 for any unknown path (R131); a missing `.gz` sibling is silent (R135) and caught by `check_images.mjs` (e); a future `mime.types` with `webmanifest` warns on the duplicate `types` entry (R136); `listen 80` is IPv4-only (R138, probe 28 recorded); the http-level `error_log crit` hides upstream diagnostics (R130, question 43).
- The client sees the seven headers on API responses too; the probe table of `docs/testing.md` "Delivery (M7)" records two `Content-Security-Policy` and two `X-Content-Type-Options` lines on `/api/v1/openapi.json`.
- Recorded deviations: B-99 (no on-the-fly gzip), B-100 (the template and `sky/` files), B-105 (the check script), B-110 (`/healthz` and the web HEALTHCHECK).

## Revisit trigger

- nginx changes the `add_header` inheritance rule or ships `add_header_inherit` in the stock image (then the http-level rule may relax); an API-side stored gzip of the SKYS lands (R115, question 29: `gzip_static` would then apply to nothing new, the API would serve it); the maintainer chooses the external proxy (question 40: HSTS and `FORWARDED_ALLOW_IPS` move) or HTTP-01 certificates (question 41: an explicit `location ^~ /.well-known/acme-challenge/`); `Server: nginx` is judged unacceptable (question 42: only a commercial or patched build removes it); a browser stops intersecting two policies the way the suite assumes; nginx below 1.30.4 in the base (CVE-2026-42533).

## Amendment (M7, 2026-09-28)

Plan D182, D185 and D188 (ADR-0025 amendment), 2026-09-28, the M7 fix pass. The external-proxy rule of option 5 and D182 reads: the api trusts `X-Forwarded-For` from `web`'s fixed address `10.213.0.3` alone, so behind an external proxy the proxy's own address, as nginx sees it, is the rate-limit key unless it is appended after the web address in `compose.override.yaml` (`FORWARDED_ALLOW_IPS: "10.213.0.3,<proxy address>"`), which is done whenever the proxy's header must be honoured, not only when the proxy is off the compose network; the `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for` directive of D183 is unchanged, and the address nginx appends is where uvicorn stops. D185's `Location: /api/` is quoted as measured on the stack: the absolute `Location: http://127.0.0.1/api/` (nginx builds the redirect from `$host`), the path `/api/`. The decision text above is unchanged.

What the two acceptance runs of plan D196 measured on the clones' stacks (`docs/testing.md` "Delivery (M7)", the last column of the probe table); the decision text above is unchanged.

- D185, the down state (the sentence "while the API is down nginx answers 504 once (...) and then 502 until the new address resolves" is superseded).
