# ADR-0023: Container images and the docker gates

- Status: Accepted
- Date: 2026-09-28 (M7)

## Context

The brief asks for a multi-stage backend image with uv (`UV_COMPILE_BYTECODE=1`, `uv sync --locked --no-dev`, a non-root user, a healthcheck on `/api/v1/health`; l.394, l.489), a frontend image with a build stage and nginx (l.489), the bases `python:3.14-slim` with uv from `ghcr.io/astral-sh/uv`, `node:24` and `nginx:stable-alpine` (l.35), images that build for linux/amd64 and linux/arm64 with CI verifying amd64 only (l.270, l.427: `docker/build-push-action`, no push), the budgets `api` < 400 MB and `web` < 50 MB (l.299), no data baked into an image (l.96, l.556) and the definition of done "from a clean clone, `docker compose run --rm api sky-data fetch` then `docker compose up` reaches `ready`" (l.490).

Facts verified on 2026-09-27 and 2026-09-28 (plan Context): `python:3.14-slim` (trixie) is 159,715,328 B unpacked on arm64 (43,744,428 B compressed); the runtime dependency set (`uv export --no-dev`, 48 distributions) installs to 285.3 MB without bytecode (pyarrow 143.1 MB, numpy 54.2, pandas 42.4, uvloop 16.5; 49.2 MB of `.py`, from which the plan estimated 45-55 MB of bytecode before any build; the built `/app/.venv` layer measures 276 MB on arm64 after the trims; vendored test suites 22.9 MB); `nginx:stable-alpine` is 66,039,808 B unpacked (25,981,205 B compressed), over the 50 MB budget before a single asset, with five modules (xslt, geoip, image-filter, njs, acme) and a curl the configuration never uses, while `nginx:stable-alpine-slim` is 15,212,544 B unpacked (6,103,396 B compressed), keeps nginx 1.30.5, `gettext-envsubst` and the template entrypoint, has busybox `wget --spider` and the `gzip_static` module and no curl; `node:24` is Debian bookworm with glibc and the lockfile carries the `-gnu` native binaries. fastapi-cli 0.0.32 reads `[tool.fastapi] entrypoint` from the `pyproject.toml` of the current directory, `fastapi run --port` reads the `PORT` environment variable, uvicorn 0.53.0 reads `WEB_CONCURRENCY` when `--workers` is absent and `FORWARDED_ALLOW_IPS` when the flag is absent; `SKYAPI_WORKERS` is a documented setting no code consumes; an exec-form image `CMD` never expands variables. Docker here: 29.6.2 with the containerd image store, Compose v5.3.1, buildx 0.35.0 with one `default` builder that listed linux/arm64 only on 2026-09-27 (the distro's `/proc/sys/fs/binfmt_misc` holds no `qemu-x86_64` entry), while on 2026-09-28, after Docker Desktop's own restart, a `docker buildx build --platform linux/amd64 --load` succeeded here: the handlers live in Docker Desktop's VM, and nothing was registered by the agent; the CI runner `ubuntu-latest` is Ubuntu 24.04 (Docker 28.0.4, Compose 2.38.2) today and becomes Ubuntu 26.04 with the containerd store by default between 2026-10-19 and 2026-11-19, so a size gate must not depend on the store: `docker image inspect .Size` is the unpacked size on a graphdriver store and the compressed content on a containerd store. The site-packages trims edit uv-installed distributions (their `RECORD` files then disagree), so a runtime import smoke must guard them.

## Options considered

1. Python base: `python:3.14-slim` as the brief says (chosen, `ARG PYTHON_IMAGE`), an alpine Python (rejected: l.35, musl wheels for pyarrow and numpy are not what the lockfile proves), a distroless final stage (rejected: no shell for `docker compose run --rm api sky-data ...` diagnostics and no `useradd`; the size gain sits inside the base, not the venv).
2. Dependency install: `uv sync --locked --no-dev` in two layers with the project built as a wheel by the bundled `uv_build` (`--no-editable`, chosen: `src/` never enters the final image and the wheel is what `pip`-less runtime imports prove); `uv pip install .` (rejected: bypasses the lockfile); an editable sync with `COPY src/` at run time (rejected: a second copy of the sources and a path the loaders depend on).
3. Runtime identity: a fixed uid:gid 1000:1000 (the development host's, so a clean clone's `data/` is writable without a `chown`) with compose `user:` for other hosts (chosen); running as root (rejected, l.489); a user-namespaced or rootless daemon (the operator's choice, out of scope); `nginxinc/nginx-unprivileged` for the web tier (deferred: maintainer question 37; the stock root master with uid-101 workers is the official model).
4. The size reading of l.299: `docker image inspect .Size` (rejected as the gate: store-dependent, see Context), `docker system df` (rejected: shared layers counted once), the per-platform unpacked size measured store-independently as the payload of `docker export` on a created container (chosen: the sum of the tar entries' `size` fields is what the files occupy whatever the store), with the containerd `Unpacked`/`Content` figures, `.Size` and the gzip -9 `docker save` size recorded beside it and never gated. If the api still exceeds 400,000,000 B unpacked on either platform after the acceptable trims, backlog B-111 records both figures, `check_images.mjs --api-reading compressed` gates the compressed figure with that row cited, and maintainer question 36 decides (accept, or authorise dropping bytecode or an alpine Python, both refused here).
5. Size trims, a ladder measured after each rung: (1) nothing from the build enters the final image; (2) pip, `pip-*.dist-info`, ensurepip and `/usr/local/bin/pip*` removed; (3) `pandas/tests`, `pyarrow/tests`, every `numpy/**/tests` removed; (4) the pyarrow Flight, cloud-filesystem (S3, GCS, Azure, HDFS), ORC, C++ header, `.pxd`/`.pyx` and C++ test-module files removed (never `libarrow_substrait/dataset/acero/compute`, `libparquet`, `libarrow`, `libarrow_python*`, `_dataset*`, `_parquet*`, `_fs`, `_csv`, `_json`, `_compute`, `_acero`, `_substrait`: `libarrow_python` links them); (5) the stdlib `idlelib`, `tkinter`, `turtledemo` only within 10 MB of the budget. Forbidden: dropping bytecode (l.489), an alpine Python (l.35), hollowing rich, typer or pygments, `strip`, dependency edits. Rung reached on this tree: 5 (2026-09-28, measured on arm64 pass by pass: rung 2 alone 487,450,579 B, rungs 2-4 395,875,816 B (4,124,184 B under the budget, so the "within 10 MB" rule fired), rungs 2-5 394,364,527 B; rung 5 is kept on both architectures, amd64 measuring 379,547,713 B).
6. Web build stage: `node:24` (bookworm; the lockfile's `-gnu` binaries; `.npmrc` `engine-strict=true` copied), `npm ci --no-audit --no-fund` with a `/root/.npm` cache mount and `NODE_ENV` unset so `tsc -b` has its devDependencies (chosen); an alpine Node (rejected: the `-musl` binaries are a second native set to prove); building on the host and copying `dist/` (rejected: the image must build from a clean clone, l.490). Precompression at build time (`gzip -9 -k -n` plus `touch -r` so `gzip_static` finds equal mtimes; `.js .css .svg .webmanifest .html .json`, never PNG) rather than nginx compressing on the fly (ADR-0024). `dist/.vite/manifest.json` is removed in the build stage (it feeds `scripts/check_chunks.mjs`, which stays in `make build` and the CI frontend job because it needs the repository root).
7. Web serving base: `nginx:stable-alpine-slim` (chosen, backlog B-98) against the brief's `nginx:stable-alpine` (l.35), because l.274 wants nothing unused in the edge and l.299 budgets the image at 50 MB while the brief's tag measures 66,039,808 B unpacked before any asset; the reversal rule (the brief's tag under 40 MB unpacked would let the maintainer reverse) did not fire; maintainer question 35 records the choice.
8. Pins: base image tags (`python:3.14-slim`, `nginx:stable-alpine-slim`, `node:24`), never digests (chosen: tags float like `.node-version` and `.python-version`; `docker compose build --pull` before a release and CI `pull: true` refresh them; the resolved digests are written into the release-checklist record at each acceptance run); uv exact `0.12.19` (the uv Docker guide's own recommendation); hadolint `ghcr.io/hadolint/hadolint:v2.15.1`.
9. Dockerfile lint: hadolint as a pinned multi-arch image over stdin, one line each in CI and `make images` (chosen: the twin rule of `.claude/rules/tooling.md`; ghcr avoids Docker Hub's anonymous pull limits on runner IPs; exceptions inline with `# hadolint ignore=<ids>` and a reason, a `.hadolint.yaml` being invisible to the stdin form), `hadolint/hadolint-action` (rejected: a second pin without a local twin), no lint (rejected: the only automated review of the two Dockerfiles). Plus `docker build --check` (BuildKit's own checks; network, outside `make check`; BuildKit's build checks shipped with Docker 27, so the runner's Docker 28.0.4 is expected to have them; the first remote run confirms it, or the two CI steps are dropped while the Makefile keeps them).
10. Multi-arch proof (l.270): the agent registering QEMU here with a privileged container (refused: maintainer question 38), a single-arch build (rejected: l.270), the static proof plus a native build per side (chosen): no `--platform`, no architecture string outside comments, `uv.lock` carrying cp314 manylinux x86_64 and aarch64 wheels for every native distribution, `package-lock.json` carrying `-linux-{x64,arm64}-{gnu,musl}`, every base publishing amd64 and arm64/v8 manifests; `make images` builds the machine's own architecture (arm64 here), the CI `docker` job builds amd64 after the maintainer's push. Docker Desktop's VM supplied the QEMU handlers on 2026-09-28 (nothing registered by the agent), so a `docker buildx build --platform linux/amd64 --load` also builds here and its size figures are recorded as a cross-check (D178); the amd64 runtime proof stays CI's, `import pyarrow` and `import pandas` segfaulting under `qemu-x86_64`.
11. The gate script: a shell pipeline in the workflow (rejected: no local twin, `wc -c` on a 400 MB stream per store), one Node script identical in CI and `make images` (chosen, backlog B-105): `scripts/check_images.mjs`.
12. The e2e image: a second Dockerfile (rejected: l.370 names one), no image with the debug hook (rejected: the acceptance runs the CI Playwright projects through nginx), `ARG BUILD_SCRIPT=build` with `build:e2e` only through `compose.e2e.yaml` (chosen, backlog B-107; the production build is grepped for `__sky` inside the image build).

## Decision

Records plan rows D169-D178 and D190-D192 (with backlog B-98, B-104, B-105, B-106, B-107, B-109 and B-111 (conditional), and risks R116, R117, R118, R122, R123, R124, R126, R127, R128, R144, R145).

### D169 `backend/Dockerfile`

Two stages on `ARG PYTHON_IMAGE=python:3.14-slim`. Builder: `COPY --from=ghcr.io/astral-sh/uv:0.12.19 /uv /uvx /bin/`, `UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_PYTHON_DOWNLOADS=never UV_NO_PROGRESS=1`, `WORKDIR /app`; layer 1 `uv sync --locked --no-dev --no-install-project` with a `/root/.cache/uv` cache mount and bind mounts of `uv.lock`, `pyproject.toml`, `.python-version`, `README.md`; layer 2 `COPY pyproject.toml uv.lock .python-version README.md ./`, `COPY src/ ./src/`, `uv sync --locked --no-dev --no-editable`; then the rungs 3-4 `RUN` of the ladder (option 5): `pandas/tests`, `pyarrow/tests`, every `numpy/**/tests`, `pyarrow/include`, `pyarrow/includes`, the `.pxd`/`.pyx` files, `libarrow_flight.so*`, `_flight`, `libarrow_python_flight.so*`, `_pyarrow_cpp_tests`, `_s3fs`, `_gcsfs`, `_azurefs`, `_hdfs`, `_orc` and `_dataset_orc` removed from the venv. Final stage: pip, `pip-*.dist-info`, ensurepip and `/usr/local/bin/pip*` removed (rung 2) together with the stdlib `idlelib`, `tkinter` and `turtledemo` packages (rung 5: slim installs no Tk library and nothing imports them), `groupadd --gid 1000 skyapi`, `useradd --uid 1000 --gid 1000 --no-log-init --no-create-home --shell /usr/sbin/nologin skyapi` (passwd and login are in trixie-slim; `adduser` is not), `/data` created and owned by 1000:1000, `WORKDIR /app`, `COPY --from=builder /app/.venv` and `/app/pyproject.toml` only, `ENV PATH=/app/.venv/bin:$PATH PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1 HOME=/tmp SKYAPI_DATA_DIR=/data`, `EXPOSE 8000`, `USER 1000:1000`, the HEALTHCHECK of D172, `ARG GIT_SHA=unknown` and `ARG BUILD_DATE=unknown` declared after the last `RUN`, the OCI labels (`title`, `description`, `source`, `licenses=MIT`, `version=0.1.0`, `revision`, `created`), `CMD ["fastapi", "run", "--host", "0.0.0.0", "--port", "8000"]` and no `ENTRYPOINT`. `backend/.dockerignore` keeps `pyproject.toml`, `uv.lock`, `.python-version`, `README.md` and `src/` in the context and excludes `.venv/`, `.git/`, `tests/`, `typings/`, the caches, `.env*`, the Dockerfile itself.

### D170 Runtime identity

The api runs as uid:gid 1000:1000 (the development host's uid, so a clean clone's `data/` needs no `chown`), `/app` root-owned and read-only, `/data` the only writable path, `HOME=/tmp`; compose adds `user: "${SKY_UID:-1000}:${SKY_GID:-1000}"`, `read_only: true`, `tmpfs: [/tmp:size=64m,mode=1777]`, `cap_drop: [ALL]` and `security_opt: [no-new-privileges=true]` (ADR-0025). The bootstrap writes `manifest.json`, `cache/**`, `.bootstrap.lock` and `.part` files into `DATA_DIR` only.

### D171 Worker count

The image `CMD` carries no `--workers` (an exec-form CMD never expands a variable); compose passes `command: ["fastapi", "run", "--host", "0.0.0.0", "--port", "8000", "--workers", "${SKYAPI_WORKERS:-1}"]`, interpolated from `.env` at parse time; outside compose the image honours uvicorn's own `WEB_CONCURRENCY`; `PORT` is never set (`fastapi run` reads it as its port); `Settings.workers` stays informational (ADR-0003 amendment).

### D172 The api healthcheck

The same values in the Dockerfile and compose: `--interval=30s --timeout=5s --start-period=300s --start-interval=5s --retries=3`, `CMD ["python", "-c", "import sys, urllib.request as u; sys.exit(0 if u.build_opener(u.ProxyHandler({})).open('http://127.0.0.1:8000/api/v1/health', timeout=4).status == 200 else 1)"]`: a 503 raises `HTTPError` and exits 1; `ProxyHandler({})` ignores an `HTTP(S)_PROXY` set for `sky-data fetch` (R128); the slim image has no curl. A success ends the start period at once, failures inside it do not count, so `unhealthy` comes at the earliest about 390 s after start; Docker never restarts an unhealthy container (ADR-0008 amendment, D200).

### D173 Image-size reading and the trim ladder

The figure of record for l.299 (400,000,000 B and 50,000,000 B, decimal) is the per-platform unpacked size measured as the `docker export` payload (option 4); recorded beside it and never gated: containerd `Manifests[].ImageData.Size.Unpacked` and `Size.Content` (the Docker API `GET /images/<ref>/json?manifests=true` over the unix socket, at the daemon's own API version), `docker image inspect .Size`, the compressed size (`docker save` through gzip -9). The ladder of option 5 is applied rung by rung and the rung reached is recorded (5); B-111 is the conditional fallback and did not trigger. Figures of the milestone commit (export payload, 2026-09-28): api 394,364,527 B on arm64 (`make images`, 98.6 % of the budget) and 379,547,713 B on amd64 (the local QEMU build, a cross-check; the CI `docker` job prints the runner's figure on the first remote run); web 16,829,111 B on arm64 (33.7 %) and 16,375,691 B on amd64 (local QEMU build; the runner's figure on the first remote run). Beside them, arm64 / amd64: containerd `Unpacked` 435,613,696 / 420,720,640 B (api) and 19,329,024 / 18,882,560 B (web), `Content` 126,535,102 / 129,977,856 B and 7,644,631 / 7,287,812 B, `docker image inspect .Size` 126,535,958 / 129,978,712 B and 7,645,487 / 7,288,668 B (within 1 kB of the compressed content on this containerd store, as option 4 says), `docker save` through gzip -9 125,733,540 B (api arm64) and 7,627,504 B (web arm64) from the gate's record lines. The amd64 api is 14,816,814 B smaller than the arm64 one (the debian base layer 87.6 MB against 110 MB), so R117 did not materialise.

### D174 `frontend/Dockerfile` build stage

`node:24`, `WORKDIR /app`, `COPY package.json package-lock.json .npmrc ./`, `npm ci --no-audit --no-fund` with a `/root/.npm` cache mount, `COPY . .`, `ARG BUILD_SCRIPT=build`, `npm run "$BUILD_SCRIPT"`, the `__sky` grep failing the build when `BUILD_SCRIPT=build`, `rm -rf dist/.vite`, the `.gz` siblings (`gzip -9 -k -n` + `touch -r`). `frontend/.dockerignore` excludes `node_modules/`, `dist/`, `dist-*/`, `e2e/`, the Playwright and coverage output, `.vite/`, `*.log`, `.env*`, the Dockerfile (backlog B-109; `tsc -b` survives an absent `e2e/`).

### D175 Web serving stage

`nginx:stable-alpine-slim` (B-98); `rm -f /etc/nginx/conf.d/default.conf && rm -rf /usr/share/nginx/html/*`; `COPY nginx.conf /etc/nginx/nginx.conf`, `COPY nginx/templates/ /etc/nginx/templates/`, `COPY nginx/sky/ /etc/nginx/sky/`, `COPY --from=build /app/dist/ /usr/share/nginx/html/`; `ENV SKY_GEOCODER_ORIGIN=https://nominatim.openstreetmap.org SKY_WEB_MODE=http NGINX_ENVSUBST_FILTER=^SKY_ NGINX_ENTRYPOINT_QUIET_LOGS=1` (envsubst substitutes defined variables only, so the image defaults keep the templates renderable and compose overrides them from `.env`); `EXPOSE 443` (80, the ENTRYPOINT, CMD and `STOPSIGNAL SIGQUIT` are inherited); `HEALTHCHECK --interval=30s --timeout=3s --start-period=10s --start-interval=2s --retries=3 CMD ["wget", "-q", "--spider", "http://127.0.0.1:80/healthz"]` (backlog B-110); the same `ARG`/`LABEL` block as the api. Root master, workers uid 101 (maintainer question 37).

### D176 Pins

Base tags, never digests; uv exact `0.12.19`; hadolint `ghcr.io/hadolint/hadolint:v2.15.1`; `docker compose build --pull` before a release and CI `pull: true`; the resolved base digests are recorded in the release-checklist record at each acceptance run (the index digests the local builds of 2026-09-27/28 resolved, the arm64 and the emulated amd64 build alike: `python:3.14-slim@sha256:51dafde81dbdb6ebde285137a295cf18a47ca95234fe388a343719cb97305b3d`, `node:24@sha256:64af3819f9275802414d7cdc38c27e9d82bd564dec4d4da87d008255d36c63b4`, `nginx:stable-alpine-slim@sha256:32463212baf0e7d91aded2e9b843a4f2b9e017804b8c9d5bae7b51dcef64389c`, `ghcr.io/astral-sh/uv:0.12.19@sha256:04d046b13e60d6bcec73cbc5e1cad25d680dea90c8573340950a0ac2d1aef424`; the acceptance run's `docker compose build --pull` re-resolves them and the release checklist records the digests of each deployment); the nginx floor 1.30.4 (CVE-2026-42533) is noted in `frontend/nginx.conf`.

### D177 hadolint and `docker build --check`

`docker run --rm -i ghcr.io/hadolint/hadolint:v2.15.1 < backend/Dockerfile` (and `frontend/Dockerfile`) at the default failure threshold, one line each in the CI `docker` job and `make images`; exceptions only inline with a reason (backlog B-106); `docker build --check -f <Dockerfile> <context>` beside it (network; outside `make check`).

### D178 Multi-arch proof

Static (no `--platform`, no architecture string outside comments, the lockfiles' wheel and binary sets, every base publishing amd64 and arm64/v8), the native arm64 build here through `make images`, amd64 by the CI `docker` job after the maintainer's push (l.270 "CI verifies amd64 only"); the agent registers no QEMU handler (question 38 asked whether it may; since Docker Desktop's VM supplied the handlers by itself on 2026-09-28, the question becomes whether local emulated figures may stand in for CI's before the push). Cross-check of 2026-09-28: `docker buildx build --platform linux/amd64 --load` built both images here (api 71.3 s, web 278.6 s), export payloads api 379,547,713 B and web 16,375,691 B; the web image passes `nginx -t` in both modes and renders its templates under emulation; `import fastapi, skyfield.api` and `import numpy` pass on the api image while `import pyarrow` and `import pandas` segfault under `qemu-x86_64` whatever `ARROW_USER_SIMD_LEVEL` (an emulator limit, not an image defect), so the amd64 runtime proof stays CI's. The runner's amd64 figures are printed by the first remote run of the CI `docker` job (release checklist item 12).

### D190 Makefile targets

`check: check-backend check-frontend check-i18n check-delivery check-contract`; `check-delivery` runs `scripts/check_nginx_headers.mjs` (hermetic); `images` = hadolint x2, `docker build --check` x2, `docker compose config -q` on the base file and both overlays, `docker compose build`, `node scripts/check_images.mjs --api intersidera-api:local --web intersidera-web:local` (the CI docker job's twin, outside `make check`); `up` = a warning when `.env` is absent (code defaults: de441 and an auto-fetch of 3.3 GB inside the container), then `docker compose up --build --detach --wait --wait-timeout 420` and the URLs; `down` = `docker compose down` (never `-v`); `HADOLINT` and `COMPOSE` variables; no `--env-file` on `up` or `images` (compose reads the project `.env` itself). Backlog B-104.

### D191 The CI `docker` job

Independent (`needs` none), `if: github.event_name != 'schedule'`, `timeout-minutes: 20`; checkout, setup-node; hadolint x2; `docker build --check` x2; `docker/setup-buildx-action@v4`; `docker/build-push-action@v7` x2 with `context`, `file`, `platforms: linux/amd64`, `push: false`, `load: true`, `pull: true`, `provenance: false`, `tags: intersidera-api:ci` / `intersidera-web:ci`, `build-args: GIT_SHA=${{ github.sha }}`, `cache-from: type=gha,scope=<img>`, `cache-to: type=gha,scope=<img>,mode=max`; `docker compose config -q` on the base file (no `.env` in CI: the files must parse on their defaults alone) and both overlays; `node scripts/check_images.mjs --api intersidera-api:ci --web intersidera-web:ci`; no artifact upload; `permissions: contents: read` unchanged. The frontend job gained `node ../scripts/check_nginx_headers.mjs` after `check_i18n.mjs`. Backlog B-105.

### D192 `scripts/check_images.mjs`

Identical in CI and `make images`; checks (a) the store line (`docker info --format '{{.Driver}} {{.ServerVersion}}'`); (b) `docker image inspect` fields (`Os`, `Architecture`, a non-root `Config.User` on the api, the HEALTHCHECK present with the documented timings, the OCI labels, the exposed ports, the api's exec-form `Cmd` without an `Entrypoint`); (c) the export-payload gate per image with `.Size`, `Unpacked`, `Content` and the compressed size printed on one record line per image; (d) `docker run --rm <web> nginx -t` in http and tls mode (a throwaway EC pair from `openssl`); (e) the web runtime on `127.0.0.1:18080` (`/`, `/nowhere` with and without a query string, `/index.html`, `/manifest.webmanifest`, `/favicon.svg`, the entry script and stylesheet, `/api/v1/docs` and `/api/v1/docs/` 404, `/.vite/manifest.json` 404, `/healthz` 204: the seven headers equal to `securityHeaders({ geocoderOrigin })` on every response, the Cache-Control classes, `Server: nginx`, no HSTS on plain HTTP, `Content-Encoding: gzip` and `Vary: Accept-Encoding` under `Accept-Encoding: gzip` on the HTML, the script, the stylesheet and the manifest, an `ETag` on the document; `nginx -T` with `SKY_GEOCODER_ORIGIN=https://geocoder.example.org` rendering that origin into `connect-src`); (f) the api without data on `127.0.0.1:18000` (`SKYAPI_AUTO_FETCH=false`, `SKYAPI_EPHEMERIS=de440s.bsp`, `--read-only` with tmpfs `/tmp` and `/data` mounts, as compose runs it): 503, `Retry-After: 5`, `Cache-Control: no-store`, `nosniff`, the API's policy, `status: starting`, the remedy in `detail`; (g) the image's healthcheck command turning that 503 into `unhealthy`, run with shortened timings (`--health-start-period 1s --health-interval 2s --health-retries 1`; the production timings are asserted in (b)); (h) `id -u` = 1000; (i) the runtime imports and `sky-data status` exit 0; (j) `import pip` fails and `uv` is absent. Docker through `execFileSync` and, for the two tar streams, `spawn`, always with argument arrays; probes through `node:http`; containers `isd-check-<pid>-*` removed in `finally` and on SIGINT/SIGTERM; exit 0/1/2; `--static` = (a)-(c); `--api-reading unpacked|compressed`; `--self-test` builds GNU and pax tars with a long name, an empty file, a symlink and a hard link and asserts the parsed payload in four chunkings. The end-to-end run on the built images, `make images` on 2026-09-28 (arm64, `docker: overlayfs 29.6.2`): `image intersidera-api:local: export 394364527 B (394.4 MB of 400.0 MB, 8868 files); inspect .Size 126535958 B; unpacked 435613696 B; content 126535102 B; compressed 125733540 B; linux/arm64; user 1000:1000; healthcheck yes`, `image intersidera-web:local: export 16829111 B (16.8 MB of 50.0 MB, 589 files); inspect .Size 7645487 B; unpacked 19329024 B; content 7644631 B; compressed 7627504 B; linux/arm64; user root; healthcheck yes`, `check_images: checks (a)-(j), 245 assertions, 0 findings` (the `unhealthy` verdict of (g) reached 7.0 s after `docker run`); the first remote run of the CI `docker` job prints the same two record lines for linux/amd64.

## Consequences

- Every image builds from a clean clone with `docker compose build`; `docker history` shows no data layer; `sky-data fetch` and `sky-data update` run as `docker compose run --rm api sky-data ...` because the image has no ENTRYPOINT.
