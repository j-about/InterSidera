# ADR-0020: Accessibility tooling: `@axe-core/playwright` in the e2e suite and Lighthouse through a pinned `npm exec`

- Status: Accepted (maintainer question 23 decided-and-continued; a devDependency for Lighthouse is the one-line alternative if preferred)
- Date: 2026-09-23 (M6)

## Context

The brief requires WCAG 2.2 AA for the UI chrome (l.290) and a "Lighthouse accessibility score >= 90 on the main view" among the acceptance budgets (l.580); its frontend dependency list (l.405) names no accessibility tool and says "Nothing else without an ADR"; a root `npx` is forbidden by the tooling rules (it fetches a floating version). Maintainer question 23 (approve `@axe-core/playwright` for M6?) is unanswered, so the decision is taken with the recorded default. Facts measured in the M6 research (plan Context and the a11y design report): Lighthouse 13.5.0 (Apache-2.0) as a package adds 116 packages and 183 MB (`@sentry/node` 45 MB, `lighthouse` 21 MB, `@paulirish/trace_engine` 17 MB, `puppeteer-core` 12 MB); `@axe-core/playwright` 4.13.0 (MPL-2.0, peer `playwright-core >= 1.0.0`) adds nothing new because `axe-core` 4.13.0 is already installed through `eslint-plugin-jsx-a11y`; Lighthouse runs headless on this WSL against the Playwright Chromium with the SwiftShader flags in 11-16 s per URL and scored 0.93 mobile / 0.94 desktop on the unfixed tree, the failures being `definition-list` and `dlitem` in `ui/time/TimeReadout.tsx`; on WSL chrome-launcher takes its Windows branch and hands Chromium a `C:\Users\...` profile path that Chromium creates relative to its cwd and nobody removes; without `--enable-error-reporting=false` the CLI prompts for Sentry on a TTY; chrome-launcher spawns Chrome `detached` (its own process group), so killing the CLI's group leaves Chrome alive; `color-contrast` is incomplete on the translucent surfaces in every state, so the M4 token computation is the only contrast evidence.

## Options considered

1. `lighthouse` as an exact-pinned devDependency (the research design's first recommendation). Rejected for M6: 183 MB and 116 packages in `node_modules` and `npm ci` on every job for a tool that runs once per audit; `@sentry/node` and `ws ^7` enlarge the `npm audit` surface (ADR-0019). Offered to the maintainer as the one-line alternative (question 23).
2. Lighthouse through `npm --prefix frontend exec --yes --prefer-offline --package=lighthouse@13.5.0 -- lighthouse ...` from `scripts/lighthouse.mjs`. Chosen: an exact pin in the npx cache, never a floating root `npx` (the same pattern as `uv tool run pip-audit==2.10.1`), `--prefer-offline` so a warm cache needs no registry round trip (a transient ECONNRESET on that check lost one run at M6) while a cold cache still fetches it.
3. The Lighthouse Node API with chrome-launcher (one Chrome for every URL). Rejected: a root script would import `lighthouse` from `frontend/node_modules` and re-implement the desktop preset; the CLI carries the presets and the JSON contract.
4. A manual score from Chrome DevTools on the host GPU. Rejected: not reproducible; the WSL headless run reproduced 0.93/0.94 eight times.
5. axe only (no Lighthouse number) or Lighthouse only (blind to the sheet, dialog, tab and AR states, and vacuous on contrast). Rejected: both, since they share axe-core 4.13.0 a green per-state axe suite predicts the Lighthouse score.
6. A jest-axe style check under Vitest. Rejected: jsdom has no layout, so `target-size` and `color-contrast` cannot run there.

## Decision

Records plan rows D155 and D156 (with backlog B-88 and B-90, risks R100, R101 and R108, Q66 and Q74).

- `@axe-core/playwright ^4.13.0` joins `frontend/package.json` `devDependencies` (MPL-2.0 tooling in an MIT project; the caret cannot cross an axe-core minor, so the rule set is pinned to 4.13.x and the version is recorded with every score, R108). `frontend/e2e/axe.ts` is the single home of `AxeBuilder`: `axeScan(page, { exclude?, disable?, experimental? })` runs `withTags(['wcag2a', 'wcag2aa', 'wcag21a', 'wcag21aa', 'wcag22aa', 'best-practice'])` plus `experimental` on request and excludes `[data-sky-labels]` (the engine-owned label overlay); `expectNoAxeViolations(page, name, ...)` asserts the violation list equals `[]`; `color-contrast` stays enabled (incomplete-only on the translucent surfaces; `styles/tokens.test.ts` is the contrast gate, plan D157 C8). Scans run in `e2e/a11y.spec.ts` (main, each tab, the search list, About, the time editor, night level 1, the dark and light schemes emulated, `night=0.3` as incomplete-only with the annotation `axe night=0.3 (B-90)`, one experimental scan filtered to `label-content-name-mismatch`), in the new `e2e/axe.spec.ts` on both projects (main, sheet expanded, tabs, About; on the phone the 320 px reflow and the SC 2.4.11 keyboard-collapse assertions) and in three states of `e2e/ar.spec.ts`. `a11y.spec.ts` is three `test()` blocks (the mechanics; the eight light-scheme scans; the five night and scheme scans) so each stays well under the 180 s cap (the integrator's Step F decision after one timeout under five SwiftShader workers: a two-way cut left the axe block at 168 s, 93 % of the cap, the three-way cut keeps the longest block near 56 % under `--repeat-each=2` on five workers).
- `scripts/lighthouse.mjs` (Node built-ins only) spawns the pinned CLI once per URL with `--only-categories=accessibility --output json --output html --output-path reports/lighthouse/<name> --quiet --max-wait-for-load 90000 --enable-error-reporting=false --chrome-flags="--headless=new --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist --user-data-dir=<mkdtemp>"` (the profile directory is the last chrome flag because the last occurrence of a switch wins; the child's cwd is a temporary directory; both are removed in `finally`; `CHROME_PATH` defaults to `@playwright/test`'s `chromium.executablePath()`; `--extra-chrome-flags` passes more through) over six URLs (main, main `--preset=desktop`, `night=1`, night desktop, `lang=fr&sel=hip:32349`, `/`), asserts `lhr.categories.accessibility.score >= --min-score` (default 0.9) and an empty `runWarnings`, prints name, score, failing audits and the axe-core version, and writes `reports/lighthouse/summary.json` (`/reports/` gitignored; a `--only` subset writes `summary-only.json`). The verdict is the run's own: the report pair is removed before the CLI starts, a non-zero exit or the 5 min timeout fails the run whatever a report says, and on a timeout the detached process group is killed and the Chrome processes holding the profile are found through `/proc` and killed before the profile is removed (Ctrl-C does the same). `make lighthouse` runs it (the API on 8000 and the e2e preview on 4173 first); the CI e2e job restarts both in the background after Playwright, waits on `/health`, runs the script as a gate (>= 0.9, should) and uploads `reports/lighthouse` with `if: ${{ !cancelled() }}`.

## Consequences

- Scores of record (area C final report, section 3.1; Lighthouse 13.5.0, axe-core 4.13.0, HeadlessChrome/153 on SwiftShader): 0.93 / 0.94 before the M6 fixes, 1.00 on all six URLs after them, `runWarnings []`, 90 s for the six runs; the four non-night scores are light-scheme scores (headless Chrome renders the light scheme by default), the two night URLs override the scheme through `data-mode`.
- axe: zero violations in every scanned state on both projects; at the night floor `color-contrast` reports 0 violation nodes and 47 incomplete nodes (B-90, the recorded exception: night dimming below level 1 fails SC 1.4.3 by user choice).
- axe counts `aria-hidden` text as visible for the label-in-name rule, which is why the Switch's state word became an `aria-hidden` sibling outside the button (D157 C4) rather than the plan's in-button span.
- The CI e2e job polls `/health` for HTTP 200 before the Lighthouse step, not for the literal `ready`: the CI data set carries no MPC tables and answers `degraded` (contract step summary).
- A Lighthouse run on the x86-64 GitHub runner is unproven until the first push (R100); the profile leak (R101) is guarded by the temp cwd and `git status --porcelain` staying empty after `make lighthouse`.
- `make lighthouse` on this WSL needs the Playwright browser variables (`LD_LIBRARY_PATH`, `FONTCONFIG_PATH`, `FONTCONFIG_FILE`, `docs/dev-wsl2.md`).
- Backlog B-88 records the two additions beyond l.405 (the devDependency and the pinned `npm exec` tool).

## Revisit trigger

- Question 23 answered the other way (then `lighthouse` becomes an exact-pinned devDependency and the script drops `exec`); an axe-core minor (bump the caret deliberately and re-record the scores); Lighthouse dropping the CLI or changing the `lhr` shape; a runner where SwiftShader cannot boot the sky (then the gate becomes a record).
