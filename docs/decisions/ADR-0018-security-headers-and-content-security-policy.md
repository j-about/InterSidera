# ADR-0018: Security headers and the Content-Security-Policy, defined once and served before nginx exists

- Status: Accepted
- Date: 2026-09-23 (M6; the nginx template that applies the same values arrives at M7)

## Context

The brief requires "strict Content-Security-Policy without inline scripts, `connect-src` limited to the app origin plus the configured geocoder; standard security headers set by nginx; CORS limited to the app origin" (l.274), no trackers, third-party scripts or server-side storage of requests (l.275), and the acceptance rows "no requests to origins other than the app and the configured geocoder" (l.580) and no browser storage (l.581). nginx, the Dockerfiles and compose arrive at M7, so at M6 the headers had to be defined in one place, served by the dev and preview servers, proven by tests and handed to M7. Facts measured in the M6 research (plan Context): the shipped bundle has no `eval`, `new Function`, `WebAssembly`, inline scripts or styles, `innerHTML`, `data:`/`url(`/`@font-face` in CSS; `createObjectURL` serves the PNG download anchor only; the camera `<video>` takes a `MediaStream` through `srcObject`; Vite 8's `preview.headers` and `server.headers` apply to `index.html` (SPA fallback included) and the assets; `@vitejs/plugin-react` 6 injects the Fast Refresh preamble as an inline module script in `vite dev`; Chromium 153 warns on the `Permissions-Policy` feature `bluetooth`; Swagger UI loads jsdelivr scripts, a stylesheet and one inline script; the dev and preview proxies pass `/api` upstream headers unchanged, so only the API itself can put `nosniff` on `/api` in those stacks.

## Options considered

1. `<meta http-equiv="Content-Security-Policy">` in `index.html`. Rejected: it cannot carry `frame-ancestors`, cannot know the geocoder origin of the deployment, would conflict with the dev nonce and covers the HTML document only; headers cover every response.
2. A report endpoint (`report-to` / `report-uri`, or a `Content-Security-Policy-Report-Only` twin). Rejected: the brief forbids storing requests (l.275) and a report endpoint is exactly that; violations are proven in CI instead by the `cspViolations` fixture (plan D153).
3. Trusted Types (`require-trusted-types-for 'script'; trusted-types 'none'`). Deferred (plan D154, Q69): the research probe ran clean on the desktop and on the phone emulation (security design report, section 1b), but Baseline 2026 enforcement reaches Firefox and Safari while the suite proves Chromium only; revisit after a `webkit` run and a Firefox pass. No `Report-Only` header either (option 2).
4. Self-hosting `swagger-ui-dist` so the docs page needs no `cdn.jsdelivr.net`, or a `SKYAPI_DOCS_ENABLED` switch. Rejected (plan D150): a twelfth `SKYAPI_` variable breaks the closed list of l.397 and self-hosting adds a package for a page production hides at the edge; the docs page keeps its own relaxed policy in development.
5. `Cross-Origin-Embedder-Policy`. Not set: nothing needs cross-origin isolation.
6. `HEAD` support on `/health` for probes. Dropped (Q80): a `head` operation is a contract change; `HEAD` answers 405.

## Decision

Records plan rows D147, D148, D149, D150, D154 and D166 (with backlog B-85, B-87, B-95 and risks R102, R103, R104, R111).

- One module, `frontend/security-headers.ts` (Node side, tested by `security-headers.test.ts`): `CSP_GEOCODER_ORIGIN_DEFAULT`, `geocoderOriginFromEnv(env)` (the value must equal its own `new URL(v).origin`, http(s) only), `cspHeader({ geocoderOrigin, nonce? })` and `securityHeaders(...)`. `vite.config.ts` serves the production set through `preview.headers` and, in interactive dev only, the same policy with a per-process `randomBytes(16)` nonce on `script-src` and `style-src` through `server.headers` plus `html: { cspNonce }`. The geocoder origin comes from `SKY_GEOCODER_ORIGIN` (D148, B-85: a web-tier variable outside the `SKYAPI_` list, read through `loadEnv` with the prefix filter only when the config serves pages, `process.env` winning, default Nominatim; it must equal the origin of `SKYAPI_GEOCODER_URL`).
- Production values, served on `/`, the entry asset, `/manifest.webmanifest`, `/favicon.svg` and the SPA fallback: `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; connect-src 'self' https://nominatim.openstreetmap.org; manifest-src 'self'; worker-src 'none'; media-src 'none'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`; `Permissions-Policy: camera=(self), geolocation=(self), gyroscope=(self), magnetometer=(self), accelerometer=(self), xr-spatial-tracking=(self), microphone=(), payment=(), usb=(), serial=(), hid=(), midi=(), display-capture=(), picture-in-picture=(), publickey-credentials-get=(), idle-detection=()` (16 features, no `bluetooth`); `Referrer-Policy: strict-origin-when-cross-origin` (the `<meta name="referrer">` stays); `X-Content-Type-Options: nosniff`; `X-Frame-Options: DENY`; `Cross-Origin-Opener-Policy: same-origin`; `Cross-Origin-Resource-Policy: same-origin`. HSTS (`max-age=31536000; includeSubDomains`, never `preload` without the maintainer), `upgrade-insecure-requests` and `Cache-Control` belong to the nginx TLS block at M7.
- Dev differs by the nonce and by `worker-src blob:` (the integrator's Step F decision): Vite 8.3.0's dev client polls for a server restart from a `SharedWorker` built on a `blob:` URL (`client.mjs` `waitForSuccessfulPing`, l.1084-1104), which `'none'` blocked so a tab never reconnected (measured 2026-09-23, area B final report, section 3.4); production keeps `worker-src 'none'`. After a dev-server restart the client reconnects and Vite reloads the tab with the new nonce (R103; re-measured at Step F: `[vite] connected.` 4.7 s after the restart and 0 violations in every phase once the browser trusts the dev certificate for the poller's WebSocket).
- The API (D149, `backend/src/skyapi/middleware/headers.py`, pure ASGI, placed outside `CORSMiddleware`, ADR-0017) appends when absent `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'` on every response (preflights, problem documents, 304s and the `/api/v1/docs/` redirect included), and on GET `app.docs_url` alone (a 405 problem document on the same path stays strict) the relaxed `DOCS_POLICY`: `default-src 'none'; script-src https://cdn.jsdelivr.net 'unsafe-inline'; style-src https://cdn.jsdelivr.net 'unsafe-inline'; img-src https://fastapi.tiangolo.com data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'` (never `sandbox`). `unhandled_exception_handler` adds the same two headers beside `X-Request-Id` (Starlette's error layer is outermost); `create_app` passes `swagger_ui_oauth2_redirect_url=None` so FastAPI registers no root-level `/docs/oauth2-redirect` page (its inline script violated the strict policy; the route was `include_in_schema=False`, so `make types` is unchanged). B-87 records the deviation from "set by nginx".
- Proof: `e2e/csp.spec.ts` on both CI projects asserts (a) the exact header set on the five responses with `connect-src` equal to `new URL(meta.geocoder.url).origin` (R104), (b) a negative control (one `data:` image -> exactly one `{ effectiveDirective: 'img-src', blockedURI: 'data' }` record and one Chromium refusal line, then reset) and (c) the PNG export against the real engine; the `cspViolations`, `foreignRequests` and `noStorage` auto fixtures of `e2e/fixtures.ts` guard every spec; `security-headers.test.ts` asserts no `'unsafe-inline'`/`'unsafe-eval'`, every directive once, the nonce on two directives only and `worker-src` per variant; `tests/api/test_middleware.py` (nine header test functions at l.183-296, 14 parametrised cases, including the stack order, a 304, a preflight, a refused preflight, a 405, a 429, a 503 and the docs page) and `tests/api/test_problems.py` (the 500 path). The 16-feature `Permissions-Policy` draws no console line on either project (R102 closed) and the preflight test proves the placement (R111 closed).

## Consequences

- The M7 hand-off list: the nginx template applies the same values with `add_header ... always` at server level (`connect-src 'self' ${SKY_GEOCODER_ORIGIN}`), HSTS and `upgrade-insecure-requests` in the TLS block, `location ~ /\. { return 404; }` (the `dist/.vite/manifest.json` that `vite preview` serves today), `location = /api/v1/docs { return 404; }` (B-95; the container still serves it inside the compose network), `proxy_hide_header Server` and `server_tokens off` (D166), `Cache-Control` (`index.html` `no-cache`, `/assets/*` `public, max-age=31536000, immutable`, favicon and manifest `max-age=3600`), the web image copying `dist/` without `.vite/`, `FORWARDED_ALLOW_IPS=<compose network>` for the rate-limit key, the production `SKY_GEOCODER_ORIGIN` equal to the origin of `SKYAPI_GEOCODER_URL` (a release-checklist item), and a `scripts/check_nginx_headers.mjs` diff against `cspHeader()`. On `/api` nginx then adds the web-tier set beside the API's own two headers: the browser intersects the two policies.
- The manual dev-server checks of plan D165 (area B final report, section 3.4: `vite dev` on 5173 with the API up) are clean at boot, on a Fast Refresh edit and on a Tailwind edit under the nonce policy; the HMR reconnect was the one refusal (`worker-src`, `blockedURI: 'blob'`) before the `worker-src blob:` dev variant landed.
- A 500 problem document carries no CORS headers and nginx adds none: the app only calls relative URLs, so a cross-origin client sees a network error and the retry policy handles it (documented in `docs/api.md`).
- New origins (a self-hosted geocoder, ADR-0015) are configuration on both tiers, never a code change; a new browser feature the app uses must be added to `Permissions-Policy` and run once through both CI projects with a clean console before it is called proven.

## Revisit trigger

- Trusted Types once `webkit` and a Firefox pass are green (Q69); a new origin or a new worker (the `worker-src 'none'` production value is the first thing a WebGPU or Babylon feature would trip); a Vite release changing the dev client's reconnect mechanism; FastAPI gaining a per-environment docs toggle (then B-95 could close without nginx).
