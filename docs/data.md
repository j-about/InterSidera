# Data sources

Status: written at M1. The registry is `backend/src/skyapi/data/data_files.toml` (inside the package, ADR-0005); this document mirrors it. The brief's list (`docs/brief.xml` l.303-334) was verified against the live sources on 2026-09-02 and 2026-09-03; the table below is the corrected version and supersedes the brief where they differ (see `docs/plan.md` section 5 for the evidence).

Every file is downloaded by `sky-data fetch` into `DATA_DIR` (`SKYAPI_DATA_DIR`, default `../data` relative to `backend/`) with SHA-256 verification and resumable downloads; none is committed to the repository. Sizes are exact byte counts observed on 2026-09-03 unless marked approximate.

## Licensing policy (brief l.323-329)

- Third-party data is never committed. Allowed in git: test excerpts under 1 MB in `backend/tests/fixtures/excerpts/` with a source and license header and a `THIRD_PARTY_NOTICES.md` entry; the small factual CSVs authored for this project; machine-generated fixtures holding JPL Horizons values.
- `THIRD_PARTY_NOTICES.md` (generated from the registry at M1) lists every dataset with source URL, version or fetch date, license and attribution; the About screen renders the same credits (mandatory for CC BY-SA and OpenStreetMap).
- Catalogs derived from share-alike sources (HYG, OpenNGC, Stellarium) are served under the same license, declared in `/meta.catalogs.<name>.license` and `.attribution`; the build scripts being public satisfies the share-alike condition.
- Never add data, images, fonts or textures with an unknown or non-commercial license.

## Integrity: pinned and recorded hashes

Immutable files carry a SHA-256 pin in the registry (observed on 2026-09-03); `sky-data verify` and the test fixture `kernels_dir` compare the file on disk with it. Refreshable files (OpenNGC, Stellarium, d3-celestial, the two MPC files) change upstream, so their hash is recorded in `DATA_DIR/manifest.json` at fetch time together with the size, URL, `Last-Modified` and fetch time, and `verify` compares against that record. `de440.bsp` and `de441.bsp` were not downloaded at M1 (114 MB and 3.1 GB): their registry entries carry the known sizes and a pending pin, and `fetch` records the observed hash into the manifest until a pin is added.

## `DATA_DIR` layout

```
data/
  de440s.bsp  pck00011.tpc  moon_de440_250416.tf  moon_pa_de440_200625.bpc   (kernels; optional: de440.bsp, de441.bsp, pck00010.tpc)
  hip_main.dat  hyg_v44.csv.gz  NGC.csv  addendum.csv                           (catalog sources)
  stellarium_modern_index.json  stellarium_modern_description.md  constellations.bounds.json
  MPCORB.DAT  CometEls.txt                                                      (MPCORB.DAT.gz is inflated on arrival)
  manifest.json                                                                 (what was fetched: hash, size, URL, Last-Modified, time)
  cache/
    stars.skys  stars_index.json  hipparcos.parquet  dso.json  constellations.json
    mpc/asteroids.parquet  mpc/comets.parquet  mpc/index.parquet
    manifest.json                                                               (source hashes; per artifact: sha256 = ETag, bytes, count, version, meta, declared license)
```

Caches are rebuilt per group (stars, DSO, constellations, MPC) when a source hash, the cache format version or the DSO limits change, or when an artifact is missing or corrupt (`sky-data build-caches`, `--force` to rebuild everything). Artifact versions are `<format version>-<12 hex of the source hashes>`; the artifact SHA-256 is the strong ETag served at M2.

## `sky-data` (brief l.364)

Run from the repository root as `uv run --directory backend sky-data <verb>` (settings from `SKYAPI_DATA_DIR` and `SKYAPI_EPHEMERIS`; `make data` loads `.env` and runs `fetch` then `build-caches`). Global options: `-v/--verbose`; `--registry PATH` points at another registry file and exists for the test suite only.

| Verb                                                         | Effect                                                                                                                                                    |
| ------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fetch [--full] [--only KEY ...] [--force]`                  | downloads the ephemeris named by `SKYAPI_EPHEMERIS` plus every non-optional dataset (resumable, verified); `--full` adds `de441.bsp`; prints a warning before any download above 1 GB |
| `update`                                                     | re-downloads the refreshable datasets (every unpinned entry whose `refresh` is not `never`: MPC weekly, OpenNGC and Stellarium yearly; d3-celestial is `never` and the pending-pin ephemerides are immutable, so both are left alone), skipping those whose `ETag`/`Last-Modified` HEAD probe matches the manifest, refreshes the manifest, rebuilds the cache groups whose sources changed and, when something changed, reminds you to restart the API |
| `verify`                                                     | checks every file against its pin or its manifest record and every cache artifact against `cache/manifest.json`; reports each, exit 1 with the mismatch count                |
| `build-caches [--force] [--dso-mag-limit 14] [--dso-size-arcmin 5]` | builds `cache/` from the downloaded files                                                                                                           |
| `status [--json]`                                            | lists every registry entry (downloads, built-in tables, committed files, runtime services, UI assets) with kind, presence, size, hash status, license, attribution and refresh |

Weekly refresh (brief l.298), for example in a crontab on the host running compose (M7):

```cron
15 4 * * 1  cd /srv/intersidera && uv run --directory backend sky-data update && docker compose restart api
```

## When NAIF revises a kernel

NAIF replaces the Moon frame kernel under a new dated name (`moon_de440_220930.tf` became `moon_de440_250416.tf`) and archives the old one under `a_old_versions/`. Procedure: read the release note in the NAIF `fk/satellites/` directory, add the new file as the registry entry's `url` and move the previous one to `fallback_urls`, download it, update `filename`, `size_bytes` and `sha256`, run `sky-data verify`, `make notices`, and record the change in `docs/plan.md` section 5. `sky-data verify` fails loudly (404 or size guard) rather than caching a wrong file.

## Coverage summary reported by `/meta` (brief l.331-333)

Ephemeris coverage from the loaded kernel (de440s 1849-2150, de440 1550-2650, de441 -13200..+17191), shrunk by one day for light time; Moon-surface observers 1550-2650 (the binary PCK); other bodies: IAU rotation models, exact by definition, labelled `iau_rotation_approximate` outside 1800..2200; MPC elements reliable within 2 years of their epoch (`mpc_extrapolation` beyond, `mpc_unreliable` beyond 50 years); Hipparcos proper motion linear (`proper_motion_extrapolated` beyond 10,000 years); delta T tabulated from -720 (Skyfield's bundled historical table) through the IERS daily table, predicted about a year ahead, `delta_t_approximate` beyond (the long-term parabola).

## Test excerpts

`backend/tests/fixtures/excerpts/` holds excerpts under 1 MB of Hipparcos, HYG, OpenNGC (NGC and addendum), Stellarium `modern`, d3-celestial boundaries, MPCORB and CometEls. Each starts with an in-file provenance header (source URL, license, fetch date, what was kept), has a `[[excerpts]]` entry in the registry (hence a section in `THIRD_PARTY_NOTICES.md`) and is described in `excerpts/README.md`.
