# Architecture

Status: stub written at M0; backend data pipeline and astronomy core written at M1; API v1 (bootstrap, routers, middleware) written at M2; completed at M3 (frontend) and M7 (deployment). The authoritative text is `docs/brief.xml`, architecture section (l.39-98); this document explains how the code realises it and is updated in the same commit as the code.

## Principles

- Skyfield (backend) is the single astronomical authority. The frontend never computes an astronomical position from first principles: it rotates catalog unit vectors by a backend horizon rotation, applies linear proper motion with backend vectors, interpolates backend samples, applies first-order annual aberration with the backend observer velocity, and applies a refraction correction (Earth only) validated against Skyfield.
- "Backend as oracle, client as propagator": deterministic, stateless, cacheable GET requests; the client owns the simulation clock.
- No accounts, no sessions, no database, no persistence; per-user state lives in the browser and the URL.
- Determinism: identical (observer, time, options) produce byte-identical responses.

## Time model

TT Julian Date (float64) is the canonical simulation time (`frontend/src/sky/math/time.ts`, plan D75). The store holds a control block `{ mode, speed, ttAnchor, wallAnchorMs }` for the three modes (live, paused, playing at a signed speed in simulated seconds per real second) and never ticks. The engine owns the clock: every render tick reads `Date.now()` once, derives `tt` through `state/clock.ts::ttAt` (live: `liveTt(nowMs, ttMinusUtc) = ms / 86400000 + 2440587.5 + s / 86400`; paused: `ttAnchor`; playing: `ttAnchor + speed * elapsed`), clamps it to `/meta.coverage.ephemeris_tt` intersected with the observer's `coverage_tt` (a playing clock pauses at the bound, TIME-4), drives the frame buffer, and publishes the mirror `clock.tt` to the store at most twice per second (`publishTt`, only when the value changed by more than 1e-6 day). React never reads the clock at animation rate; the URL and the M4 time panel read the mirror. `performance.now()` is used only for the fps ring.

`ttMinusUtc` is seeded with 69.184 s (32.184 s plus 37 leap seconds), replaced by `/meta.server_time.tt_minus_utc_seconds` at boot and then by each frame window's `time.tt_minus_utc_seconds`, held constant within the window (brief l.51). `time.ts` also carries the calendar (Richards' algorithm, `s = 153`, floor modulo for negative Julian Dates, proleptic Gregorian with astronomical year numbering, `formatYear` with an explicit sign), `isoUtcFromTt` (the mirror of the backend `utc_iso`: half a second added then floored), `gregorianNoticeNeeded(jd) = jd < 2299160.5`, and the sampling helpers of the fetch policy (`stepSecondsForSpeed`, `clampStepSeconds`, `alignTt0`, `isSnapshot`, `clampTt`). Local-zone display formatting arrives with the time panel at M4. A tab hidden for a while simply jumps on its next tick; the fetch policy treats the jump like any other and refetches.

## Coordinate frames

ICRF exchange frame; local ENU horizon frame; ICRF -> ENU as sign-continuous Hamilton quaternions from Skyfield `rotation_at(t)` after the NEU -> ENU row swap; apparent directions for bodies; ENU -> Babylon (East +X, Up +Y, North +Z) in exactly one module, `frontend/src/sky/math/frames.ts`; equator-of-date quaternions from `framelib.true_equator_and_equinox_of_date`. Observer coordinates: WGS84 geodetic on Earth (`wgs84.latlon`), planetocentric elsewhere (`PlanetTopos.from_latlon_distance` on the triaxial radius of the IAU ellipsoid at that latitude and longitude, plus the elevation).

Body-fixed frames (M1): the Moon uses the binary PCK frame `MOON_ME_DE440_ME421` (`moon_de440_250416.tf` + `moon_pa_de440_200625.bpc`); because Skyfield 1.55 keeps only the last segment of a multi-segment binary PCK (issue #952), `astro/loader.py` builds one Skyfield `Frame` per segment and a `SegmentedFrame` dispatches every time sample to the segment that covers it. Mercury, Venus, Mars, the giant planets and Pluto use `astro/frames.py`, our implementation of the IAU rotation model encoded in `pck00011.tpc` (pole right ascension and declination, prime meridian, nutation-precession terms whose angles are polynomials of degree `MAX_PHASE_DEGREE`), exposed through the same `center`/`rotation_at`/`rotation_and_rate_at` interface that `PlanetTopos` expects (ADR-0007: Skyfield builds frames only from binary PCKs and NAIF ships none for the planets). The rotation ICRF to body-fixed is `rot_z(-W) · rot_x(-(π/2 - δ)) · rot_z(-(π/2 + α))`; the horizon rotation adds Skyfield's latitude/longitude rotations and yields the left-handed north-east-up matrix that `astro/quaternions.py` turns into a right-handed ENU quaternion (row swap, Shepperd conversion, sign continuity). Frame centres are the ephemeris targets the observer vector is added to: 399 Earth, 301 Moon, and the barycentres 1, 2, 4, 5, 6, 7, 8, 9 for the other planets (de440s has no Mars 4 -> 499 segment, and the Mars barycentre is within a metre of the planet; Mercury and Venus have no moons; the outer-planet offset is sub-arcsecond; Pluto carries the `pluto_barycenter` approximation code). `AstroState.close()` releases the kernel file handles; the M2 lifespan calls it on shutdown.

## Data flow

1. Boot (`state/boot.ts`, plan D87; brief l.65-66). `/health` is polled until it answers 200: a 503 `starting` body surfaces the download progress or the bootstrap's fatal `detail` (ADR-0008), an unreachable API backs off with the countdown shown by the splash. Then `/meta` (a 503 sends the boot back to `/health`; every `bodies[].step_class` is validated against `limits.max_step_s`; `ttMinusUtc` is seeded), then the catalogs in parallel (`api/catalogs.ts`, plan D78): the SKYS stars and the name index are required and retried with backoff; `dso` and `constellations` are fetched only when `/meta.catalogs` names them (absent or `null` means degraded: status `missing`, the layer is simply not there, backlog B-42) and fail soft. Every catalog request uses `cache: 'no-cache'`, so each page load revalidates with `If-None-Match` and a 304 serves the body from the browser cache (brief l.573); the response `ETag` is compared with `/meta.catalogs.<name>.etag` and a mismatch marks the catalog `stale` for the M4 reload prompt. The engine is created concurrently by the React shell; once it exists the star catalog is uploaded, the first frame window covering the current time is awaited, and the phase becomes `ready`. Every step and failure is mirrored into the store's `boot`, `health`, `catalogs`, `frames` and `engine` slices; the splash renders from state alone. A first frame request refused for good (`frames.lastError.blocked`: a 422 outside the coverage, another 4xx, a 503 with a long `Retry-After`) ends the boot with an `http` error instead of an endless splash; transient failures keep it waiting while the controller backs off.
2. Frame buffer (`state/frames.ts`, the pure policy; `state/frameController.ts`, the I/O; plan D76; brief l.67-70). The request is `{ body, lat, lon, elev, tt, step_s, n, bodies: 'all' }` with latitude and longitude rounded to 0.01 degree before they leave the browser (OBS-7), the longitude wrapped to `[-180, 180)` and the elevation rounded to 1 m, so shared links and requests agree and cache keys are shared across users. `step_s = max(1, ceil(|speed| * 60 / 32))` is clamped through the `step_class` of every requested body (minor bodies are M4). Window mode is `n = 32`: `tt0 = alignTt0(tt) - step` for `speed >= 0`, and `tt0 = alignTt0(tt) - (n - 2) * step` for negative speeds so the current time sits in the last segment with one sample ahead for the tangent. When the window would cover less than 5 s of real time the policy switches to snapshot mode: `n = 1`, `tt0 = alignTt0(tt)`, a refetch when the aligned `tt0` moves by more than 1e-8 day and at most every 250 ms (<= 4 Hz), no interpolation. The next window is prefetched when the direction-aware consumption reaches 70 % (`next.tt0 = current.tt0 +- (n - 1) * step`, seam sample shared); the buffer is invalidated by an observer change, a body-set change, a speed sign change or a ratio above 10, or a `tt` outside the current, next and in-flight spans; pausing keeps it. At most two windows live as `Float64Array`s. Errors: a 422 `outside-coverage` pauses the clock at the bound and blocks that request shape; a 503 with `Retry-After >= 30 s` marks the shape failed (a missing data group; M4 hides the layer); other problems and network errors back off exponentially with jitter while the engine extrapolates from the last window (brief l.69, l.281). The policy runs at most every 100 ms unless the store changed on that tick. Request identity for in-flight and backing-off requests is the shape (`shapeKey`, the query without `tt`), so a moving alignment bucket keeps a pending request of the same shape instead of aborting it and the exponential backoff really grows. A 422 at a coverage bound pauses the clock one guard (`COVERAGE_GUARD_D`, 1e-6 day) inside `range_tt` and refetches the shape flush with the bound (`boundedRequest`; the API rounds `tt` to 1e-8 day so the advertised bound itself is refused, backlog B-52), blocking the shape only if that is refused too; a 422 on a prefetch blocks that shape and playing continues; other 4xx and a 503 with a long `Retry-After` block the shape; transient errors back off per shape while the engine extrapolates.
3. Per animation frame (`SkyEngine.tick`). Compute `tt`; run the policy; evaluate the covering window into one preallocated `FrameEval` (`sky/math/interpolation.ts`, plan D74): slerp of `horizon.q` and `equinox_of_date.q` on the CPU in float64 (inputs renormalised after the API's 9-decimal rounding, sign continuity kept, nlerp for tiny arcs), cubic Hermite with Catmull-Rom tangents (one-sided at the window ends) for body directions (renormalised) and for `dist_au`, `mag` (`null` stored as NaN), `phase` and `diam_deg`, linear interpolation of `sun_dir` (renormalised) and `observer_velocity_au_d`, `lst_hours` on the 24 h circle, and extrapolation beyond the window from its two boundary samples while a request is in flight. Then one uniform upload per star shader (horizon quaternion, observer velocity for aberration, years since the SKYS epoch, refraction switch and factor, viewport, vertical field of view, magnitude limit), the body billboards refreshed from the interpolated directions, and the rotating overlays (equatorial grid of date, ecliptic) regenerated at <= 10 Hz (brief l.68).
4. Store and URL (`state/store.ts`, `state/url.ts`, `state/urlSync.ts`; plan D79, D80; UX-2, OBS-8). One zustand vanilla store with `subscribeWithSelector` is shared by React (`useStore` with `useShallow`) and the framework-agnostic engine (selector subscriptions with shallow equality on `view`, `layers`, `options`, `observer`, `meta`). The camera controller writes `view` at pointer rate; the engine applies it through its subscription; React components never select `view` at M3. `urlSync` serialises `urlStateOf(state)` (fixed key order, default-valued keys omitted except the observer, `t`, `az`, `alt`, `fov`; coordinates and alt/az rounded to 0.01 degree, fov to 0.1 degree, tt to 1e-6 day) with `history.replaceState` at most twice per second with a trailing write, preserves the hash and applies `popstate` back into the store without echo. `parseUrlState` never throws: an unknown or invalid parameter is absent and the store keeps its default. No cookie, Web Storage or IndexedDB call exists anywhere in `frontend/src`.

## Backend

Python 3.14, FastAPI application factory, Pydantic v2 models, pydantic-settings (`SKYAPI_` prefix). Package layout follows brief l.352-368 with one deviation (ADR-0005: the committed factual files live inside `skyapi/data/`): `api/v1/` routers plus `api/canonical.py` and `api/deps.py`, `bootstrap.py` (startup thread), `meta.py` (the static part of `/meta`), `astro/` (every Skyfield object), `catalogs/` (SKYS builder, OpenNGC subset, constellations, MPC caches), `data/` (registry, downloads, caches, license texts), `models/`, `middleware/` (problem details, rate limiting, logging, caching), `tools/` (`dump_openapi.py`, `render_notices.py`), `cli/sky_data.py`. Type stubs for the untyped astronomy libraries live in `backend/typings/` (ADR-0006).

### Data pipeline (M1)

- `data/registry.py` loads `data_files.toml`, the single description of every dataset (URL, fallback URLs, size, pinned SHA-256 for immutable files, license, copyright, attribution, refresh cadence, optional flag) plus the committed test excerpts. `THIRD_PARTY_NOTICES.md` is rendered from it.
- `data/download.py` downloads with the standard library only: resumable `.part` files with a sidecar, `Range`/`If-Range`, identity encoding, size and content-type guards, retries with backoff, streamed SHA-256, optional gunzip (MPCORB), atomic replace, a progress callback that `/health` will expose at M2. `DATA_DIR/manifest.json` records what was fetched (hash, size, URL, `Last-Modified`, time); refreshable files are verified against it, immutable files against their pin.
- `data/caches.py` orchestrates the builders into `DATA_DIR/cache/` and writes `cache/manifest.json` (source hashes, per-artifact SHA-256 = ETag, version, count, `meta` for `/meta.catalogs`, declared license). Caches are rebuilt only when a source hash or the format version changes.
- `cli/sky_data.py` exposes `fetch`, `update`, `verify`, `build-caches` and `status`; `make data` runs fetch then build-caches.

### Astronomy core (M1)

- `astro/loader.py` builds the frozen `AstroState` (timescale from Skyfield's bundled tables with the proleptic Gregorian calendar, the memory-mapped ephemeris opened as `SpiceKernel`, the planetary constants, the Moon frame, the IAU frames, observer and body tables, coverage ranges). Coverage is computed from the ephemeris segments along each chain to the barycentre, intersected over the served bodies and shrunk by one day for light time; multi-segment DE441 targets would otherwise return NaN silently.
- `astro/state.py` holds the kernel-level context; `catalogs/state.py` (star table, Hipparcos frame, star index, DSO, constellations) and `astro/minor_bodies.py` (search index, orbit cache) hold the catalog contexts. The root `SkyState` composes them at M2; at M1 its optional fields stay `None`.
- `astro/time.py` (sample grids, ISO strings with astronomical year numbering, TT - UTC or TT - UT1, delta T coverage, time warnings), `astro/quaternions.py` (pure), `astro/horizon.py` (horizon and equator-of-date quaternions, local sidereal time, observer velocity, authoritative alt/az), `astro/observers.py`, `astro/frames.py`, `astro/bodies.py` (apparent directions, distances, phases, angular diameters, magnitudes: Skyfield's `planetary_magnitude` for Mercury to Neptune, cited formulas for the Sun, the Moon and Pluto), `astro/sampling.py` (the `max_step_s` classes), `astro/refraction.py` (Skyfield's refraction as the reference table for the client-side formula), `astro/stars.py`, `astro/dso.py`, `astro/constellations.py`, `astro/minor_bodies.py` (MPC ids, search, defaults, Kepler orbits with `GM_SUN_DE440_km3_s2`, H-G and comet magnitudes, extrapolation warnings).
- Every function is vectorised over one `Time` array per frame and receives its state explicitly; per-body results are `astro/samples.py::Samples` arrays and warnings are `astro/warnings.py::SkyWarning` objects with the closed code list of the contract.

### Catalog builders (M1)

`catalogs/formats.py` (SKYS v1, pure, 100 % covered), `catalogs/readers.py` (provenance-header-tolerant readers), `catalogs/builders.py` (stars: one vectorised `Star` evaluated from the solar-system barycentre at J2000 and one Julian year later; star index from HYG; DSO subset from OpenNGC; constellations from Stellarium lines, d3-celestial boundaries and the committed IAU names, with the Stellarium license asserted at build time) and `catalogs/mpc_build.py` (MPC Parquet caches and the search index). `catalogs/artifacts.py` defines the shared `CachePaths`, `Artifact` and `BuildResult` types and the version rule; artifacts are versioned by the hash of their sources and served by content hash (ETag) at M2.

### Lifespan state and the bootstrap (D11, D51, ADR-0008)

Starlette 1.x removed every startup hook except lifespan, so `skyapi/lifespan.py` is an `@asynccontextmanager` created by `make_lifespan(settings, registry=None)` and passed as `FastAPI(lifespan=...)`. It configures the JSON logging, starts the bootstrap thread and yields at once a `LifespanState` TypedDict (`{"bootstrap": Bootstrap, "settings": Settings, "limiter": TokenBucketLimiter, "frame_cache": FrameCache}`) that Starlette exposes as `request.state`. uvicorn serves nothing before the lifespan has yielded, and the brief wants `/health` to report `starting` with download progress (l.80), which is why the data is loaded by a thread rather than before the yield.

`skyapi/bootstrap.py` runs five stages, each preceded by a cancellation check: (1) every default download of the registry is present (a file counts as present when it exists and is not empty: downloads land atomically, and hashing de441 at every start would eat the 60 s readiness budget; integrity stays with `sky-data verify` and with the cache builder, which hashes every source it reads); with `SKYAPI_AUTO_FETCH` a missing file is downloaded through `skyapi.data.download` with the progress callback that `/health` exposes and an interruptible sleep; without it a missing required file is fatal and a missing optional one degrades; (2) the caches are current and intact (`caches_are_current`, `verify_caches`) or `build_all` rebuilds them; stages 1 and 2 run under an exclusive `flock` on `DATA_DIR/.bootstrap.lock` so `fastapi run --workers N` never downloads or builds twice into one directory; (3) `load_astro_state`, `load_catalog_state` (DSO and constellations optional), `load_minor_body_state` when the MPC tables exist; (4) `build_meta_static`; (5) publication of the frozen `SkyState` with `ready`, or `degraded` when a data group is missing (`dso`, `constellations`, `mpc`). The holder publishes one immutable `Snapshot(status, sky, progress, detail, missing)` at a time under a lock, so a request never sees `ready` without a `SkyState`. A fatal error keeps `starting`, stores `detail` and closes any kernel already opened; the process stays up so `/health` explains. At shutdown the lifespan cancels, joins the thread and calls `AstroState.close()`.

Routes reach the state through `api/deps.py`: `get_sky_state(request)` returns the published `SkyState` or raises `DataNotReadyError` (503, `Retry-After: 5`); `get_settings`, `get_bootstrap`, `get_frame_cache`, `get_limiter` read the other entries. Nothing is stored on `app.state`, `on_event` is never used, and the factory `create_app(settings, *, registry=None)` performs no I/O (the registry is read by the thread), so `app.openapi()` renders anywhere (`dump_openapi`, the snapshot test). `skyapi/main.py` also exposes `app` as a lazily built module attribute for `fastapi dev` (ADR-0003); tests build their own app with explicit `Settings`.

### API v1 (M2)

- Routers (`api/v1/{health,meta,catalogs,minor_bodies,sky}.py`) validate, canonicalize (`api/canonical.py`: coordinates rounded to 1e-6 degrees with the longitude wrapped to `[-180, 180)`, elevation to 1 m, `tt` to 1e-8 day, `,`-separated sorted de-duplicated id lists, `bodies=all` minus the observer, the caps 100/200/4096, `step_s` clamped and echoed), call one composite of `astro/` (`astro/frame.py::compute_frame`, `astro/altaz.py::compute_altaz`, `search`, `defaults`) with the `SkyState`, and serialize Pydantic models. Compute routes are plain `def` (thread pool). Routers never import Skyfield; `astro/` never imports `api/` (the canonical query dataclasses live in `astro/queries.py`).
- Errors: typed `ApiError` subclasses in `middleware/problem.py` (400 invalid parameter, 404 unknown object, 422 outside coverage with `range_tt`, 429 rate limited, 503 data not ready) rendered by one handler as RFC 9457 `application/problem+json`; FastAPI validation errors become 400 problem documents, unrouted paths 404, unexpected exceptions 500; `instance` is the request path, never its query string.
- Caching: catalogs are served from the cache files with `FileResponse`, a content-hash `ETag` and `Cache-Control: public, max-age=3600, stale-while-revalidate=86400`; `If-None-Match` answers 304 (our code: Starlette's `FileResponse` handles `Range` only). Frames are cached per worker in `FrameCache`, an LRU of 256 serialised responses keyed on the canonical query string, and answer `Cache-Control: public, max-age=300` with `Server-Timing: compute;dur=..., cache;desc=hit|miss`; `/meta` and `/health` are `no-store`.
- Middleware (outermost first): `RequestContextMiddleware` (pure ASGI; UUID-shaped `X-Request-Id` accepted else generated, echoed, one JSON access record with the path only), `CORSMiddleware` (`allow_origins` from settings, `GET` only, `If-None-Match` allowed, `ETag`/`Server-Timing`/`Retry-After`/`X-Request-Id` exposed), `GZipMiddleware` (bodies of 1 KiB and more). Rate limiting is a dependency of the query endpoints (`/sky/frame`, `/sky/altaz`, `/minor-bodies/search`): a token bucket per client IP and per worker (`middleware/ratelimit.py`), `Retry-After` on refusal.
- Minor bodies in a frame are propagated in one batch: `StackedOrbits` runs Skyfield's `keplerlib.propagate` once for every requested orbit and one `observe().apparent()` call covers all of them (D69), which keeps light time, aberration and deflection in Skyfield while meeting the 100-body budget.
- Degraded mode: a missing optional data group leaves its `SkyState` field `None` and its code in `missing`; `/health` says `degraded`, `/meta` omits the catalog entry, and only the routes that need the group answer 503 (`/catalogs/dso`, `/catalogs/constellations`, `/minor-bodies/*`, frames with `minor=`, altaz targets `dso:`, `a:`, `c:`).

## Frontend

React 19 for UI chrome only; a framework-agnostic `SkyEngine` (Babylon.js 9, subpath imports) fed by the single simulation store described above; the Vite dev server proxies `/api` to `http://127.0.0.1:8000`. The M3 layout of `frontend/src/`: `api/` (generated `schema.d.ts`, `client.ts`, `catalogs.ts`), `sky/math/` (pure, 100 % covered), `sky/engine/` (the only directory that imports `@babylonjs/*`), `sky/shaders/` (`*.glsl` and `*.wgsl` twins imported with `?raw`), `state/` (types, url, clock, frames, frameController, store, urlSync, boot), `debug/` (the hook), `ui/` (components, no astronomy), `i18n/`, `styles/app.css`, `test/`.

### Shell (M3, plan D87)

`main.tsx` creates the store from `parseUrlState(location.search)`, applies the URL language to i18next and `document.documentElement.lang` before the first render, starts `urlSync`, creates the frame controller and renders `<App store frames createEngine={createSkyEngine}>` in StrictMode. `App` renders an `sr-only` level-1 heading, `SkyCanvas` and `BootStatus`. `SkyCanvas` owns one effect: it creates an `AbortController`, starts the boot with a deferred engine promise, creates the engine through the injected factory (unit tests pass a fake, so Babylon never runs under jsdom), records `engine.kind`/`status` in the store (a factory rejecting with `WebGL2UnavailableError` also aborts the boot and writes the `webgl2` boot error at once, so the UX-6 text does not wait for `/health`, `/meta` and the catalog download; resizing belongs to the engine's own `ResizeObserver` on the canvas, plan D85), and installs the debug hook through a dynamic `import()` guarded by `import.meta.env.DEV || import.meta.env.MODE === 'e2e'`; the cleanup aborts and disposes. The work is deferred by one microtask so React StrictMode's synchronous effect, cleanup, effect sequence in development creates exactly one engine (brief l.551). A dev/e2e hash `#engine=webgl2|webgpu` forces a backend and is never serialised. `BootStatus` reads `boot` and `health.status` and shows the splash (title, tagline, one line per phase with the download percent or megabytes, the fatal detail, the unreachable countdown, the UX-6 WebGL2 text) until the phase is `ready`, then renders nothing. Every string goes through `t()` with keys in `en.json` and `fr.json`.

### Engine (M3, plan D81-D86)

- Creation (`sky/engine/createEngine.ts`): WebGPU when `navigator.gpu` exists and `WebGPUEngine.IsSupportedAsync` resolves true after a dynamic import of the lazy `sky/engine/webgpu.ts` chunk, `new WebGPUEngine(canvas, { antialias, powerPreference: 'high-performance', xrCompatible })` plus `initAsync()` (a failure falls back to WebGL2); otherwise `new Engine(canvas, true, { powerPreference: 'high-performance', preserveDrawingBuffer: false, loseContextOnDispose: true })`, and `webGLVersion < 2` is the `WebGL2UnavailableError` behind the UX-6 message. Every `await` is followed by an abort check that disposes the engine. Neither `glslangOptions` nor `twgslOptions` is ever passed: every custom shader has a WGSL twin, so WebGPU never compiles GLSL and never downloads a wasm from a CDN (brief l.538). The side-effect imports live in `babylon.ts` (WebGL set) and `webgpu.ts`, one comment per import; `SetMissingSideEffectWarningsEnabled(true)` in dev and e2e builds.
- Geometry (ADR-0009, plan D72): every sky mesh keeps its vertices in the right-handed ENU frame and carries the axis permutation P (East -> +X, Up -> +Y, North -> +Z, determinant -1) as its frozen world matrix, built once from `sky/math/frames.ts::enuToBabylonMatrix()`. Shaders therefore use Babylon's `worldViewProjection` and contain no swizzle; the CPU never converts a vertex; `backFaceCulling` is off because a reflection flips the winding. The `TargetCamera` sits at the origin with `minZ = 1`, `maxZ = 2000` around the sphere of radius 1000, its rotation `{ x: -alt, y: az, z: 0 }` and its vertical field of view come from `frames.ts` on every view change; `alt` is clamped to +-89.99 degrees. The URL `fov` is the vertical field of view in degrees, 1 to 120.
- Star layer (`layers/StarLayer.ts`, plan D82): one mesh, four vertices per star (471,820 for 117,955 stars), `position` = the SKYS `dir` column, `starPm` (f32 x 3) and `starPhot` (i16 x 2 SNORM: V magnitude and B-V in millimagnitudes, 32767 = unknown B-V) as zero-copy views of the catalog buffer, the corner from the vertex index. The vertex shader applies `d = normalize(dir + pm * years)`, first-order annual aberration `normalize(d + v / c)` with `c = 173.1446 au/day`, the horizon quaternion, the optional refraction on the ENU altitude (azimuth kept), then `enu * 1000` through `worldViewProjection`; pixel size and brightness come from `sky/math/stars.ts` (`magnitudeLimitForFov`: 6.5 at 90 degrees rising to the catalog `magnitude_limit` at 1 degree on a log scale, replaced by the `maglim` override; `starPixelRadius`, `starBrightness`, `bvToRgb` with documented piecewise-linear stops); stars fainter than the limit collapse to a degenerate off-screen quad; the fragment is a soft disc (`exp(-4 r^2)`, `discard` outside). Additive blending, no depth write, rendering group 0; `alwaysSelectAsActiveMesh`, `doNotSyncBoundingInfo`, `scene.skipFrustumClipping`. Float32 is sufficient (`pm * years` is about 1e-7 rad).
- Bodies layer (`layers/BodiesLayer.ts`, plan D83): one mesh with one billboard quad per `/meta.bodies` entry plus a glare quad for the Sun, updatable buffers refreshed every frame from the CPU-interpolated apparent directions rotated into ENU and refracted on Earth with the same formula as the stars; `bodyParams` (angular radius, magnitude or NaN, phase, class Sun / Moon / other) and `bodySun` (the per-body body-to-Sun direction `normalize(sunEnu * dSun - enu * dBody)` from the interpolated `sun_dir` and the observer-centred distances, expressed in the billboard basis; the observer-to-Sun direction alone would light every outer planet from behind the line of sight, so it is used only for the Sun itself or when a distance is unknown) feed a fragment that shades a sphere lit from that direction (`smoothstep(-0.05, 0.05, dot(n, sun))`), the Sun fully lit with an additive glare; minimum pixel size, true angular size from `diam_deg` when larger; rendering group 2; minor bodies are parsed and drawn at M4.
- Line layers (`layers/LineLayers.ts`, generators in `sky/math/lines.ts`, plan D84): `CreateLineSystem` once per layer with preallocated `Float32Array`s updated in place; horizon circle with cardinal ticks, altitude/azimuth grid (azimuth every 15 degrees, altitude every 10 degrees) and meridian generated once in ENU; the equatorial grid of date (points in the of-date frame rotated by `q_h * conj(q_eq)`) and the J2000 ecliptic (pole from the constant obliquity 84381.406 arcsec, rotated by `q_h`; backlog B-54) refreshed at <= 10 Hz; rendering group 1. Cardinal letters and the ground are M4, so stars render below the horizon at M3.
- Camera and input (`sky/engine/CameraController.ts`, plan D85): DOM `pointerdown/move/up/cancel` with pointer capture, drag `daz = -dx * fov / height`, `dalt = dy * fov / height`, inertia decaying as `exp(-dt / 0.25 s)`, two-pointer pinch and `wheel` zoom `fov *= 1.1^(dy / 100)`, double-click or double-tap centring through `screenToDirection`; the controller writes the store, the engine applies the camera; `setHardwareScalingLevel(1 / min(devicePixelRatio, 2))` on resize.
- Refraction (`sky/math/refraction.ts`, plan D73, backlog B-50): one shared forward formula `apparentAltitudeDeg(hTrue, factor)`, a Saemundsson seed `1.02' / tan(h + 10.3 / (h + 5.11))` followed by two Bennett corrections `h_app = h + B(h_app)` with `B(a) = 1' / tan(a + 7.31 / (a + 4.4))`, both scaled by `factor = (P / 1010) * (283 / (273 + T))` with `P = 1010 * exp(-elev_m / 9100)` mbar and `T = 10 C`, zero below -1 degree and above 89.9 degrees (Skyfield's cut). The GLSL and WGSL star shaders mirror it line by line, the bodies layer and the debug hook call it, so stars and bodies share one apparent frame; `trueAltitudeDeg` (apparent -> true) exists for the M4 UI. Measured 0.057 arcmin against the fixtures, asserted <= 1 arcmin (brief l.90). Refraction applies on Earth only.
- Debug hook (`debug/skyDebug.ts`, plan D86): `window.__sky` in dev and e2e builds only (`make build` proves production bundles carry no `__sky`): `backend`, `adapterInfo`, `isReady`/`ready`, `fps()` (ten-second ring), `state()`, `altAzOf(id)` (bodies from the uploaded interpolated direction, stars through the CPU twin of the star shader; true and refracted altitude), `screenOf(id)` (pure projection), `setTime`, `pause`, `play`, `live`, `setView`, `setRefraction`, `waitForFrame`, `stats()`. `selfTest(seconds)` runs the M3 sanity checks inside the page (fps over the period, Polaris against the latitude, every body against `/sky/altaz` at the rendered instant) and the URL hash `#selftest[&report=<url>]` runs it after `ready`, shows the JSON in an overlay and optionally POSTs it: the recipe for host-GPU measurements (docs/testing.md).
- Bundle (plan D90): `build.rolldownOptions.output.codeSplitting` groups `babylon-webgpu` (the WebGPU engine, the WGSL shaders and the audio engine, reached only through the dynamic import) and `babylon`; measured on 2026-09-06 with `npm run build`: application 105 KB gzip, `babylon` 184 KB gzip, `babylon-webgpu` 145 KB gzip (downloaded only when WebGPU is used), CSS 3 KB.

Later milestones add the UI panels, labels, DSO symbols, constellations, minor bodies, atmosphere and ground, selection, search, night mode, geolocation and Nominatim (M4) and augmented reality (M5).
