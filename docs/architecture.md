## Principles

- Skyfield (backend) is the single astronomical authority. The frontend never computes an astronomical position from first principles: it rotates catalog unit vectors by a backend horizon rotation, applies linear proper motion with backend vectors, interpolates backend samples, applies first-order annual aberration with the backend observer velocity, and applies a refraction correction (Earth only) validated against Skyfield.
- "Backend as oracle, client as propagator": deterministic, stateless, cacheable GET requests; the client owns the simulation clock.
- No accounts, no sessions, no database, no persistence; per-user state lives in memory and in the URL, never in browser storage (no cookie, Web Storage or IndexedDB, OBS-8; the `noStorage` fixture asserts it at the end of every Playwright test).
- Determinism: identical (observer, time, options) produce byte-identical responses.

## Time model

TT Julian Date (float64) is the canonical simulation time (`frontend/src/sky/math/time.ts`, plan D75). The store holds a control block `{ mode, speed, ttAnchor, wallAnchorMs }` for the three modes (live, paused, playing at a signed speed in simulated seconds per real second) and never ticks. The engine owns the clock: every render tick reads `Date.now()` once, derives `tt` through `state/clock.ts::ttAt` (live: `liveTt(nowMs, ttMinusUtc) = ms / 86400000 + 2440587.5 + s / 86400`; paused: `ttAnchor`; playing: `ttAnchor + speed * elapsed`), clamps it to `/meta.coverage.ephemeris_tt` intersected with the observer's `coverage_tt` (a playing clock pauses at the bound, TIME-4), drives the frame buffer, and publishes the mirror `clock.tt` to the store at most twice per second (`publishTt`, only when the value changed by more than 1e-6 day). React never reads the clock at animation rate; the URL and the M4 time panel read the mirror. `performance.now()` is used only for the fps ring.

`ttMinusUtc` is seeded with 69.184 s (32.184 s plus 37 leap seconds), replaced by `/meta.server_time.tt_minus_utc_seconds` at boot and then by each frame window's `time.tt_minus_utc_seconds`, held constant within the window (brief l.51). `time.ts` also carries the calendar (Richards' algorithm, `s = 153`, floor modulo for negative Julian Dates, proleptic Gregorian with astronomical year numbering, `formatYear` with an explicit sign), `isoUtcFromTt` (the mirror of the backend `utc_iso`: half a second added then floored), `gregorianNoticeNeeded(jd) = jd < 2299160.5`, and the sampling helpers of the fetch policy (`stepSecondsForSpeed`, `clampStepSeconds`, `alignTt0`, `isSnapshot`, `clampTt`). Local-zone display formatting arrives with the time panel at M4. A tab hidden for a while simply jumps on its next tick; the fetch policy treats the jump like any other and refetches.

## Coordinate frames

ICRF exchange frame; local ENU horizon frame; ICRF -> ENU as sign-continuous Hamilton quaternions from Skyfield `rotation_at(t)` after the NEU -> ENU row swap; apparent directions for bodies; ENU -> Babylon (East +X, Up +Y, North +Z) in exactly one module, `frontend/src/sky/math/frames.ts`; equator-of-date quaternions from `framelib.true_equator_and_equinox_of_date`. Observer coordinates: WGS84 geodetic on Earth (`wgs84.latlon`), planetocentric elsewhere (`PlanetTopos.from_latlon_distance` on the triaxial radius of the IAU ellipsoid at that latitude and longitude, plus the elevation).

Body-fixed frames (M1): the Moon uses the binary PCK frame `MOON_ME_DE440_ME421` (`moon_de440_250416.tf` + `moon_pa_de440_200625.bpc`); because Skyfield 1.55 keeps only the last segment of a multi-segment binary PCK (issue #952), `astro/loader.py` builds one Skyfield `Frame` per segment and a `SegmentedFrame` dispatches every time sample to the segment that covers it. Mercury, Venus, Mars, the giant planets and Pluto use `astro/frames.py`, our implementation of the IAU rotation model encoded in `pck00011.tpc` (pole right ascension and declination, prime meridian, nutation-precession terms whose angles are polynomials of degree `MAX_PHASE_DEGREE`), exposed through the same `center`/`rotation_at`/`rotation_and_rate_at` interface that `PlanetTopos` expects (ADR-0007: Skyfield builds frames only from binary PCKs and NAIF ships none for the planets). The rotation ICRF to body-fixed is `rot_z(-W) · rot_x(-(π/2 - δ)) · rot_z(-(π/2 + α))`; the horizon rotation adds Skyfield's latitude/longitude rotations and yields the left-handed north-east-up matrix that `astro/quaternions.py` turns into a right-handed ENU quaternion (row swap, Shepperd conversion, sign continuity). Frame centres are the ephemeris targets the observer vector is added to: 399 Earth, 301 Moon, and the barycentres 1, 2, 4, 5, 6, 7, 8, 9 for the other planets (de440s has no Mars 4 -> 499 segment, and the Mars barycentre is within a metre of the planet; Mercury and Venus have no moons; the outer-planet offset is sub-arcsecond; Pluto carries the `pluto_barycenter` approximation code). `AstroState.close()` releases the kernel file handles; the M2 lifespan calls it on shutdown.

## Data flow

1. Boot (`state/boot.ts`, plan D87; brief l.65-66). `/health` is polled until it answers 200: a 503 `starting` body surfaces the download progress or the bootstrap's fatal `detail` (ADR-0008), an unreachable API backs off with the countdown shown by the splash. Then `/meta` (a 503 sends the boot back to `/health`; every `bodies[].step_class` is validated against `limits.max_step_s`; `ttMinusUtc` is seeded), then the catalogs in parallel (`api/catalogs.ts`, plan D78): the SKYS stars and the name index are required and retried with backoff; `dso` and `constellations` are fetched only when `/meta.catalogs` names them (absent or `null` means degraded: status `missing`, the layer is simply not there, backlog B-42) and fail soft. Every catalog request uses `cache: 'no-cache'`, so each page load revalidates with `If-None-Match` and a 304 serves the body from the browser cache (brief l.573); the response `ETag` is compared with `/meta.catalogs.<name>.etag` and a mismatch marks the catalog `stale`, which `Banners` turns into a reload prompt (UX-6). The loaded bundle is published to the store (`setBundle`) for the engine, the search index and the details controller. The engine is created concurrently by the React shell; once it exists the star catalog is uploaded, the first frame window covering the current time is awaited, and the phase becomes `ready`. Every step and failure is mirrored into the store's `boot`, `health`, `catalogs`, `frames` and `engine` slices; the splash renders from state alone. A first frame request refused for good (`frames.lastError.blocked`: a 422 outside the coverage, another 4xx, a 503 with a long `Retry-After`) ends the boot with an `http` error instead of an endless splash; transient failures keep it waiting while the controller backs off.
2. Frame buffer (`state/frames.ts`, the pure policy; `state/frameController.ts`, the I/O; plan D76; brief l.67-70). The request is `{ body, lat, lon, elev, tt, step_s, n, bodies: 'all' }` with latitude and longitude rounded to 0.01 degree before they leave the browser (OBS-7), the longitude wrapped to `[-180, 180)` and the elevation rounded to 1 m, so shared links and requests agree and cache keys are shared across users. `step_s = max(1, ceil(|speed| * 60 / 32))` is clamped through the `step_class` of every requested body; `minor` is the composed list of pins and defaults, empty when the layer is off or the server has no MPC data (plan D102). Window mode is `n = 32`: `tt0 = alignTt0(tt) - step` for `speed >= 0`, and `tt0 = alignTt0(tt) - (n - 2) * step` for negative speeds so the current time sits in the last segment with one sample ahead for the tangent. When the window would cover less than 5 s of real time the policy switches to snapshot mode: `n = 1`, `tt0 = alignTt0(tt)`, a refetch when the aligned `tt0` moves by more than 1e-8 day and at most every 250 ms (<= 4 Hz), no interpolation. The next window is prefetched when the direction-aware consumption reaches 70 % (`next.tt0 = current.tt0 +- (n - 1) * step`, seam sample shared); the buffer is invalidated by an observer change, a body-set change, a speed sign change or a ratio above 10, or a `tt` outside the current, next and in-flight spans; pausing keeps it. At most two windows live as `Float64Array`s. Errors: a 422 `outside-coverage` pauses the clock at the bound and blocks that request shape; a 503 with `Retry-After >= 30 s` marks the shape failed (a missing data group; the layers panel disables that layer's switch with the reason); other problems and network errors back off exponentially with jitter while the engine extrapolates from the last window (brief l.69, l.281). The policy runs at most every 100 ms unless the store changed on that tick. Request identity for in-flight and backing-off requests is the shape (`shapeKey`, the query without `tt`), so a moving alignment bucket keeps a pending request of the same shape instead of aborting it and the exponential backoff really grows. A 422 at a coverage bound pauses the clock one guard (`COVERAGE_GUARD_D`, 1e-6 day) inside `range_tt` and refetches the shape flush with the bound (`boundedRequest`; the API rounds `tt` to 1e-8 day so the advertised bound itself is refused, backlog B-52), blocking the shape only if that is refused too; a 422 on a prefetch blocks that shape and playing continues; other 4xx and a 503 with a long `Retry-After` block the shape; transient errors back off per shape while the engine extrapolates.
3. Per animation frame (`SkyEngine.tick`). Compute `tt`; run the policy; evaluate the covering window into one preallocated `FrameEval` (`sky/math/interpolation.ts`, plan D74): slerp of `horizon.q` and `equinox_of_date.q` on the CPU in float64 (inputs renormalised after the API's 9-decimal rounding, sign continuity kept, nlerp for tiny arcs), cubic Hermite with Catmull-Rom tangents (one-sided at the window ends) for body directions (renormalised) and for `dist_au`, `mag` (`null` stored as NaN), `phase` and `diam_deg`, linear interpolation of `sun_dir` (renormalised) and `observer_velocity_au_d`, `lst_hours` on the 24 h circle, and extrapolation beyond the window from its two boundary samples while a request is in flight. Then one uniform upload per star shader (horizon quaternion, observer velocity for aberration, years since the SKYS epoch, refraction switch and factor, viewport, vertical field of view, magnitude limit), the body billboards refreshed from the interpolated directions, and the rotating overlays (equatorial grid of date, ecliptic) regenerated at <= 10 Hz (brief l.68). Since M4 the same tick pulls the tickers (the details controller) after the evaluation, derives the Sun altitude and the sky brightness B, uploads the star, deep-sky and background uniforms, refreshes the minor-body billboards, and runs the <= 10 Hz overlay tick (constellations, labels, marker, follow, centring, the visible-label publication) and the 2 Hz readout ("Frontend" below).
4. Store and URL (`state/store.ts`, `state/url.ts`, `state/urlSync.ts`; plan D79, D80; UX-2, OBS-8). One zustand vanilla store with `subscribeWithSelector` is shared by React (`useStore` with `useShallow`) and the framework-agnostic engine (selector subscriptions with shallow equality on `view`, `layers`, `options`, `observer`, `meta`). The camera controller writes `view` at pointer rate; the engine applies it through its subscription; React components never select `view` at animation rate (`FovPresets` selects a derived pressed index). `urlSync` serialises `urlStateOf(state)` (fixed key order, default-valued keys omitted except the observer, `t`, `az`, `alt`, `fov` and `lang`, whose default is the browser's; coordinates and alt/az rounded to 0.01 degree, fov to 0.1 degree, tt to 1e-6 day) with `history.replaceState` at most twice per second with a trailing write, preserves the hash and applies `popstate` back into the store without echo. `parseUrlState` never throws: an unknown or invalid parameter is absent and the store keeps its default. No cookie, Web Storage or IndexedDB call exists anywhere in `frontend/src`.

## Backend

Python 3.14, FastAPI application factory, Pydantic v2 models, pydantic-settings (`SKYAPI_` prefix). Package layout follows brief l.352-368 with one deviation (ADR-0005: the committed factual files live inside `skyapi/data/`): `api/v1/` routers plus `api/canonical.py` and `api/deps.py`, `bootstrap.py` (startup thread), `meta.py` (the static part of `/meta`), `astro/` (every Skyfield object), `catalogs/` (SKYS builder, OpenNGC subset, constellations, MPC caches), `data/` (registry, downloads, caches, license texts), `models/`, `middleware/` (problem details, rate limiting, logging, caching), `tools/` (`dump_openapi.py`, `render_notices.py`), `cli/sky_data.py`. Type stubs for the untyped astronomy libraries live in `backend/typings/` (ADR-0006).

### Data pipeline (M1)

- `data/registry.py` loads `data_files.toml`, the single description of every dataset (URL, fallback URLs, size, pinned SHA-256 for immutable files, license, copyright, attribution, refresh cadence, optional flag) plus the committed test excerpts. `THIRD_PARTY_NOTICES.md` is rendered from it.
- `data/download.py` downloads with the standard library only: resumable `.part` files with a sidecar, `Range`/`If-Range`, identity encoding, size and content-type guards, retries with backoff, streamed SHA-256, optional gunzip (MPCORB), atomic replace, a progress callback that `/health` will expose at M2. `DATA_DIR/manifest.json` records what was fetched (hash, size, URL, `Last-Modified`, time); refreshable files are verified against it, immutable files against their pin.
- `data/caches.py` orchestrates the builders into `DATA_DIR/cache/` and writes `cache/manifest.json` (source hashes, per-artifact SHA-256 = ETag, version, count, `meta` for `/meta.catalogs`, declared license). Caches are rebuilt only when a source hash or the format version changes.
- `cli/sky_data.py` exposes `fetch`, `update`, `verify`, `build-caches` and `status`; `make data` runs fetch then build-caches.

### Astronomy core (M1)

- `astro/loader.py` builds the frozen `AstroState` (timescale from Skyfield's bundled tables with the proleptic Gregorian calendar, the memory-mapped ephemeris opened as `SpiceKernel`, the planetary constants, the Moon frame, the IAU frames, observer and body tables, coverage ranges). Coverage is computed from the ephemeris segments along each chain to the barycentre, intersected over the served bodies and shrunk by one day for light time; multi-segment DE441 targets would otherwise return NaN silently.
- `astro/state.py` holds the kernel-level context; `catalogs/state.py` (star table, Hipparcos frame, star index, DSO, constellations) and `astro/minor_bodies.py` (search index, orbit cache) hold the catalog contexts. The root `SkyState` composes them at M2; at M1 its optional fields stay `None`.
- `astro/time.py` (sample grids, ISO strings with astronomical year numbering, TT - UTC or TT - UT1, delta T coverage, time warnings), `astro/quaternions.py` (pure), `astro/horizon.py` (horizon and equator-of-date quaternions, local sidereal time, observer velocity, authoritative alt/az), `astro/observers.py`, `astro/frames.py`, `astro/bodies.py` (apparent directions, distances, phases, angular diameters, magnitudes: Skyfield's `planetary_magnitude` for Mercury to Neptune, cited formulas for the Sun, the Moon and Pluto), `astro/sampling.py` (the `max_step_s` classes), `astro/refraction.py` (Skyfield's refraction as the reference table for the client-side formula), `astro/stars.py`, `astro/dso.py`, `astro/constellations.py`, `astro/minor_bodies.py` (MPC ids, search, defaults, Kepler orbits with `GM_SUN_DE440_km3_s2`, H-G and comet magnitudes, extrapolation warnings).
- Every function is vectorised over one `Time` array per frame and receives its state explicitly; per-body results are `astro/samples.py::Samples` arrays and warnings are `astro/warnings.py::SkyWarning` objects with the closed code list of the contract.

### Catalog builders (M1)

`catalogs/formats.py` (SKYS v1, pure, 100 % covered), `catalogs/readers.py` (provenance-header-tolerant readers), `catalogs/builders.py` (stars: one vectorised `Star` evaluated from the solar-system barycentre at J2000 and one Julian year later; star index from HYG; DSO subset from OpenNGC; constellations from Stellarium lines, d3-celestial boundaries and the committed IAU names, with the Stellarium license asserted at build time) and `catalogs/mpc_build.py` (MPC Parquet caches and the search index). `catalogs/artifacts.py` defines the shared `CachePaths`, `Artifact` and `BuildResult` types and the version rule; artifacts are versioned by the hash of their sources and served by content hash (ETag) at M2.

### Lifespan state and the bootstrap (D11, D51, ADR-0008)

Starlette 1.x removed every startup hook except lifespan, so `skyapi/lifespan.py` is an `@asynccontextmanager` created by `make_lifespan(settings, registry=None)` and passed as `FastAPI(lifespan=...)`. It configures the JSON logging, starts the bootstrap thread and yields at once a `LifespanState` TypedDict (`{"bootstrap": Bootstrap, "settings": Settings, "limiter": TokenBucketLimiter, "frame_cache": FrameCache}`) that Starlette exposes as `request.state`. uvicorn serves nothing before the lifespan has yielded, and the brief wants `/health` to report `starting` with download progress (l.80), which is why the data is loaded by a thread rather than before the yield.

`skyapi/bootstrap.py` runs five stages, each preceded by a cancellation check: (1) every default download of the registry is present (a file counts as present when it exists and is not empty: downloads land atomically, and hashing de441 at every start would eat the 60 s readiness budget; integrity stays with `sky-data verify` and with the cache builder, which hashes every source it reads); with `SKYAPI_AUTO_FETCH` a missing file is downloaded through `skyapi.data.download` with the progress callback that `/health` exposes and an interruptible sleep; without it a missing required file is fatal and a missing optional one degrades; (2) the caches are current and intact (`caches_are_current`, `verify_caches`) or `build_all` rebuilds them; stages 1 and 2 run under an exclusive `flock` on `DATA_DIR/.bootstrap.lock` so `fastapi run --workers N` never downloads or builds twice into one directory; (3) `load_astro_state`, `load_catalog_state` (DSO and constellations optional), `load_minor_body_state` when the MPC tables exist; (4) `build_meta_static`; (5) publication of the frozen `SkyState` with `ready`, or `degraded` when a data group is missing (`dso`, `constellations`, `mpc`). The holder publishes one immutable `Snapshot(status, sky, progress, detail, missing)` at a time under a lock, so a request never sees `ready` without a `SkyState`. A fatal error keeps `starting`, stores `detail` and closes any kernel already opened; the process stays up so `/health` explains. At shutdown the lifespan cancels, joins the thread and calls `AstroState.close()`.

Routes reach the state through `api/deps.py`: `get_sky_state(request)` returns the published `SkyState` or raises `DataNotReadyError` (503, `Retry-After: 5`); `get_settings`, `get_bootstrap`, `get_frame_cache`, `get_limiter` read the other entries. Nothing is stored on `app.state`, `on_event` is never used, and the factory `create_app(settings, *, registry=None)` performs no I/O (the registry is read by the thread), so `app.openapi()` renders anywhere (`dump_openapi`, the snapshot test). `skyapi/main.py` also exposes `app` as a lazily built module attribute for `fastapi dev` (ADR-0003); tests build their own app with explicit `Settings`.

### API v1 (M2)

- Routers (`api/v1/{health,meta,catalogs,minor_bodies,sky}.py`) validate, canonicalize (`api/canonical.py`: coordinates rounded to 1e-6 degrees with the longitude wrapped to `[-180, 180)`, elevation to 1 m, `tt` to 1e-8 day, `,`-separated sorted de-duplicated id lists, `bodies=all` minus the observer, the caps 100/200/4096, `step_s` clamped and echoed), call one composite of `astro/` (`astro/frame.py::compute_frame`, `astro/altaz.py::compute_altaz`, `search`, `defaults`) with the `SkyState`, and serialize Pydantic models. Compute routes are plain `def` (thread pool). Routers never import Skyfield; `astro/` never imports `api/` (the canonical query dataclasses live in `astro/queries.py`).
- Errors: typed `ApiError` subclasses in `middleware/problem.py` (400 invalid parameter, 404 unknown object, 422 outside coverage with `range_tt`, 429 rate limited, 503 data not ready) rendered by one handler as RFC 9457 `application/problem+json`; FastAPI validation errors become 400 problem documents, unrouted paths 404, unexpected exceptions 500; `instance` is the request path, never its query string.
- Caching: catalogs are served from the cache files with `FileResponse`, a content-hash `ETag` and `Cache-Control: public, max-age=3600, stale-while-revalidate=86400`; `If-None-Match` answers 304 (our code: Starlette's `FileResponse` handles `Range` only). Frames are cached per worker in `FrameCache`, an LRU of 256 serialised responses keyed on the canonical query string, and answer `Cache-Control: public, max-age=300` with `Server-Timing: compute;dur=..., cache;desc=hit|miss`; `/meta` and `/health` are `no-store`.
- Middleware (outermost first): `RequestContextMiddleware` (pure ASGI; UUID-shaped `X-Request-Id` accepted else generated, echoed, one JSON access record with the path only), `CORSMiddleware` (`allow_origins` from settings, `GET` only, `If-None-Match` allowed, `ETag`/`Server-Timing`/`Retry-After`/`X-Request-Id` exposed), `GZipMiddleware` (bodies of 1 KiB and more). Rate limiting is a dependency of the query endpoints (`/sky/frame`, `/sky/altaz`, `/minor-bodies/search`): a token bucket per client IP and per worker (`middleware/ratelimit.py`), `Retry-After` on refusal.
- Minor bodies in a frame are propagated in one batch: `StackedOrbits` runs Skyfield's `keplerlib.propagate` once for every requested orbit and one `observe().apparent()` call covers all of them (D69), which keeps light time, aberration and deflection in Skyfield while meeting the 100-body budget.
- Degraded mode: a missing optional data group leaves its `SkyState` field `None` and its code in `missing`; `/health` says `degraded`, `/meta` omits the catalog entry, and only the routes that need the group answer 503 (`/catalogs/dso`, `/catalogs/constellations`, `/minor-bodies/*`, frames with `minor=`, altaz targets `dso:`, `a:`, `c:`).

## Frontend

Layout of `frontend/src/` after M5 (backlog B-64 and B-77 record the additions to brief l.369-385): `api/` (generated `schema.d.ts`, `client.ts`, `catalogs.ts`, `geocoder.ts`, `rateGate.ts`), `sky/math/` (pure, 100 % covered; since M5 `orientation.ts` and `cameraFov.ts`), `sky/engine/` (the only directory that imports `@babylonjs/*`: `SkyEngine.ts`, `CameraController.ts`, `resolver.ts`, `layers/`, and the lazy `xr/` with `babylonXr.ts`, `XrBridge.ts`, `xrFlow.ts`), `sky/ar/` (the lazy, Babylon-free sensor-mode modules `arController.ts`, `sensors.ts`, `cameraVideo.ts`, `webxr.ts`, `offsetDrag.ts`, reached only through the dynamic import in `SkyEngine`), `sky/shaders/` (the `*.glsl` and `*.wgsl` twins `stars`, `bodies`, `dso`, `background`, imported with `?raw`), `state/` (types, url, clock, frames, frameController, store, urlSync, boot, the M4 modules coords, timeDisplay, coverage, warnings, presets, geolocation, detailsController, minorBodies, domSync, snapshotTime, and the eager M5 modules `arCapabilities.ts` and `arPermission.ts`), `search/` (index, normalize, minorSearch), `i18n/` (`en.json`, `fr.json`, detect, keys, labelText, format), `data/` (the generated `credits.json`, `credits.ts`, `repository.ts`), `debug/` (the hook), `types/` (`webkit-device-orientation.d.ts`), `ui/` (`components/` primitives, `shell/`, `observer/`, `time/`, `panels/`, `controls/`, `ar/` (`ArButton`, the lazy `ArOverlay`, `TimeOffsetBadge`, `CompassIndicator`), `shortcuts.ts`, `SkyCanvas.tsx`, `BootStatus.tsx`), `styles/app.css`, `test/`.

### Shell and layout (M3 plan D87, M4 plan D112)

`main.tsx` parses the URL, fills a missing `lang` from `navigator.languages` (`i18n/detect.ts`: the first entry whose primary subtag is supported, else `en`; the language, detected or chosen, is written with every URL write, `en` included, because a URL without `lang` takes the language of the browser that opens it: omitting the default lost an explicit English on a browser preferring French, found by the M7 acceptance and fixed on 2026-09-30), creates the store, starts `state/domSync.ts` (three store subscriptions fired at once that write `data-mode="night"`, `--night-brightness` and `lang` on `<html>` and call `i18next.changeLanguage`, so the first paint is already right), starts `urlSync`, requests the geolocation when the URL carries none of `body`, `lat`, `lon` and `elev`, creates the frame controller and the details ticker, and renders `<App>` in StrictMode once `changeLanguage` has resolved.

`App` (VIEW-5) renders, in DOM order: the skip link (`ui/shell/SkipLink.tsx`, the first Tab stop; its click focuses `#panel` in script so the URL hash and its dev/e2e `#engine` override stay untouched, and expands the sheet on the phone); `<main>` with the `sr-only` level-1 heading and `#sky-stage` holding `SkyCanvas` (the canvas and, as its `aria-hidden` sibling, the label overlay root, `pointer-events-none` with `contain: strict`); a floating chrome column (`pointer-events-none`, each direct child `pointer-events-auto`, so the sky between the boxes keeps receiving gestures) holding the `<header>` top bar (or, while augmented reality runs, the lazily loaded `ArOverlay` in its place, plan D127, below), `GeoBanner`, `Banners`, `Toast` and `HintBanner`; the control panel `PanelShell`; and the boot splash. `installShortcuts(store)` runs from one effect. ### Engine (M3 plan D81-D86, amended at M4)

- Creation (`sky/engine/createEngine.ts`): WebGPU when `navigator.gpu` exists and `WebGPUEngine.IsSupportedAsync` resolves true after a dynamic import of the lazy `sky/engine/webgpu.ts` chunk, `new WebGPUEngine(canvas, { antialias, powerPreference: 'high-performance', xrCompatible })` plus `initAsync()` (a failure falls back to WebGL2); otherwise `new Engine(canvas, true, { powerPreference: 'high-performance', preserveDrawingBuffer: false, loseContextOnDispose: true })`, and `webGLVersion < 2` is the `WebGL2UnavailableError` behind the UX-6 message. Every `await` is followed by an abort check that disposes the engine. Neither `glslangOptions` nor `twgslOptions` is ever passed: every custom shader has a WGSL twin, so WebGPU never compiles GLSL and never downloads a wasm from a CDN (brief l.538). The side-effect imports live in `babylon.ts` (WebGL set) and `webgpu.ts`, one comment per import; `SetMissingSideEffectWarningsEnabled(true)` in dev and e2e builds. The canvas gets `tabIndex` 0 (Babylon's default of 1 would make it the first Tab stop before the skip link).
- Geometry (ADR-0009, plan D72): every sky mesh keeps its vertices in the right-handed ENU frame and carries the axis permutation P (East -> +X, Up -> +Y, North -> +Z, determinant -1) as its frozen world matrix, built once from `sky/math/frames.ts::enuToBabylonMatrix()`. Shaders therefore use Babylon's `worldViewProjection` and contain no swizzle; the CPU never converts a vertex; `backFaceCulling` is off because a reflection flips the winding. The `TargetCamera` sits at the origin with `minZ = 1`, `maxZ = 2000` around the sphere of radius 1000, its rotation `{ x: -alt, y: az, z: 0 }` and its vertical field of view come from `frames.ts` on every view change; `alt` is clamped to +-89.99 degrees. The URL `fov` is the vertical field of view in degrees, 1 to 120. Rendering groups after M4: 0 = the sky background quad (`alphaIndex` 0), the stars (1) and the deep-sky symbols (2); 1 = the line overlays and the constellations; 2 = the bodies and the minor bodies; 3 = the ground quad.
- Star layer (`layers/StarLayer.ts`, plan D82): one mesh, four vertices per star (471,820 for 117,955 stars), `position` = the SKYS `dir` column, `starPm` (f32 x 3) and `starPhot` (i16 x 2 SNORM: V magnitude and B-V in millimagnitudes, 32767 = unknown B-V) as zero-copy views of the catalog buffer, the corner from the vertex index. The vertex shader applies `d = normalize(dir + pm * years)`, first-order annual aberration `normalize(d + v / c)` with `c = 173.1446 au/day`, the horizon quaternion, the optional refraction on the ENU altitude (azimuth kept), then `enu * 1000` through `worldViewProjection`; pixel size and brightness come from `sky/math/stars.ts` (`magnitudeLimitForFov`: 6.5 at 90 degrees rising to the catalog `magnitude_limit` at 1 degree on a log scale, replaced by the `maglim` override; `starPixelRadius`, `starBrightness`, `bvToRgb` with documented piecewise-linear stops); stars fainter than the limit collapse to a degenerate off-screen quad; the fragment is a soft disc (`exp(-4 r^2)`, `discard` outside). Since M4 the vertex shader fades under daylight (`uAtmosphere`, below) and the fragment applies `uNight`. Additive blending, no depth write, rendering group 0; `alwaysSelectAsActiveMesh`, `doNotSyncBoundingInfo`, `scene.skipFrustumClipping`. Float32 is sufficient (`pm * years` is about 1e-7 rad).
- Bodies layer (`layers/BodiesLayer.ts`, plan D83): one mesh with one billboard quad per `/meta.bodies` entry plus a glare quad for the Sun, updatable buffers refreshed every frame from the CPU-interpolated apparent directions rotated into ENU and refracted on Earth with the same formula as the stars (`sky/math/apparent.ts`); `bodyParams` (angular radius, magnitude or NaN, phase, class Sun / Moon / other) and `bodySun` (the per-body body-to-Sun direction `normalize(sunEnu * dSun - enu * dBody)` from the interpolated `sun_dir` and the observer-centred distances, expressed in the billboard basis `apparent.ts::billboardBasis`; the observer-to-Sun direction alone would light every outer planet from behind the line of sight, so it is used only for the Sun itself or when a distance is unknown) feed a fragment that shades a sphere lit from that direction (`smoothstep(-0.05, 0.05, dot(n, sun))`), the Sun fully lit with an additive glare; minimum pixel size, true angular size from `diam_deg` when larger; `uBodyPx` is a `vec4` (minimum disc radius, glare radius, pixel scale, tail length); rendering group 2. The minor-body layer shares this material (below).
- Line layers (`layers/LineLayers.ts`, generators in `sky/math/lines.ts`, plan D84): `CreateLineSystem` once per layer with preallocated `Float32Array`s updated in place; horizon circle with cardinal ticks, altitude/azimuth grid (azimuth every 15 degrees, altitude every 10 degrees) and meridian generated once in ENU; the equatorial grid of date (points in the of-date frame rotated by `q_h * conj(q_eq)`) and the J2000 ecliptic (pole from the constant obliquity 84381.406 arcsec, rotated by `q_h`; backlog B-54) refreshed at <= 10 Hz; rendering group 1; `setNight` recolours them. The cardinal letters are labels (below) and the ground is the background layer's second pass.
- Camera and input (`sky/engine/CameraController.ts`, plan D85, D106): DOM `pointerdown/move/up/cancel` with pointer capture, drag `daz = -dx * fov / height`, `dalt = dy * fov / height`, inertia decaying as `exp(-dt / 0.25 s)` (skipped under `prefers-reduced-motion`, followed live through the `change` event), two-pointer pinch and `wheel` zoom `fov *= 1.1^(dy / 100)`, a single tap picking the object under it through the engine's `pick` and selecting it (nothing -> deselect), a double click or double tap centring through `screenToDirection`; a drag, a pinch or a double tap ends follow mode while a single tap keeps it (tapping another object follows that one); the controller writes the store, the engine applies the camera; `setHardwareScalingLevel(1 / min(devicePixelRatio, 2))` on resize.
- Refraction (`sky/math/refraction.ts`, plan D73, backlog B-50): one shared forward formula `apparentAltitudeDeg(hTrue, factor)`, a Saemundsson seed `1.02' / tan(h + 10.3 / (h + 5.11))` followed by two Bennett corrections `h_app = h + B(h_app)` with `B(a) = 1' / tan(a + 7.31 / (a + 4.4))`, both scaled by `factor = (P / 1010) * (283 / (273 + T))` with `P = 1010 * exp(-elev_m / 9100)` mbar and `T = 10 C`, zero below -1 degree and above 89.9 degrees (Skyfield's cut). The GLSL and WGSL star and DSO shaders mirror it line by line; every CPU path (bodies, minor bodies, labels, picking, readout, debug hook) reaches it through `sky/math/apparent.ts`, so the picture and the overlays share one apparent frame; the readout's geometric altitude is the unrefracted ENU altitude the resolver computes before its refraction step (`resolver.ts`, `altTrue`); the inverse `trueAltitudeDeg` (apparent -> true) stays exported and covered but has no caller yet. Measured 0.057 arcmin against the fixtures, asserted <= 1 arcmin (brief l.90). Refraction applies on Earth only.

### Rendering layers (M4, plan D101-D105)

- Background, atmosphere and ground (SKY-6, SKY-7; `layers/BackgroundLayer.ts`, `shaders/background.*`): one clip-space full-screen quad shader serves two meshes, mode 0 the sky and mode 1 the ground; the fragment rebuilds the ENU direction of every pixel from the camera basis (`frames.ts::cameraBasis`) and `(tan(fov / 2), aspect)`, so nothing rotates and no swizzle exists (canvas only: a render target would need Babylon's y flip after the varying). The colour model is pure `sky/math/atmosphere.ts`, mirrored line by line: `skyBrightness(sunAlt)` is 1 with the Sun up, 0.30 at the end of civil twilight (-6 degrees), 0.05 at the end of nautical twilight (-12), 0 at the end of astronomical twilight (-18), linear between; `twilight(s) = exp(-((s + 3) / 5)^2)`; `skyColor` blends a horizon-to-zenith day gradient scaled by B with an orange tint toward the Sun's azimuth, black below -3 degrees. The Sun altitude comes from `rotate(q_h, sunDir)` in `tick`; the atmosphere applies on Earth only (`atm` is forced off and its switch disabled elsewhere). Stars and deep-sky objects fade through `uAtmosphere = B`: `limitEff = uMagLimit - 8 B` and `brightness *= 1 - 0.85 B`; a manual `maglim` is absolute (B is not applied, plan Q43). Ground alpha 1 (`opaque`) or 0.6 (`dim`), the mesh hidden when `off`; the sky mesh is hidden when B = 0 or the atmosphere is off. Labels, the marker and picking cull `alt < 0` under an opaque ground. The cardinal letters (N, E, S, W; `O` for west in French) are labels at +1.5 degrees gated by the `horizon` layer.
- Deep-sky objects (SKY-3; `layers/DsoLayer.ts`, `shaders/dso.*`): one mesh, four vertices per object (5,229 in the full catalog), attributes `position` (ICRS unit vector), `dsoShape` (magnitude or 99, major semi-axis in radians, minor/major ratio, position angle) and `dsoType` 0..5. The vertex shader applies first-order aberration to the catalog direction (brief l.41 (d); the annual aberration reaches about 20 arcsec, and a cluster symbol must sit on its stars), the horizon rotation and the optional refraction; it hides an object unless `mag <= limit - 8 B` or its major axis reaches the size limit, and unless its type flag is on (two `vec3` 0/1 uniforms, no integer uniform, plan Q47); it expands the corners to `max(4 px, tan(major) / tan(fov / 2) * height / 2)` in the billboard basis with the on-screen position angle from the north tangent. The fragment draws one procedural outline per type: galaxy ellipse with the ratio and the angle, open cluster dashed ring, globular cluster ring and plus, planetary nebula ring and centre dot, nebula square, other diamond. Limits in pure `sky/math/dso.ts`: magnitude 7 at a 90 degree field rising on the star log scale to 14 at 1 degree, or a manual `maglim + 1`; size `fov * 60 / 300` arcminutes (12 arcmin at 60 degrees). `disableDepthWrite`, `depthFunction ALWAYS`, `alphaIndex` 2. Backlog B-61 records the four-vertex quads instead of "instanced" and the aberration on catalog directions.
- Minor bodies (SKY-4; `layers/MinorLayer.ts`): the bodies shader (shared material) gains class 4, a flat disc whose radius is `clamp(1 + 0.5 (9 - mag), 1.5, 4)` css px (`sky/math/minorBodies.ts`), and class 5, a 30 px comet tail along the antisolar tangent projected on the billboard basis; two quads per slot; nothing is drawn for a body whose `samples` were `null`. `state/minorBodies.ts` fetches `/minor-bodies/defaults` once the layer is on and `/meta.catalogs.minor_bodies` exists (one attempt per arming; a 503 reads `missing`; "retry now" or toggling the layer retries); twenty defaults are requested until "show more" (session-only, backlog B-58); the URL `minor` carries the user's pins alone; the layer switch is disabled with the reason when the server has no MPC data.
- Constellations (SKY-5; `layers/ConstellationLayer.ts`): the 695 Stellarium line pairs resolved through `hipIndex` and recomputed from the star catalog at <= 10 Hz through `apparentStarEnuAt` (they follow proper motion, brief l.150) into one updatable `LinesMesh` created with vertex colours, so the highlight of the selected constellation, the dimming of the others and the night palette live in the `ColorKind` buffer alone (a vertex-coloured `LinesMesh` ignores `mesh.color`); the IAU boundaries are the served rings (`polygons`, both rings of Serpens) drawn as chords and rotated by `q_h` at <= 10 Hz, without densification (the corners are J2000-precessed B1875 edges and precession stays server-side, brief l.62; chord sag up to about 1 degree on the 30 degree edges, backlog B-61) and without refraction (like the grids: near the horizon a ring and the figure it encloses may differ by up to about 0.5 degree); the names are label candidates at `label.ra_deg/dec_deg`. The constellation of the selection is `details.con` (below), never a client-side polygon test.
- Labels and marker (VIEW-3; `layers/LabelLayer.ts`, pure `sky/math/labels.ts`): an engine-owned pool of 96 `<span>` in `labelRoot` plus one ring `div` (`[data-marker]`, `data-marker-id`). Every <= 10 Hz tick projects the candidates through the resolver, runs the greedy layout (a box to the right of its symbol, rectangle-overlap rejection, viewport and behind-camera culling) and writes only what changed: `textContent` and `data-label-id`/`data-label-kind` when a slot's id changes, `transform: translate3d(...)` when its rounded position moves, `hidden` when it empties; widths are measured once per text with an offscreen `measureText`, so the layout is deterministic and the e2e specs assert on the layout's own boxes. Candidates in priority order: the selection, the cardinal letters (`horizon` on), then under a non-zero budget the planets, the named stars by magnitude (density 1: brighter than 1.5, 2: brighter than 3, 3: every indexed star), the Messier objects, the constellation names (`cnames`), the minor bodies and the other named deep-sky objects; budget 0 / 14 / 36 / 90 for `labels=0..3`, the selection and the cardinal letters exempt (`labels=0` shows them alone, plan Q46). A star or deep-sky label is placed only while the shaders draw the object (the same effective magnitude and size limits, daylight fade included). The visible ids reach the store through `setVisibleLabels` at <= 1 Hz on change and the layers panel lists them as text (UX-4). React never touches the overlay; the PNG export composites it with `fillText`.
- Resolver (plan D94; `sky/engine/resolver.ts::SkyResolver` on the kernels of pure `sky/math/apparent.ts`): the single CPU twin of the shader pipeline (aberration on catalog directions, the horizon rotation, the D73 refraction on Earth). It turns `hip:<n>`, `dso:<id>` or `dso:M<n>` (matched case-insensitively, as `/sky/altaz` and the details panel do), a body id, `a:`/`c:` and, for centring only, `con:<abbr>` into an apparent ENU direction or a full `SelectionReadout` (refracted and geometric altitude, azimuth, RA/Dec in ICRS and of date through `equinoxQ`, distance, magnitude, phase, diameter; `NaN` unknown), memoising the last parsed id and allocating nothing per call. Labels, constellation lines, picking, follow, centring, the marker, the readout and the debug hook all read it, so the overlay and the picture cannot disagree.
- Picking (INFO-1; pure `sky/math/picking.ts`, `SkyEngine.pick`): a tap becomes an ICRF direction; a cone of 24 css px scaled by the field of view (plus 0.6 degree for refraction) pre-filters the stars up to the effective magnitude limit (binary search on the magnitude-sorted column), the deep-sky objects the shader shows, the bodies and the drawn minor bodies; the survivors are refined on screen and the nearest within the tolerance wins, ties within 3 px preferring body > minor > DSO > star; below an opaque ground nothing is picked. It runs on a tap, never per frame.
- Follow and centring (VIEW-4 [S], INFO-2): `follow` is transient (backlog B-60); the engine re-centres on the selection through `setView` on every frame (plan D139, the seam above). A `centreRequest` (search, the details "Centre" button) is served as soon as the resolver knows the object and cleared with `clearCentre(seq)`, dropped after 10 s or once the selection moved elsewhere (a `con:` request survives a selection).
- Night (UX-3, plan D108): `uNight = (on, level)` in the stars, bodies, DSO and background fragments (`rgb = vec3(dot(rgb, luma), 0, 0) * level`), `setNight` on the line and constellation layers; the level is `options.nightLevel` (0.3 to 1, `night=0.xx` in the URL).

### Selection and details (INFO-1; plan D106)

`state/detailsController.ts` is an engine ticker. Once the boot is `ready` it issues one `/sky/altaz` request for the selection (`refraction = refr && body === 'earth'`, `retry.maxAttempts = 1`) whenever the selection, the observer, that effective flag or the clock's control block changes, and otherwise at most once per second while time flows (`mode !== 'paused'`), with the engine's rendered `tt`; at most one request is in flight (a change aborts it); a 429 is honoured through the shared `api/rateGate.ts`, which `/minor-bodies/search` uses too (the server has one per-IP bucket, plan Q44), and the request is reissued once the gate opens, paused or not (a paused selection has no cadence to pick it up). ## Security and privacy (M6; plan D147-D150, D154, D166; ADR-0018)

Every security header of the web tier is defined once, in `frontend/security-headers.ts` (Node side: `CSP_GEOCODER_ORIGIN_DEFAULT`, `geocoderOriginFromEnv(env)`, `cspHeader({ geocoderOrigin, nonce? })`, `securityHeaders(...)`), and served by `vite preview` (`preview.headers`: what Playwright, `make lighthouse` and CI run against) and by `vite dev` (`server.headers` with a per-process nonce plus `html.cspNonce`); in the container stack nginx applies the same values once at http level (`frontend/nginx/templates/00-headers.conf.template`, rendered by the web image's entrypoint: `add_header ... always`, ADR-0024), `scripts/check_nginx_headers.mjs` diffs the template against the module on every `make check` (`check-delivery`) and `scripts/check_images.mjs` (e) probes the running image. Headers only: no `<meta http-equiv>` (it cannot carry `frame-ancestors`, cannot know the deployment's geocoder origin, would conflict with the dev nonce and covers the HTML document alone), no report endpoint (brief l.275 forbids storing requests), no COEP (nothing needs cross-origin isolation), no HSTS or `Cache-Control` here (nginx owns them through the `$sky_hsts` and `$sky_cache_control` maps of the same template). The one variable is `SKY_GEOCODER_ORIGIN` (backlog B-85): an origin, never a URL, equal to the origin of `SKYAPI_GEOCODER_URL`, read by `vite.config.ts` through `loadEnv(mode, <repository root>, 'SKY_GEOCODER_ORIGIN')` merged under `process.env` only when serving pages (`vite build` and vitest read no `.env`), default `https://nominatim.openstreetmap.org`; `csp.spec.ts` compares the served `connect-src` with `new URL(/meta.geocoder.url).origin`, and the production pair is item 1 of the release checklist ("Deployment" below; plan R104).

The CSP directives, one reason each: `default-src 'none'` closes everything not listed; `script-src 'self'` covers the module scripts under `/assets/` (the shipped bundle holds no `eval`, `new Function`, `WebAssembly`, inline script or `innerHTML`; WebGPU compiles WGSL twins and never downloads a wasm from a CDN, so no `'wasm-unsafe-eval'`); `style-src 'self'` covers the built stylesheet (no inline `style` attribute anywhere); `img-src 'self'` covers `/favicon.svg` and the PNG icons (the PNG export hands a `blob:` URL to a download anchor, not to an image); `connect-src 'self' <geocoder origin>` covers `/api/v1/*` on the same origin and the browser-direct Nominatim call (OBS-4); `manifest-src 'self'` the web manifest; `worker-src 'none'` (nothing spawns a worker in production; the dev variant opens `blob:` because Vite 8.3.0's client polls for a server restart from a `SharedWorker` built on a `blob:` URL and a tab would otherwise never reconnect, measured 2026-09-23); `media-src 'none'` (the camera `<video>` takes a `MediaStream` through `srcObject`, which no fetch directive governs); `object-src 'none'`; `base-uri 'none'`; `form-action 'none'` (every form submit is intercepted in script); `frame-ancestors 'none'`. Trusted Types (`require-trusted-types-for 'script'`) is not enforced at M6 and no `Report-Only` header exists: the suite proves Chromium only, so the decision waits for a `webkit` run and a Firefox pass (plan D154, Q69). The dev nonce is `randomBytes(16).toString('base64')` per `vite dev` process, stamped through `html.cspNonce` on Vite's injected tags (the Fast Refresh preamble and the dev client's `<style>` elements); after a dev-server restart the restart poller, which `worker-src blob:` lets run, reconnects and Vite reloads the tab with the new nonce (4.7 s in the Step F probe; a browser that has not accepted the dev certificate for the poller's WebSocket stays on `Polling for restart...` and needs a manual reload; plan R103).

The API adds two headers of its own (`middleware/headers.py::SecurityHeadersMiddleware`, pure ASGI; plan D149, backlog B-87): `X-Content-Type-Options: nosniff` and `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'; base-uri 'none'` on every response, appended only when absent; the Swagger page (`app.docs_url`, on GET alone: a 405 problem document on the same path stays strict) gets the relaxed `DOCS_POLICY` (`default-src 'none'; script-src https://cdn.jsdelivr.net 'unsafe-inline'; style-src https://cdn.jsdelivr.net 'unsafe-inline'; img-src https://fastapi.tiangolo.com data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'none'`; never `sandbox`). The middleware order is `RequestContextMiddleware` > `SecurityHeadersMiddleware` > `CORSMiddleware` > `GZipMiddleware` > app (plan D63 amended): placed outside CORS, the headers land on preflights (which `CORSMiddleware` answers itself), on problem documents and on 304s (`test_middleware.py`: 200, 400, 404, 304, 429, 503, the accepted and the refused preflight, 405, the docs page and its slash redirect). Starlette's `ServerErrorMiddleware` sits outside every user middleware, so the 500 handler of `middleware/problem.py` adds the same two headers itself beside `X-Request-Id` (`test_problems.py`); a 500 problem document carries no CORS headers and nginx adds none: the application only calls relative URLs on its own origin, so a cross-origin client seeing a network error for a 500 is accepted (plan D150, D166). The brief assigns the headers to nginx (l.274); the API adds these two because the dev and preview servers proxy `/api` upstream headers unchanged, so nothing else can put `nosniff` on the API in those stacks; in the container stack nginx adds the full web-tier set on `/api` too and the browser intersects the two policies (plan D193: +781 B per API response, a 304 about 1.1 kB instead of 0.3; probe 8 of `docs/testing.md` "Delivery (M7)" records the two `Content-Security-Policy` lines on `/api/v1/openapi.json`). No OAuth flow exists, so `swagger_ui_oauth2_redirect_url=None` keeps FastAPI from registering the root-level `/docs/oauth2-redirect` page (an inline script the strict policy would refuse; it answers 404 with the strict headers now).

Privacy (brief l.275): no account, cookie, Web Storage, IndexedDB, tracker, analytics or third-party script (the `noStorage` and `foreignRequests` fixtures assert it after every e2e test; the Swagger page's jsdelivr scripts exist in development only and are hidden at the edge in production); latitude and longitude are rounded to 0.01 degree before they leave the browser (OBS-7: `observerQuery` and the URL codec), the place search sends the typed text alone and a geolocation fix is never stored; the API's JSON access record carries the path and never the query string or a coordinate (`test_logging.py`), and the rate limiter keeps client addresses in memory only (buckets evicted after 60 s idle once the table exceeds 10,000 keys); `/meta.geocoder.email` is public by design (every browser forwards it to Nominatim, so never a private mailbox); `Referrer-Policy` and the referrer meta keep the URL's coordinates out of the Nominatim referer.

Dependency audits (brief l.276; plan D151, ADR-0019): `make audit` and the CI `audit` job run `npm audit`, `pip-audit` 2.10.1 over the exported lock and `scripts/check_audit.mjs` against `scripts/audit-allowlist.json`; the record and the allow-list rules are in `docs/testing.md` ("Audit record"). ## Deployment (M7; plan D169-D200; ADR-0023, ADR-0024, ADR-0025)

Development: `fastapi dev` (port 8000) and `vite` (port 5173, HTTPS via `@vitejs/plugin-basic-ssl` in development only) through `make dev`; `vite preview` on 4173 (HTTP) for Playwright, `make lighthouse` and the host-GPU checks (`docs/dev-wsl2.md`). Everything below is the container stack of `compose.yaml` (brief l.96, l.489): two services, no database, no volume of ours, the data directory bind-mounted from the host. The files: `backend/Dockerfile` and `backend/.dockerignore`, `frontend/Dockerfile` and `frontend/.dockerignore`, `frontend/nginx.conf` with `frontend/nginx/templates/*.template` and `frontend/nginx/sky/*.conf`, `compose.yaml`, `compose.tls.yaml`, `compose.e2e.yaml`, `data/.gitkeep`, `.env.example`; the rules in `.claude/rules/deploy.md`; the gates `scripts/check_nginx_headers.mjs` (`make check`) and `scripts/check_images.mjs` (`make images`, the CI `docker` job); the probe outcomes and the image figures in `docs/testing.md` "Delivery (M7)".

### Topology

- `api` (`intersidera-api:local`, `backend/Dockerfile`, ADR-0023): `python:3.14-slim` with the `skyapi` wheel and its locked non-dev dependencies installed by uv 0.12.19 in a builder stage (`uv sync --locked --no-dev --no-editable`, bytecode compiled; pip and ensurepip removed; the vendored test suites and the pyarrow Flight, cloud-filesystem, ORC and header files the API never loads removed in the builder stage (rungs 3-4 of the size ladder) and the stdlib `idlelib`, `tkinter` and `turtledemo` packages removed in the final stage (rung 5: slim installs no Tk library and nothing imports them); the rung reached is 5, recorded in "Delivery (M7)"), running `fastapi run --host 0.0.0.0 --port 8000 --workers ${SKYAPI_WORKERS:-1}` as uid:gid `${SKY_UID:-1000}:${SKY_GID:-1000}` on a read-only root with a 64 MB `/tmp` tmpfs, every capability dropped, `no-new-privileges`, a memory limit of `${SKY_API_MEMORY_LIMIT:-2G}` with `memswap_limit` equal to it (no swap for the api: an anonymous overrun is an OOM kill and a restart under `restart: unless-stopped`, never host swap thrash; plan Q97) and json-file logs capped at 10 MB x 3. It listens on the compose network only (nothing published) and is `healthy` when `/api/v1/health` answers 200 (`interval 30s, timeout 5s, retries 3, start_period 300s, start_interval 5s`; the probe is a `urllib.request` one-liner, the slim image having no curl). `SKYAPI_DATA_DIR=/data` and `FORWARDED_ALLOW_IPS=10.213.0.3` (`web`'s fixed address, the one address whose `X-Forwarded-For` uvicorn trusts) are set by compose and win over `.env`.
- `web` (`intersidera-web:local`, `frontend/Dockerfile`, ADR-0024): a `node:24` build stage runs `npm ci` and `npm run build` (the production build, grepped for `__sky`), removes `dist/.vite` and writes `.gz` siblings (`gzip -9 -k -n`, equal mtimes) for the text assets; the serving stage is `nginx:stable-alpine-slim` (nginx 1.30.5; backlog B-98) with `frontend/nginx.conf`, the templates rendered by the image entrypoint from `SKY_GEOCODER_ORIGIN` and `SKY_WEB_MODE` (envsubst, filter `^SKY_`), and `dist/` at `/usr/share/nginx/html`. It publishes 80 (and 443 with `compose.tls.yaml`), holds the fixed address `10.213.0.3` on the compose network (`x-sky.web_address`, `networks.default.ipv4_address`), starts only once `api` is healthy (`depends_on: condition: service_healthy`), runs read-only with tmpfs mounts on `/etc/nginx/conf.d`, `/var/cache/nginx` and `/run` (each `mode=0755`: Docker's default `1777` would let the uid-101 workers write the live configuration directory the root master re-reads on `nginx -s reload`), `cap_drop: [ALL]` plus `CHOWN, SETGID, SETUID, NET_BIND_SERVICE, KILL` (the root master must signal its uid-101 workers), and is `healthy` when `wget -q --spider http://127.0.0.1:80/healthz` succeeds (`interval 30s, timeout 3s, retries 3, start_period 10s, start_interval 2s`).
- The network `10.213.0.0/24` and `web`'s fixed address `10.213.0.3` on it are written once (`x-sky.subnet`, `x-sky.web_address`): the subnet is `networks.default.ipam.config`, the address is `web`'s `ipv4_address` and the api's `FORWARDED_ALLOW_IPS` (the one trusted `X-Forwarded-For` source; the gateway `10.213.0.1`, which relays the host's connections, stays untrusted); the network sits outside Docker's default pools and WSL 2's NAT range (plan D188, amended 2026-09-28).
- The data directory (brief l.96): `SKY_DATA_DIR` (`.env`, default `./data`) is bind-mounted at `/data` with `create_host_path: false` (a missing directory is a daemon error, never a root-owned directory Docker created); the host's `uv run --directory backend sky-data fetch` and the container's `docker compose run --rm api sky-data fetch` fill the same files; a clean clone owns `data/` as the cloning user through the tracked `data/.gitkeep` (backlog B-103). No data file is ever baked into an image (`docker history` shows no data layer).

### The request path

Browser -> nginx (`:80`, or `:443` with the :80 redirect in tls mode) -> either a file under `/usr/share/nginx/html` (`try_files $uri /index.html`: a deep link answers `index.html` with 200; a `.gz` sibling is served under `Accept-Encoding: gzip` with `Vary: Accept-Encoding`; the `Cache-Control` class and the seven security headers come from the http-level `00-headers.conf`) or, for `/api/`, `proxy_pass http://skyapi` -> `upstream skyapi` (`server api:8000 resolve`, the embedded resolver `127.0.0.11` re-read every 10 s, keepalive 16) -> uvicorn (`--proxy-headers` on by default: `X-Forwarded-For` and `X-Forwarded-Proto` from nginx, trusted from `web`'s address `10.213.0.3` only, so uvicorn stops at the address nginx appended, the real client on a Linux host or the gateway `10.213.0.1` behind Docker Desktop's userland proxy, and a client-supplied `X-Forwarded-For` never becomes the rate-limit key). Every response from nginx carries the seven headers (the 404 of a dotfile, the 504 and 502 while the api is down and the API's own responses included; on `/api/*` the API's `nosniff` and deny policy ride beside them, plan D193); `/api/v1/docs` and `/api/v1/docs/` answer 404 at the edge, `/api/v1/openapi.json` stays public; `/healthz` answers 204 without an access record; request lines above 8 kB answer 414; a request body above 16 kB 413. The API's `Cache-Control`, `ETag`, `Server-Timing`, `Retry-After` and `X-Request-Id` pass through unchanged, its gzipped JSON too, the SKYS uncompressed with `Accept-Ranges: bytes` (Range 206 through nginx). While the `api` container is stopped nginx answers 504 after `proxy_connect_timeout` (5 s: the connect attempt to the container's address gets no answer), and once the container is back but uvicorn does not listen yet it answers 502 at once (its inline pages, the seven headers); then comes the API's 503 `starting` with `Retry-After: 5`, then 200, within about 10 s of the API becoming ready if its address changed (the resolver re-reads it every 10 s; measured in the two acceptance runs of 2026-09-30: 504s for as long as the container stayed stopped (four requests over 20 s in each run, the last one the header dump; `upstream_time_s` 5.00 on each of run 1's, the run whose access log covers the down state), then 502, 503 and the first 200 at 3.5-5.0 s after `start`, `up -d --force-recreate api` and `restart api`): the client retries 429/502/503/504 by itself and polls `/health` (`retryOnStatus`, `pollHealth`).

### First start

```bash
cp .env.example .env    # de440s (development); production: SKYAPI_EPHEMERIS=de441.bsp, SKYAPI_WORKERS = cores, the geocoder e-mail, SKYAPI_CORS_ORIGINS, SKY_GEOCODER_ORIGIN
```

### Operations

- Logs: `docker compose logs -f api` and `docker compose logs -f web`; both services use the json-file driver capped at `10m` x `3` files. The api writes one JSON object per record (the path, the status, the duration and the request id; never a query string or a coordinate, brief l.275; the healthcheck probes appear as `/api/v1/health` records). nginx writes the `sky` format: `time` (ISO 8601), `status`, `method`, `path` (`$uri` after the `try_files` rewrite, so `/nowhere?lat=48.86&lon=2.35` is expected to be logged as `/index.html`; probe 23 of "Delivery (M7)" confirms it on the stack), `bytes`, `request_time_s`, `upstream_time_s`, `request_id` (the API's `X-Request-Id`); no request line, query string, referer, user agent or client address; `error_log` at `crit` inside http (request-bound error lines carry the client address and the query string; maintainer question 43), `log_not_found off`, no record for `/healthz`. Expected noise: the api log opens with fastapi-cli's plain-text banner (`Starting FastAPI in production mode`, `Documentation at http://0.0.0.0:8000/docs`, backlog B-26) before the JSON lines; while `api` is down the web log carries `[error] <pid>#<pid>: api could not be resolved (2: Server failure)` from the upstream resolver (the main-level `error_log ... warn`; no client data).
- Health: `docker compose ps` shows `healthy`, `unhealthy` or `starting`; `docker inspect --format '{{json .State.Health}}' intersidera-api-1` shows the probe log; `/api/v1/health` answers 503 `starting` with `progress` (a download) or `detail` (a fatal reason and its remedy), 200 `ready` or `degraded` with `missing`. Docker never restarts an unhealthy container (plan D200; `restart: unless-stopped` acts on process exit only, and the process stays up so the reason can be read): after a fatal bootstrap read `docker compose logs api`, fix the data (`docker compose run --rm api sky-data fetch`, `sky-data verify`, `sky-data build-caches`), then `docker compose restart api` and `docker compose up -d` to start `web` if `up --wait` had stopped.
- Weekly refresh (brief l.298; `docs/data.md`): `15 4 * * 1  cd /srv/intersidera && docker compose run --rm api sky-data update && docker compose restart api`; `web` needs no restart (the `resolve` upstream picks up the re-created `api` within 10 s). `sky-data update` refreshes the refreshable datasets (MPC weekly, OpenNGC and Stellarium yearly), rebuilds the cache groups whose sources changed and reminds you to restart; the `.bootstrap.lock` serialises the API's own workers only, hence update then restart.
- Restart and stop: `docker compose restart api` (while the container is stopped a request answers 504 after the 5 s `proxy_connect_timeout`; once it is back, 502 until uvicorn listens, then 503 `starting`, then 200: 3.0-3.9 s after `start`, `up -d --force-recreate api` and `restart api` in the rehearsal of 2026-09-28, 3.5-5.0 s in the two acceptance runs of 2026-09-30; every one of these pages carries the seven headers and the client retries them); `docker compose stop web` is expected under 2 s (0.656 s on 2026-09-30; the image's `STOPSIGNAL SIGQUIT` is a graceful shutdown the master commands through its workers' channels, so the stop itself needs no capability, 0.475 s in a control without `KILL`; the capability in `cap_add` serves the master's `SIGKILL` of a worker that ignores a fast shutdown; probe 27 of "Delivery (M7)" times the stop on the stack); `make down` = `docker compose down` keeps the data directory (never `-v`: there is no volume of ours to remove, and `-v` would touch nothing useful).
- Upgrading: `git pull`, `docker compose build --pull` (fresh base tags), `docker compose run --rm api sky-data verify` (a registry change may need `sky-data fetch`), `docker compose up -d --wait`; then the release checklist below. A configuration change to the templates needs a new image (`docker compose up -d --build`); a certificate rotation does not (below).
- TLS, path A, nginx terminates (brief l.96; plan D182; `compose.tls.yaml`): put root-owned copies of `fullchain.pem` and `privkey.pem` in `SKY_TLS_DIR` (default `./certs`, gitignored), made with `cp -L` from certbot's `live/<domain>/` (its entries are symlinks into `../../archive/` that dangle inside the container: never bind-mount that directory); the files must be root-owned (a root-owned 600 key is fine) or readable by others, because the root master runs without `CAP_DAC_OVERRIDE` (`cap_drop: [ALL]`) and a 600 key owned by another user restart-loops `web` (probe 19 of "Delivery (M7)"; the two troubleshooting rows below); set `SKY_WEB_MODE=tls` (the overlay sets it too) and run `docker compose -f compose.yaml -f compose.tls.yaml up -d --build --wait`, or `export COMPOSE_FILE=compose.yaml:compose.tls.yaml` in the shell (never in `.env`: `env_file` would hand it to the api container). The :80 server answers `/healthz` 204 and redirects everything else to `https://$host$request_uri` (a non-standard port is dropped, plan R132); the :443 server (`http2 on`, TLS 1.2 and 1.3, the Mozilla intermediate ECDHE list, no stapling, tickets off) serves the app; HSTS `max-age=31536000; includeSubDomains` is sent on TLS connections only and never `preload` (maintainer question 39). Rotation: copy the new pair again with `cp -L` (root-owned), then `docker compose exec web nginx -s reload`. Renewal happens outside nginx (DNS-01 or an external ACME client): `location ~ /\. { return 404; }` blocks HTTP-01 under `/.well-known/`, so an explicit `location ^~ /.well-known/acme-challenge/` must be added to `frontend/nginx/sky/app.conf` if HTTP-01 is wanted (maintainer question 41).
- TLS, path B, an external proxy (plan D182): keep `SKY_WEB_MODE=http`, narrow `web` to loopback in the gitignored `compose.override.yaml` (`services: { web: { ports: !override ["127.0.0.1:8080:80"] } }`) and let the proxy forward to it with `X-Forwarded-For` and `X-Forwarded-Proto`. The proxy owns HSTS. nginx appends the address it sees the proxy from to `X-Forwarded-For`, and uvicorn takes the first untrusted address from the right while trusting `web`'s address `10.213.0.3` alone: without an override the proxy's own address (the gateway `10.213.0.1` for a host process behind Docker Desktop) is the rate-limit key, one bucket shared by every client behind the proxy and never a forged key; a proxy whose `X-Forwarded-For` must be honoured is appended after the web address in the override (`services: { api: { environment: { FORWARDED_ALLOW_IPS: "10.213.0.3,<the proxy's address as nginx sees it>" } } }`, plan D182), never `*` and never the whole network (a client relayed by the gateway could then forge the key).
- Disk and memory: the two images (the table above), the data directory (612 MB with de440s, 3,949,027,410 B with de441, MPCORB and the caches; `du -sb data/`), the logs (at most 30 MB per service), the tmpfs mounts (api `/tmp` 64 MB; web 1 MB + 256 MB + 1 MB), which count against the containers' memory (plan R142); `SKY_API_MEMORY_LIMIT` follows 1 GB plus 1 GB per worker (a worker serving concurrent 100-body frames peaks near 1 GB, plan R114; maintainer question 46) and `memswap_limit` equals it in `compose.yaml`, so the api gets no swap (plan Q97: Docker would otherwise grant as much swap again).
- Backups: none of ours. Every file in the data directory is re-downloadable (`sky-data fetch`) or rebuildable (`sky-data build-caches`), the manifests with them; no user data exists anywhere (brief l.275, no persistence). Keep `.env` and the certificates.
- Local overrides: `compose.override.yaml` (gitignored, read automatically by `docker compose`) holds the host's ports and, on a subnet collision, every use of the network (the subnet, `web`'s address, `FORWARDED_ALLOW_IPS`; below).

### Release checklist

1. `SKY_GEOCODER_ORIGIN` equals the origin of `SKYAPI_GEOCODER_URL` (plan R104, backlog B-85): `docker compose exec web nginx -T | grep connect-src` names the origin `/api/v1/meta` advertises in `geocoder.url`.
2. HSTS ownership decided with the TLS termination (maintainer questions 39, 40): nginx in tls mode sends `max-age=31536000; includeSubDomains` on TLS only; behind an external proxy the proxy sends it; never `preload`.
3. Root-owned `cp -L` copies of `fullchain.pem` and `privkey.pem` in `SKY_TLS_DIR` (a 600 key must be root-owned: the master runs without `CAP_DAC_OVERRIDE`; never a bind mount of certbot's `live/<domain>/` symlinks) with renewal outside nginx (DNS-01 or an external ACME client), or an explicit `location ^~ /.well-known/acme-challenge/` added before `location ~ /\.` (maintainer question 41); rotation = copy again with `cp -L`, then `docker compose exec web nginx -s reload`.
4. `SKYAPI_GEOCODER_EMAIL` is a public contact address: `/api/v1/meta` advertises it and every browser forwards it to Nominatim.
5. `SKYAPI_CORS_ORIGINS` = the app origin (behind nginx the API requests are same-origin and no CORS request happens); the development `https://localhost:5173` must not ship.
6. `SKYAPI_WORKERS` = the CPU cores and `SKY_API_MEMORY_LIMIT` = 1 GB plus 1 GB per worker (maintainer question 46), checked against the recorded first-start `memory.peak`; `memswap_limit` follows the limit in `compose.yaml` (no swap for the api, plan Q97).
7. `SKYAPI_EPHEMERIS=de441.bsp` and `docker compose run --rm api sky-data fetch --full` done before the first `up` (3.3 GB; `sky-data status` lists it present).
8. The `SKYAPI_AUTO_FETCH` policy decided (maintainer question 47): `false` with the out-of-band `fetch`/`update` above, or `true` accepting a download at a restart after a registry change.
9. The data directory exists and is owned by `SKY_UID:SKY_GID` (`ls -ld $SKY_DATA_DIR`; compose never creates it); `docker compose run --rm api sky-data verify` exits 0.
10. `FORWARDED_ALLOW_IPS` is `web`'s fixed address `10.213.0.3` as compose sets it (`docker compose exec api sh -c 'echo $FORWARDED_ALLOW_IPS'`); an external proxy whose `X-Forwarded-For` must be honoured is appended after it in `compose.override.yaml` (its address as nginx sees it); never `*`, never the whole network.
