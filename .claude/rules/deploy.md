# Deployment rules (the container images, the nginx edge, compose)

- The runbook, the operations and the numbered release checklist live in `docs/architecture.md` "Deployment"; the probe outcomes and the image figures in `docs/testing.md` "Delivery (M7)"; the decisions in ADR-0023 (images and docker gates), ADR-0024 (the nginx edge) and ADR-0025 (compose and operations). Committed non-doc files (compose, Dockerfiles, nginx, scripts) cite documents by section, never a plan number; every figure a running stack or a built image supplies is measured, never estimated, and recorded per architecture.
- `backend/Dockerfile` (plan D169, D170; brief l.35, l.394, l.489): two stages on `ARG PYTHON_IMAGE=python:3.14-slim`; uv comes only into the builder (`COPY --from=ghcr.io/astral-sh/uv:0.12.19 /uv /uvx /bin/`, an exact pin); `UV_COMPILE_BYTECODE=1 UV_LINK_MODE=copy UV_PYTHON_DOWNLOADS=never`; layer 1 `uv sync --locked --no-dev --no-install-project` on bind-mounted `uv.lock`, `pyproject.toml`, `.python-version`, `README.md`, layer 2 `COPY src/` then `uv sync --locked --no-dev --no-editable` (the project is a wheel built by the bundled `uv_build`, no `src/` at run time); the final stage copies `/app/.venv` and `/app/pyproject.toml` only (fastapi-cli reads `[tool.fastapi] entrypoint` from the working directory's `pyproject.toml`, so `WORKDIR /app` stays), removes pip and ensurepip, creates `skyapi` as uid:gid 1000:1000, sets `HOME=/tmp`, `SKYAPI_DATA_DIR=/data`, `PYTHONDONTWRITEBYTECODE=1`, `PYTHONUNBUFFERED=1`, runs as `USER 1000:1000` and ends with an exec-form `CMD ["fastapi", "run", "--host", "0.0.0.0", "--port", "8000"]` and no `ENTRYPOINT` (so `docker compose run --rm api sky-data fetch` replaces the command). `ARG GIT_SHA`/`BUILD_DATE` are declared after the last `RUN`, right before `LABEL` (a changed ARG invalidates every later RUN). No data file ever enters an image (brief l.96, l.556). Never an alpine Python (l.35), never a dropped bytecode compile (l.489), never `strip`, never a dependency edit for size: the trim ladder (rung 2 pip and ensurepip; rungs 3-4 the vendored `tests` directories and the pyarrow Flight/cloud/ORC/header components the API never loads, in the builder stage; rung 5 the stdlib `idlelib`, `tkinter` and `turtledemo` packages, in the final stage, never a stdlib module the API imports) is the only size lever, measured rung by rung (ADR-0023; rung 5 was needed: rungs 2-4 alone left 395,875,816 B on arm64, 4.1 MB under the budget).
- `frontend/Dockerfile` (plan D174, D175; brief l.35, l.370, l.410, l.556): `node:24` build stage (`npm ci --no-audit --no-fund` with a `/root/.npm` cache mount, `NODE_ENV` unset so `tsc -b` has its devDependencies), `ARG BUILD_SCRIPT=build` declared after `COPY . .` (`build:e2e` only through `compose.e2e.yaml`; the production build is grepped for `__sky` and fails the build when it appears), `rm -rf dist/.vite`, `.gz` siblings by `gzip -9 -k -n` + `touch -r` for `.js .css .svg .webmanifest .html .json` (never PNG; `gzip_static` wants equal mtimes; a failing `gzip` or `touch` on any file fails the build: the loop exits 1 instead of reporting its last iteration only); the serving stage is `nginx:stable-alpine-slim` (backlog B-98: the brief's `nginx:stable-alpine` measures 66,039,808 B unpacked, over the 50 MB budget of l.299 before any asset) with the stock `default.conf` and welcome pages removed, `nginx.conf` at `/etc/nginx/nginx.conf`, `nginx/templates/` and `nginx/sky/` copied, `ENV SKY_GEOCODER_ORIGIN=<CSP_GEOCODER_ORIGIN_DEFAULT> SKY_WEB_MODE=http NGINX_ENVSUBST_FILTER=^SKY_ NGINX_ENTRYPOINT_QUIET_LOGS=1` and a `wget -q --spider http://127.0.0.1:80/healthz` HEALTHCHECK (the slim image has no curl). `scripts/check_chunks.mjs` stays in `make build` and the CI frontend job, never in the image build (it needs the repository root).
- The nginx tree (`frontend/nginx.conf`, `frontend/nginx/templates/*.template`, `frontend/nginx/sky/*.conf`; plan D179-D186, D193; ADR-0024): the nine `add_header ... always` directives live ONCE at http level in the rendered `conf.d/00-headers.conf` (the seven values of `frontend/security-headers.ts` byte for byte with `${SKY_GEOCODER_ORIGIN}` in `connect-src`, plus `Cache-Control $sky_cache_control` and `Strict-Transport-Security $sky_hsts` from `map` variables, an empty value adding no header); nothing below http may declare `add_header` (nginx inherits `add_header` only into scopes that declare none of their own: one `add_header Cache-Control` in a location would drop every security header there), no `add_header_inherit`, no `Content-Security-Policy-Report-Only`, no `upgrade-insecure-requests` (byte identity with `cspHeader()`), HSTS `max-age=31536000; includeSubDomains` from the `$https` map only and never `preload`. `gzip off` everywhere; `gzip_static on; gzip_vary on;` in the app server for the build-time siblings; the API's gzipped JSON passes through and the SKYS stays uncompressed with its strong `ETag`, `Accept-Ranges` and Range 206 (B-46, B-84, B-99). The access log is the `sky` JSON format with the path only (`$uri`, never `$request`, `$request_uri`, `$args`, the referer, the user agent or a client address; brief l.275), `error_log crit` at http level, `log_not_found off`, `/healthz` `access_log off`. The upstream is `upstream skyapi { zone skyapi 64k; server api:8000 resolve; resolver 127.0.0.11 valid=10s ipv6=off; ... }` (no parse-time DNS: `nginx -t` passes outside the network and a re-created `api` is picked up within 10 s); `location ^~ /api/` proxies with `proxy_hide_header Server`, `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for` (the api trusts `web`'s fixed address alone, so uvicorn stops at the address nginx appends here and never reads a client-supplied entry) and no `proxy_intercept_errors` (the API's 503 body drives the splash); `location ~ /\. { return 404; }`, `location = /api/v1/docs { return 404; }` and its slash twin, `try_files $uri /index.html`; `server_tokens off` (`Server: nginx` remains: OSS nginx cannot omit it); `SKY_WEB_MODE=http|tls` selects `include /etc/nginx/sky/mode-${SKY_WEB_MODE}.conf` (envsubst has no conditionals); the tls server uses the Mozilla intermediate ECDHE list, `ssl_protocols TLSv1.2 TLSv1.3`, `ssl_session_tickets off`, no stapling, no `ssl_dhparam`. The only variables the templates may reference are `${SKY_GEOCODER_ORIGIN}` and `${SKY_WEB_MODE}`; `scripts/check_nginx_headers.mjs` (`make check-delivery`, the CI frontend job) fails on any other placeholder and on every deviation from the list above, with a 19-mutation self-test on every run. nginx >= 1.30.4 (CVE-2026-42533, the `map` regex plus a non-cacheable variable).
- `compose.yaml` (plan D187-D189, D194; ADR-0025): `name: intersidera`; the compose network and `web`'s fixed address on it are written once (`x-sky.subnet: &sky_subnet 10.213.0.0/24`, `x-sky.web_address: &sky_web 10.213.0.3`): the subnet feeds `networks.default.ipam.config`, the address feeds `web.networks.default.ipv4_address` and `FORWARDED_ALLOW_IPS` on `api` (that one address, never the whole network and never `*`: the gateway `10.213.0.1` relays the host's connections and, behind Docker Desktop's userland proxy, every published-port connection, so with the /24 trusted a client-supplied `X-Forwarded-For` became the rate-limit key; with the address alone uvicorn stops at the address nginx itself appends and a forged header is keyed like an unforged one); a collision is fixed through the gitignored `compose.override.yaml` (every use: the subnet, the address, the variable), never by editing the base file. `api`: `env_file: [{ path: .env, required: false }]`, `SKYAPI_DATA_DIR: /data`, the exec-form `command` with `--workers ${SKYAPI_WORKERS:-1}` (an image CMD never expands variables), the bind mount `${SKY_DATA_DIR:-./data}:/data` with `create_host_path: false` (a missing directory is a daemon error, never a root-owned directory), `user: "${SKY_UID:-1000}:${SKY_GID:-1000}"`, `read_only: true`, a sized `/tmp` tmpfs, `cap_drop: [ALL]`, `security_opt: [no-new-privileges=true]` (the `=` form), the same healthcheck values as the Dockerfile (`interval 30s, timeout 5s, retries 3, start_period 300s, start_interval 5s`), `restart: unless-stopped`, `deploy.resources.limits.memory: ${SKY_API_MEMORY_LIMIT:-2G}` (1 GB plus 1 GB per worker) with `memswap_limit: ${SKY_API_MEMORY_LIMIT:-2G}` (equal to the limit: no swap for the api, an anonymous overrun is an OOM kill and a restart, never host swap thrash; plan Q97), json-file logging `10m` x `3`. `web`: `depends_on: api: condition: service_healthy`, `SKY_GEOCODER_ORIGIN` and `SKY_WEB_MODE` with defaults, `ports: ["80:80"]` (443 only through `compose.tls.yaml`; loopback-only ports through `compose.e2e.yaml`), `networks.default.ipv4_address: *sky_web`, `read_only: true` with the three nginx tmpfs mounts (`/etc/nginx/conf.d:size=1m,mode=0755`, `/var/cache/nginx:size=256m,mode=0755`, `/run:size=1m,mode=0755`: Docker's default tmpfs mode is `1777`, which would let the uid-101 workers write nginx's live configuration directory; the root master and the entrypoint need no world-writable mount), `cap_drop: [ALL]` plus `cap_add: [CHOWN, SETGID, SETUID, NET_BIND_SERVICE, KILL]` (without `KILL` the root master cannot signal its uid-101 workers), the same `security_opt`, healthcheck, restart and logging. No `version:` key, no named volume, no port published beyond 80 in the base file, no `.env` value copied into the compose file, no `SKYAPI_*` or `VITE_*` variable added (the compose-tier variables are `SKY_*`, backlog B-101). Every compose key used must exist on Compose 2.38 (the runner today), 5.1 and 5.3.
- Overlays: `compose.tls.yaml` (`SKY_WEB_MODE: tls`, `443:443`, `${SKY_TLS_DIR:-./certs}:/etc/nginx/certs:ro` with `create_host_path: false`; rotation = copy + `docker compose exec web nginx -s reload`); `compose.e2e.yaml` is the acceptance overlay only (de440s, `SKYAPI_AUTO_FETCH="false"`, `127.0.0.1:8000:8000`, the `build:e2e` image tagged `intersidera-web:e2e`, `ports: !override ["127.0.0.1:4173:80"]`) and never a deployment (with 8000 published, host clients reach uvicorn directly from the gateway, an address the api does not trust, so their `X-Forwarded-For` is ignored: loopback only, acceptance only). `COMPOSE_FILE` is a shell export, never a `.env` line (it would leak into the api container through `env_file`).
- `scripts/check_images.mjs` (plan D192; the CI `docker` job and `make images`, never `make check`): Node built-ins plus `../frontend/security-headers.ts` through type stripping; docker through `execFileSync`/`spawn` argument arrays, never a shell string; probes through `node:http`, never curl; the size figure of record is the `docker export` payload (store-independent), the containerd `Unpacked`/`Content`, `inspect .Size` and the gzip -9 `docker save` size printed beside it and never gated; `--api-reading compressed` only ever with backlog row B-111 cited beside the flag; containers named `isd-check-<pid>-*` removed in `finally` and on SIGINT/SIGTERM; the data-less api of checks (f)-(j) runs `--read-only` with tmpfs `/tmp` and `/data` mounts, as compose runs it; the web image of check (e) runs with the compose hardening too (`--read-only`, the three tmpfs mounts at `mode=0755`, `--cap-drop ALL` plus `CHOWN`, `SETGID`, `SETUID`, `NET_BIND_SERVICE` and `KILL`, `no-new-privileges`), asserts the access log, the container's stdout (the line of the query-string probe carries `"path":"/index.html"`; one line per request outside `/healthz`; never `lat=`, `lon=`, `?` or an IPv4 address, the client's included), and ends with `docker exec <c> nginx -s reload`: exit 0, every worker replaced (`docker top`), `/healthz` still 204 and no `failed` line in the error log, the container's stderr, apart from the resolver's `... while resolving, resolver: 127.0.0.11:53` lines (outside compose no embedded DNS answers the upstream's resolver); check (g) asserts the last health-log entry's `ExitCode` 1 and urllib's `HTTP Error 503` in its output (the probe judged the 503), never a bare `unhealthy`, which a probe that cannot run, or that fails before it reaches the API, would also produce; `--self-test` proves the tar parser on GNU-format and pax-format tars; exit 0/1/2. `hadolint` runs as the pinned image `ghcr.io/hadolint/hadolint:v2.15.1` over stdin (`docker run --rm -i ... < Dockerfile`), so a `.hadolint.yaml` is invisible: exceptions are inline `# hadolint ignore=<ids>` lines with a reason, never a configuration file.
- Do not: bake a data file into an image; run the api container as root or without `read_only`; declare `add_header` below http level or `gzip on` in the edge; set `PORT` anywhere (`fastapi run` reads it as its port); publish a port beyond 80 in `compose.yaml`; set `FORWARDED_ALLOW_IPS` to `*` or to the whole compose network (the gateway relays host connections, so a client could forge its rate-limit key; `web`'s fixed address alone); use `docker compose down -v`; pin a base image by digest in the Dockerfile (tags float like `.node-version`; the resolved digests are recorded at each release); pass `--platform` or name an architecture outside a comment (brief l.270: the same files build linux/amd64 in CI and linux/arm64 here); register QEMU handlers without the maintainer.
