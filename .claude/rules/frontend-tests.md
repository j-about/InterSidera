# Frontend test rules (Vitest, Testing Library, Playwright)

- Vitest is configured in `vite.config.ts` (`defineConfig` from `vitest/config`): `environment: 'jsdom'`, `globals: true`, `setupFiles: ['./src/test/setup.ts']`, explicit `include: ['src/**/*.{test,spec}.{ts,tsx}']` and `exclude` re-adding `e2e/**` and `dist/**` (Vitest 4 excludes only `node_modules` and `.git` by default). `test.projects`, never `workspace`.
- `src/test/setup.ts` imports `@testing-library/jest-dom/vitest` (the `/vitest` subpath) and `../i18n` so components render real translations.
- Coverage gate (plan D88): `npm run test` = `vitest run --coverage` with `coverage.include: ['src/sky/math/**/*.ts', 'src/state/url.{ts,tsx}']`, `exclude: ['**/*.test.ts', 'src/test/**']` (load-bearing in Vitest 4) and 100 % thresholds on lines, functions, branches and statements; `make check` and CI run it. Subset runs use `vitest run --coverage=false <paths>`. Never lower a threshold; cover the line or delete dead code.
- Pure-module tests start with `// @vitest-environment node` (no jsdom cost, no DOM). Fixtures come from `backend/tests/fixtures/*.json` through `src/test/fixtures.ts` (`node:fs` + `new URL(..., import.meta.url)` with structural type guards); never copy fixture numbers into a test.
- Unit tests cover `sky/math`, `state/{url,clock,frames,store,urlSync,boot}` and `api/{client,catalogs}` against the shared fixtures and fake fetches (`vi.fn<typeof fetch>`, `Response` objects); Testing Library smoke tests cover components with a fake engine factory and a fake frame controller (`fetch` stubbed to hang so the boot never reaches the network). Babylon.js never runs in jsdom: engine and shader behaviour are tested only in Playwright.
- Playwright projects (plan D89): `chromium-desktop` (Desktop Chrome), `chromium-mobile` (Pixel 7) and `webkit` (Desktop Safari) ignore `webgpu.spec.ts`; `chromium-webgpu` (`channel: 'chromium'`, `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader`) runs only `webgpu.spec.ts`. `make e2e` and CI run `chromium-desktop` and `chromium-mobile`; `webkit` and `chromium-webgpu` are manual. `baseURL` is `http://127.0.0.1:4173` (`vite preview` of the `--mode e2e` build); the API runs on `http://127.0.0.1:8000` with `SKYAPI_AUTO_FETCH=false` and `SKYAPI_EPHEMERIS=de440s.bsp`. Use `127.0.0.1`, never `localhost` (may resolve to `::1`).
- `trace: 'retain-on-failure'`; `retries: 1` and `workers: 1` in CI only; `forbidOnly` in CI. Specs that wait for the first frame set `test.describe.configure({ timeout: 180_000 })`: SwiftShader compiles the shaders and uploads 471,820 vertices.
- The `window.__sky` debug hook exists only in dev and e2e builds (`tsconfig.node.json` has `lib: DOM` so specs can type it). Specs import its type only as `import type { SkyDebugApi } from '../src/debug/skyDebugApi.ts'` (explicit extension) and nothing else from `src/`. Functions passed to `page.evaluate` are serialized: they must reach the hook through `window.__sky` directly and cannot call helpers of the spec. Sanity checks: `isReady`, `backend`, `altAzOf('hip:11767').alt` within 1 degree of 51.48 from Greenwich, a planet's `altAzOf` within 1 arcmin of `/sky/altaz` at the same `tt` with matching `refr`/`refraction`, `setTime` + `waitForFrame` + `state().tt` for a rendered instant, `setView` + `screenOf` for the projection.
- No request may leave for an origin other than the app (`page.on('request')` asserts every `http(s)` host is `127.0.0.1`) and, from M4, the configured geocoder; tests never call Nominatim or Horizons. `url-state.spec.ts` asserts the absence of cookies, localStorage, sessionStorage and IndexedDB databases (OBS-8).
- Suites: smoke, engine (WebGL2), webgpu, url-state (M3); selection, search, time, night-mode, mobile to grow (brief l.385).
- Browsers on this WSL: either `sudo env "PATH=$PATH" fnm exec --using=24 npm --prefix frontend exec -- playwright install-deps` once, or the sudo-free `~/.local/pw-libs` directory exported through `LD_LIBRARY_PATH` and `FONTCONFIG_PATH` (docs/dev-wsl2.md). `TextRunHarfBuzz error` lines on stderr are font noise. CI runs Chromium only.
- Never skip, weaken, delete or mark a test as expected failure to make a gate pass; when the engine or the store misbehaves, report the failure instead of adapting the spec.
