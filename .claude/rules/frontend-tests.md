# Frontend test rules (Vitest, Testing Library, Playwright)

- Vitest is configured in `vite.config.ts` (`defineConfig` from `vitest/config`): `environment: 'jsdom'`, `globals: true`, `setupFiles: ['./src/test/setup.ts']`, explicit `include: ['src/**/*.{test,spec}.{ts,tsx}']` and `exclude` re-adding `e2e/**` and `dist/**` (Vitest 4 excludes only `node_modules` and `.git` by default). `test.projects`, never `workspace`.
- `src/test/setup.ts` imports `@testing-library/jest-dom/vitest` (the `/vitest` subpath) and `../i18n` so components render real translations, polyfills `HTMLDialogElement.showModal`/`close` (the `open` state, the focus moved inside and restored to the opener, the `close` event; no top layer or inert, which Playwright asserts; backlog B-65) and stubs `window.matchMedia` to "no match" (the phone layout, no reduced motion); both shims are skipped under the node environment. Test-only support modules: `src/test/fixtures.ts` (the shared backend fixtures), `src/test/fakeBundle.ts` (a small real-star `CatalogBundle` and `/meta`), `src/test/meta.ts` (a complete `/meta`, `makeMeta` overrides); application code never imports `src/test/`.
- Coverage gate (plan D88): `npm run test` = `vitest run --coverage` with `coverage.include: ['src/sky/math/**/*.ts', 'src/state/url.{ts,tsx}']`, `exclude: ['**/*.test.ts', 'src/test/**']` (load-bearing in Vitest 4) and 100 % thresholds on lines, functions, branches and statements; `make check` and CI run it. The M4 pure modules `sky/math/{apparent,dso,labels,atmosphere,minorBodies,picking}.ts` fall under it; the pure `state/*`, `search/*`, `api/{geocoder,rateGate}` and `i18n/*` modules are tested exhaustively but stay outside the include (plan Q48). Subset runs use `vitest run --coverage=false <paths>`. Never lower a threshold; cover the line or delete dead code.
- Pure-module tests start with `// @vitest-environment node` (no jsdom cost, no DOM). Fixtures come from `backend/tests/fixtures/*.json` through `src/test/fixtures.ts` (`node:fs` + `new URL(..., import.meta.url)` with structural type guards); never copy fixture numbers into a test. Zone-dependent logic (`state/timeDisplay.ts`) takes an injected `offsetAt`; the negative-year and DST editor cases live here, not in Playwright (de440s covers 1849-2150).
- Unit tests cover `sky/math`, `state/*` and `api/*` against the shared fixtures and fake fetches (`vi.fn<typeof fetch>`, `Response` objects, injected `fetchAltAz`/`fetchDefaults`/`search`/`geocode` functions and clocks), `search/*` and `i18n/*` against `fakeBundle`. Testing Library covers every component with a real store (`createSkyStore`) and fakes for the engine factory, the frame controller, geolocation, the geocoder and `fetch` (stubbed to hang so the boot never reaches the network): one `*.test.tsx` per component, asserting roles, names and store writes, not markup. Babylon.js does not run under Vitest, with exactly one sanctioned exception (plan D161, backlog B-93): `sky/engine/xr/XrBridge.test.ts` (`// @vitest-environment node`) drives the bridge on Babylon's `NullEngine` with a fake experience handed through `XrBridge.create`'s test-only `createExperience` parameter around a real `WebXRCamera` (the rig zeroing, the yaw composition, `delta0` from a compass heading, the nudges, the `NOT_TRACKING` guard, the fov mirror); every other engine, layer and shader behaviour is tested only in Playwright. The debug hook has one unit test, `debug/skyDebug.test.ts` (jsdom, a fake engine, no Babylon): `timing()` answers `{ timeOrigin, marks: {}, navigation: null }` and `resources()` `[]` where the Performance classes are missing, the `sky:*` marks report their last occurrence, `afterFrames(n)` settles, `stats()` answers zeros for `frames`, the cost rings and `renderWidth`/`renderHeight` on the `NO_PERF` fallback, and `performance.setResourceTimingBufferSize(1000)` is called at install. Area A's jsdom suites (M5) inject what jsdom 30 lacks: `sky/ar/sensors.test.ts` passes a plain `OrientationSensorTarget` (jsdom has neither `ondeviceorientationabsolute` nor `screen.orientation`; the WebKit compass fields are added to the event instances with `Object.defineProperty`), `sky/ar/offsetDrag.test.ts` defines `clientHeight` by hand on the overlay root, and `sky/engine/CameraController.test.ts` drives a fake canvas (`clientWidth`/`clientHeight`, `getBoundingClientRect`, `hasPointerCapture` and `releasePointerCapture` defined by hand; `setPointerCapture` stays missing and the controller guards it) with `Date.now` mocked through `vi.spyOn`; area B's `sky/ar/cameraVideo.test.ts` injects a duck-typed stream and track, an element whose `play()` returns a Promise (jsdom's returns `undefined`) and a page object with a writable `visibilityState`. AR component tests (M5): the fake `SkyEngineApi` of `ui/ar/ArOverlay.test.tsx` returns its `enterXr`/`exitXr` mocks as locals beside the engine object (asserting on `engine.enterXr` trips `@typescript-eslint/unbound-method`); `TimeOffsetBadge.test.tsx` runs under `vi.useFakeTimers()` with `vi.setSystemTime` and drives the clock through `setTime(tt, nowMs)` and `publishTt`; `App.test.tsx` awaits the lazy overlay with `findByRole` and drives the store (`setArCapabilities`, `requestAr`, `setArMode`, `exitAr`) to prove the swap and the focus return; `ArButton.test.tsx` proves the call order (`pending`, the helper, `requestAr`) with a `store.subscribe` log and an injected `requestPermission`, and with two unsettled promises that the late outcome of an exited tap never overwrites a fresh `pending` (a rejecting helper records `prompt`).
- Playwright projects (plan D89, D146): `chromium-desktop` (Desktop Chrome), `chromium-mobile` (Pixel 7, `hasTouch`) and `webkit` (Desktop Safari) carry `testIgnore: /(webgpu|perf)\.spec\.ts/`; `chromium-webgpu` (`channel: 'chromium'`, `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader`) runs only `webgpu.spec.ts`; `perf` (Desktop Chrome) runs only `perf.spec.ts`, the measurement file (the four-profile boot matrix through CDP `Network.emulateNetworkConditions` and the sampling heap profile, each attached as JSON under `test-results/`; it runs `test.describe.configure({ mode: 'default', timeout: 300_000 })` so `npm run e2e -- --project=perf` uses one worker and never skips a measurement after another fails). `make e2e` and CI run `chromium-desktop` and `chromium-mobile`; `webkit`, `chromium-webgpu` and `perf` are manual. `baseURL` is `http://127.0.0.1:4173` (`vite preview` of the `--mode e2e` build); the API runs on `http://127.0.0.1:8000` with `SKYAPI_AUTO_FETCH=false` and `SKYAPI_EPHEMERIS=de440s.bsp` (a reused local server must run de440s too: the time spec relies on year -44 lying outside the coverage). Use `127.0.0.1`, never `localhost` (may resolve to `::1`).
- `trace: 'retain-on-failure'`; `retries: 1` and `workers: 1` in CI only; `forbidOnly` in CI. One boot per scenario: one `test()` with `test.step` inside and `test.describe.configure({ timeout: 180_000 })` (SwiftShader compiles the shaders and uploads 471,820 vertices); the one scenario split over three `test()` blocks for the 180 s cap is `a11y.spec.ts` (the keyboard, name and landmark mechanics; the eight light-scheme axe scans; the five night and scheme axe scans), split at M6 because its 120 s alone approached the cap under five workers and a two-way cut still left the axe block at 168 s there (93 % of the cap), never by raising the cap or dropping a scan; `mobile.spec.ts` skips off the phone project and `a11y.spec.ts` on it (a project condition, never a data condition).
- Data conditions never skip: read `/api/v1/meta` through `support.ts::metaOf(page)` (after `waitReady` when the page is up) and branch on what the server has (`catalogs.minor_bodies` absent in CI: `/health` `degraded`, `missing: ["mpc"]`, `/minor-bodies/*` 503; `geocoder.enabled` and `geocoder.email`; `coverage.ephemeris_tt`), so the same spec passes on the CI data set (de440s, no MPCORB) and on the full local data.
- The `window.__sky` debug hook exists only in dev and e2e builds (`tsconfig.node.json` has `lib: DOM` so specs can type it). Specs import its type only as `import type { SkyDebugApi } from '../src/debug/skyDebugApi.ts'` (explicit extension) and nothing else from `src/`. Functions passed to `page.evaluate` are serialized: they must reach the hook through `window.__sky` directly and cannot call helpers of the spec. Sanity checks: `isReady`, `backend`, `altAzOf('hip:11767').alt` within 1 degree of 51.48 from Greenwich, a planet's `altAzOf` within 1 arcmin of `/sky/altaz` at the same `tt` with matching `refr`/`refraction`, `setTime` + `waitForFrame` + `state().tt` for a rendered instant, `setView` + `screenOf` for the projection, `pick`, `labels()`, `stats()`, `skyBrightness()`, `constellationOf`, `setFollow`.
- `support.ts::appUrl` adds `atm=0` (the Sun is up at `TT_FIXED` from Greenwich and the daylight fade would cull the probe stars); a spec that tests the atmosphere sets `atm=1` itself. `centrePatch` returns `max`, `min` and the per-channel maxima (`maxR`, `maxG`, `maxB`) for the night probes; it decodes the screenshot through `Uint8Array.from(atob(base64), ...)` -> `new Blob([bytes], { type: 'image/png' })` -> `createImageBitmap` -> `drawImage`, never through a `data:` image (`img-src 'self'` refuses one and the `cspViolations` fixture would fail the test; plan D153). Await two rendered frames before any pixel probe (plan D140): `afterFrames(page, 2)` (`__sky.afterFrames(n)` resolves after `n` further `renderFrame` completions) sits between the `setView`/`setTime` evaluate and the first `centrePatch` in `expectRendered`, `renderAt` and `night.spec.ts::aimAtSirius`, and `selection.spec.ts` samples `screenOf`, the canvas box and `state().tt` in one `page.evaluate` right after `afterFrames(page, 1)`; a screenshot round trip under a five-worker SwiftShader load eats most of a 10 s poll (plan R97), so never widen `LIT_MIN`/`DARK_MAX` or a poll instead. `openPanelTab`/`openTab` expand the sheet on the phone before clicking a tab; `blurActiveElement` before a single-key shortcut; `definitionOf` and `parseDegrees` read the details panel rows.
- Every spec imports `test` and `expect` from `./fixtures.ts`, never from `@playwright/test` (ESLint block G; type imports such as `Page`, `Route` stay on `@playwright/test`). `fixtures.ts` (plan D153) extends `test` with three auto fixtures, all page-scoped (a page opened with `context.newPage()` has neither the init script nor the collector): `cspViolations` (an init script records every `securitypolicyviolation` on `document` with `effectiveDirective`, `blockedURI`, `disposition`, `sample`, `sourceFile`, `lineNumber`, and the records survive navigations through `page.exposeFunction('__cspViolation')`; the teardown asserts `[]`; `readCspViolations(page)` and `resetCspViolations(page, violations)` serve a deliberate negative control), `foreignRequests` (`{ urls, allow(host) }`: every `http(s)` request to a host other than `127.0.0.1` is recorded unless `allow(host)` named it, filtering at record time, so `urls` never lists an allowed host; the teardown asserts it empty; the only host ever allowed is the geocoder host a spec has routed) and `noStorage` (the OBS-8 evaluation at teardown: no cookie, no `localStorage`/`sessionStorage` key, no IndexedDB database; typed `undefined` because the lint refuses `void`). The three auto fixtures are the single enforcement; `support.ts::collectForeignRequests(page, allowedSet: ReadonlySet<string>)` is the fixture's implementation, and a spec MAY keep an explicit `collectForeignRequests(page)` call or an OBS-8 storage evaluation of its own as the acceptance-row evidence of docs/testing.md (`support.ts` says so; ten specs and `url-state.spec.ts` do), never as a replacement for the fixtures. Nominatim is never contacted: `observer.spec.ts` intercepts `${new URL(meta.geocoder.url).origin}/**` with `page.route`, fulfils one jsonv2 row, collects the fulfilled URLs in a set and asserts the documented parameters (`format=jsonv2`, `limit=5`, `accept-language`, `q` equal to the typed text, no `lat`/`lon`, `email` only when configured, a `referer` of the page origin); a `page.route` fulfilment still fires `page.on('request')`, hence `foreignRequests.allow(geocoderHost)` before the first submit. `collectAssetRequests(page, pattern)` records the request URLs whose pathname matches (the lazy-chunk proof of plan D131/D134: no `arController-*`, `ArOverlay-*`, `XrBridge-*`, `webgpu-*` or `babylon-webgpu-*` chunk before AR entry). Tests never call Nominatim or Horizons. The storage assertion (OBS-8) is the `noStorage` fixture on every test; `url-state.spec.ts` also asserts the 304 second load on the Resource Timing rows (`0 < transferSize < 1000`: a 304 carries headers where a heuristic cache hit reports 0; `decodedBodySize` unchanged) and `smoke.spec.ts` the session download (`DOWNLOAD_BUDGET_BYTES = 6_000_000`, brief l.258).
- Geolocation: `test.use({ geolocation, permissions: ['geolocation'] })` for the granted path; the denied and never-answered paths replace `navigator.geolocation.getCurrentPosition` through `page.addInitScript` (headless Chromium's behaviour on an un-granted prompt is undocumented, plan R65). Assert `state().observer` unrounded, the URL and every `/sky/frame` request rounded to two decimals.
- Named status regions: `a11y.spec.ts` is the single home of the rule "after ready, every `role=status` region has an accessible name"; the other specs scope on the names (`Loading the sky`, `Notifications`, `Your location`, `Getting started`, `Edge of the data`, `Catalogs updated`; the AR regions `Augmented reality status`, `Time offset from now`, `Compass`, `Starting augmented reality`, `Align the sky` and the alert `Augmented reality unavailable` are name-asserted in `ar.spec.ts`, since `a11y.spec.ts` is desktop-only and AR never starts there) instead of counting regions. Chromium's own `Failed to load resource` console lines for a deliberate 404, 422, 429 or abort are filtered on their text (`startsWith('Failed to load resource')`, `includes('status of 422')`); every other console error fails the spec. Error-path conventions (plan D163, UX-6): E1 (no WebGL2) is an `addInitScript` replacing `HTMLCanvasElement.prototype.getContext` (null for `webgl2`, `webgl`, `experimental-webgl`, `webgpu`; 2D kept) and defining an own `navigator.gpu = undefined` (the prototype accessor cannot be deleted), the splash then shows `engine.unsupported` and only Babylon's "WebGL not supported" console line is tolerated; E2 (a first frame refused for good) is a `page.route` 422 `outside-coverage` problem on `/sky/frame*` installed BEFORE `goto` with a `range_tt` far from now so the B-56 bounded continuation does not fire; E3 (the missing minor-body group) rewrites `/meta` with `catalogs.minor_bodies = null` (the CI data set forced on any server; no `/minor-bodies/*` route is stubbed, the switch is disabled from `/meta` alone) and, only when the server advertises the group, fulfils the `minor=` frame requests with 503 `Retry-After: 60` and asserts exactly one such request and none within 3 s; E4 (the geocoder blocked) fulfils the second routed submit with 429 and asserts the `geocoder.blocked` text, exactly two geocoder requests and no automatic retry; E5 (the PNG export) is `csp.spec.ts` step (c): `page.waitForEvent('download')` around the export button, `suggestedFilename()` matching `intersidera-YYYY-MM-DDTHHMMSSZ.png`, the PNG signature and an IHDR equal to `stats().renderWidth` x `renderHeight` (the engine's render target through the hook, never a recomputation of the DPR cap in the spec). A regex `toContainText` is not whitespace-normalised, so an expected unit string carries the U+00A0 the resources use (`/retrying in \d+\u00a0s/`); a search option is chosen by clicking it (on the phone layout the resting pointer makes the hovered star the active option, so Enter would pick the wrong row).
- Suites: smoke, engine (WebGL2), webgpu (manual), url-state, observer, time, layers, selection, details, search, night, about, degraded, mobile, a11y (brief l.385), ar (M5, mobile only), axe and csp (M6, both CI projects), perf (M6, manual).
- axe (plan D156): `e2e/axe.ts` is the single home of `AxeBuilder` (`expectNoAxeViolations(page, name, { exclude?, disable?, experimental? })`, `axeScan`, `summarizeViolations`, `incompleteSummary`; the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, `best-practice`, plus `experimental` on request; `[data-sky-labels]`, the engine's label overlay, excluded; `expect` imported from `./fixtures.ts`); its blind spot: `color-contrast` returns incomplete (not a violation) on the translucent panel surfaces in every state, so the contrast gate is `src/styles/tokens.test.ts` (node environment, outside the coverage include: it parses `app.css`'s `@theme`, night and light blocks, composites the translucent surfaces over `#05070f`, reads the field-border alpha from `TextField.tsx` and asserts the WCAG pairs), never an axe scan. Playwright renders the light scheme unless told otherwise (`colorScheme` defaults to `'light'` and `playwright.config.ts` sets none), so every axe scan before the scheme step of `a11y.spec.ts` is a light-scheme scan and that step emulates `dark` (`page.emulateMedia({ colorScheme: 'dark' })`, polled through `matchMedia`) before scanning it. The `night=0.3` step records its `color-contrast` counts as a test annotation (`axe night=0.3 (B-90)`), read with `--reporter=json`, never asserted.
- `ar.spec.ts` (plan D134): `test.skip(({ isMobile }) => !isMobile)` and, at file level (legal there, refused inside `describe`), `test.use({ launchOptions: { args: ['--use-fake-device-for-media-stream', '--use-fake-ui-for-media-stream'] }, permissions: ['camera', 'accelerometer', 'gyroscope', 'magnetometer'] })`: the worker gets its own browser with the fake camera (a rolling test pattern; on the headless shell the fake device alone answers `getUserMedia` with `NotSupportedError`, hence the fake UI), and the four permissions because a `permissions` list denies what it omits and Chromium >= 152 answers `requestPermission()` from the sensors permission; no project change. Orientation comes from an `addInitScript` ticker dispatching `deviceorientationabsolute` (or `deviceorientation` with `absolute: false`) every 100 ms from `window.__fakeOrientation`, declared in the spec's `declare global` (never CDP's `setDeviceOrientationOverride`, which drives the relative sensor only); the fixture pose `alpha 270, beta 90, gamma 0` looks east at the horizon. Drags go through `page.mouse` (`Touchscreen` has only `tap`); `blurActiveElement` precedes the Escape shortcut because the shortcuts bail on the focused exit button; a React range `Slider` is driven with the keyboard (`focus()` then `Home`/`End`/arrows), never `locator.fill()`, which assigns `input.value` through React's value-tracker setter before dispatching `input`, so React's `onChange` sees no change. The camera failures are stubs of `navigator.mediaDevices.getUserMedia`: the init script installs a never-settling promise, which keeps the transient `requesting` state observable (the status `Starting augmented reality` with Cancel -> `off`, no video, no error, the AR button focused), then `page.evaluate` re-stubs a rejection with `NotAllowedError` (denied) and `NotFoundError` (missing); the URL's `fov` is compared numerically (`url.ts` rounds to 0.1 degree and the spec's `boundingBox()` may be fractional where the engine reads integer client sizes), never as a string; WebXR is an init-script `Object.defineProperty(navigator, 'xr', ...)` stub with `isSessionSupported` true and `requestSession` rejecting `NotSupportedError` (or `isSessionSupported` false for the negative), kept present because Babylon's `CreateAsync` logs `console.error` without it; the WebXR steps may `console.warn` (Babylon's `makeXRCompatible` and dom-overlay notes), never `console.error`. The lazy-chunk proof is `collectAssetRequests` with `/(arController|ArOverlay|XrBridge|webxr|webgpu|babylon-webgpu)-[^/]+\.js$/` (`webxr-*` is the chunk Rolldown shares between the controller and the bridge; `scripts/check_chunks.mjs` lists the same prefixes): empty before `waitReady`, `arController-*` and `ArOverlay-*` present after the tap, no `XrBridge-*` before AR entry. The fake camera's size is read from `__sky.arVideo()` and the video element (1280x720 on the headless shell, 640x480 on full Chromium, never hardcoded, R92) and the expected `view.fov` is recomputed in the spec with the one-line cover formula of `sky/math/cameraFov.ts` (the specs import nothing from `src/` but the hook's type; `cameraFov.ts` imports `./frames` without an extension, which `tsconfig.node.json`'s `nodenext` refuses). `a11y.spec.ts` asserts the desktop absence: the AR button count 0 and `state().ar.capabilities.touch === false` (polled: the probe resolves asynchronously).
- Browsers on this WSL: either `sudo env "PATH=$PATH" fnm exec --using="$PWD/.node-version" npm --prefix frontend exec -- playwright install-deps` from the repository root once, or the sudo-free `~/.local/pw-libs` directory exported through `LD_LIBRARY_PATH`, `FONTCONFIG_PATH` and, since the UI has native form controls, a private `fonts.conf` exported as `FONTCONFIG_FILE` (docs/dev-wsl2.md; without it the headless shell dies with `FATAL SkFontMgr_FontConfigInterface.cpp Not implemented` on the first `<select>` or `<input>`). `TextRunHarfBuzz error` lines on stderr are font noise. CI runs Chromium only.
- Never skip, weaken, delete or mark a test as expected failure to make a gate pass; when the engine or the store misbehaves, report the failure instead of adapting the spec.
