# Frontend test rules (Vitest, Testing Library, Playwright)

- Vitest is configured in `vite.config.ts` (`defineConfig` from `vitest/config`): `environment: 'jsdom'`, `globals: true`, `setupFiles: ['./src/test/setup.ts']`, explicit `include: ['src/**/*.{test,spec}.{ts,tsx}']` and `exclude` re-adding `e2e/**` and `dist/**` (Vitest 4 excludes only `node_modules` and `.git` by default). `test.projects`, never `workspace`.
- `src/test/setup.ts` imports `@testing-library/jest-dom/vitest` (the `/vitest` subpath) and `../i18n` so components render real translations, polyfills `HTMLDialogElement.showModal`/`close` (the `open` state, the focus moved inside and restored to the opener, the `close` event; no top layer or inert, which Playwright asserts; backlog B-65) and stubs `window.matchMedia` to "no match" (the phone layout, no reduced motion); both shims are skipped under the node environment. Test-only support modules: `src/test/fixtures.ts` (the shared backend fixtures), `src/test/fakeBundle.ts` (a small real-star `CatalogBundle` and `/meta`), `src/test/meta.ts` (a complete `/meta`, `makeMeta` overrides); application code never imports `src/test/`.
- Coverage gate (plan D88): `npm run test` = `vitest run --coverage` with `coverage.include: ['src/sky/math/**/*.ts', 'src/state/url.{ts,tsx}']`, `exclude: ['**/*.test.ts', 'src/test/**']` (load-bearing in Vitest 4) and 100 % thresholds on lines, functions, branches and statements; `make check` and CI run it. The M4 pure modules `sky/math/{apparent,dso,labels,atmosphere,minorBodies,picking}.ts` fall under it; the pure `state/*`, `search/*`, `api/{geocoder,rateGate}` and `i18n/*` modules are tested exhaustively but stay outside the include (plan Q48). Subset runs use `vitest run --coverage=false <paths>`. Never lower a threshold; cover the line or delete dead code.
- Pure-module tests start with `// @vitest-environment node` (no jsdom cost, no DOM). Fixtures come from `backend/tests/fixtures/*.json` through `src/test/fixtures.ts` (`node:fs` + `new URL(..., import.meta.url)` with structural type guards); never copy fixture numbers into a test. Zone-dependent logic (`state/timeDisplay.ts`) takes an injected `offsetAt`; the negative-year and DST editor cases live here, not in Playwright (de440s covers 1849-2150).
- Unit tests cover `sky/math`, `state/*` and `api/*` against the shared fixtures and fake fetches (`vi.fn<typeof fetch>`, `Response` objects, injected `fetchAltAz`/`fetchDefaults`/`search`/`geocode` functions and clocks), `search/*` and `i18n/*` against `fakeBundle`. Testing Library covers every component with a real store (`createSkyStore`) and fakes for the engine factory, the frame controller, geolocation, the geocoder and `fetch` (stubbed to hang so the boot never reaches the network): one `*.test.tsx` per component, asserting roles, names and store writes, not markup. Babylon.js never runs in jsdom: engine and shader behaviour are tested only in Playwright.
- Playwright projects (plan D89): `chromium-desktop` (Desktop Chrome), `chromium-mobile` (Pixel 7, `hasTouch`) and `webkit` (Desktop Safari) ignore `webgpu.spec.ts`; `chromium-webgpu` (`channel: 'chromium'`, `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader`) runs only `webgpu.spec.ts`. `make e2e` and CI run `chromium-desktop` and `chromium-mobile`; `webkit` and `chromium-webgpu` are manual. `baseURL` is `http://127.0.0.1:4173` (`vite preview` of the `--mode e2e` build); the API runs on `http://127.0.0.1:8000` with `SKYAPI_AUTO_FETCH=false` and `SKYAPI_EPHEMERIS=de440s.bsp` (a reused local server must run de440s too: the time spec relies on year -44 lying outside the coverage). Use `127.0.0.1`, never `localhost` (may resolve to `::1`).
- `trace: 'retain-on-failure'`; `retries: 1` and `workers: 1` in CI only; `forbidOnly` in CI. One boot per scenario: one `test()` with `test.step` inside and `test.describe.configure({ timeout: 180_000 })` (SwiftShader compiles the shaders and uploads 471,820 vertices); `mobile.spec.ts` skips off the phone project and `a11y.spec.ts` on it (a project condition, never a data condition).
- Data conditions never skip: read `/api/v1/meta` through `support.ts::metaOf(page)` (after `waitReady` when the page is up) and branch on what the server has (`catalogs.minor_bodies` absent in CI: `/health` `degraded`, `missing: ["mpc"]`, `/minor-bodies/*` 503; `geocoder.enabled` and `geocoder.email`; `coverage.ephemeris_tt`), so the same spec passes on the CI data set (de440s, no MPCORB) and on the full local data.
- The `window.__sky` debug hook exists only in dev and e2e builds (`tsconfig.node.json` has `lib: DOM` so specs can type it). Specs import its type only as `import type { SkyDebugApi } from '../src/debug/skyDebugApi.ts'` (explicit extension) and nothing else from `src/`. Functions passed to `page.evaluate` are serialized: they must reach the hook through `window.__sky` directly and cannot call helpers of the spec. Sanity checks: `isReady`, `backend`, `altAzOf('hip:11767').alt` within 1 degree of 51.48 from Greenwich, a planet's `altAzOf` within 1 arcmin of `/sky/altaz` at the same `tt` with matching `refr`/`refraction`, `setTime` + `waitForFrame` + `state().tt` for a rendered instant, `setView` + `screenOf` for the projection, `pick`, `labels()`, `stats()`, `skyBrightness()`, `constellationOf`, `setFollow`.
- `support.ts::appUrl` adds `atm=0` (the Sun is up at `TT_FIXED` from Greenwich and the daylight fade would cull the probe stars); a spec that tests the atmosphere sets `atm=1` itself. `centrePatch` returns `max`, `min` and the per-channel maxima (`maxR`, `maxG`, `maxB`) for the night probes. `openPanelTab`/`openTab` expand the sheet on the phone before clicking a tab; `blurActiveElement` before a single-key shortcut; `definitionOf` and `parseDegrees` read the details panel rows.
- No request may leave for an origin other than the app: `collectForeignRequests(page, { allow })` asserts every `http(s)` host is `127.0.0.1` plus the hostnames in `allow`, which is only the geocoder host a spec has mocked. Nominatim is never contacted: `observer.spec.ts` intercepts `${new URL(meta.geocoder.url).origin}/**` with `page.route`, fulfils one jsonv2 row, collects the fulfilled URLs in a set and asserts the documented parameters (`format=jsonv2`, `limit=5`, `accept-language`, `q` equal to the typed text, no `lat`/`lon`, `email` only when configured, a `referer` of the page origin); a `page.route` fulfilment still fires `page.on('request')`, hence the allow list. Tests never call Nominatim or Horizons. `url-state.spec.ts` asserts the absence of cookies, localStorage, sessionStorage and IndexedDB databases (OBS-8).
- Geolocation: `test.use({ geolocation, permissions: ['geolocation'] })` for the granted path; the denied and never-answered paths replace `navigator.geolocation.getCurrentPosition` through `page.addInitScript` (headless Chromium's behaviour on an un-granted prompt is undocumented, plan R65). Assert `state().observer` unrounded, the URL and every `/sky/frame` request rounded to two decimals.
- Named status regions: `a11y.spec.ts` is the single home of the rule "after ready, every `role=status` region has an accessible name"; the other specs scope on the names (`Loading the sky`, `Notifications`, `Your location`, `Getting started`, `Edge of the data`, `Catalogs updated`) instead of counting regions. Chromium's own `Failed to load resource` console lines for a deliberate 404, 422 or abort are filtered on their text (`startsWith('Failed to load resource')`, `includes('status of 422')`); every other console error fails the spec.
- Suites: smoke, engine (WebGL2), webgpu (manual), url-state, observer, time, layers, selection, details, search, night, about, degraded, mobile, a11y (brief l.385).
- Browsers on this WSL: either `sudo env "PATH=$PATH" fnm exec --using=24 npm --prefix frontend exec -- playwright install-deps` once, or the sudo-free `~/.local/pw-libs` directory exported through `LD_LIBRARY_PATH`, `FONTCONFIG_PATH` and, since the UI has native form controls, a private `fonts.conf` exported as `FONTCONFIG_FILE` (docs/dev-wsl2.md; without it the headless shell dies with `FATAL SkFontMgr_FontConfigInterface.cpp Not implemented` on the first `<select>` or `<input>`). `TextRunHarfBuzz error` lines on stderr are font noise. CI runs Chromium only.
- Never skip, weaken, delete or mark a test as expected failure to make a gate pass; when the engine or the store misbehaves, report the failure instead of adapting the spec.
