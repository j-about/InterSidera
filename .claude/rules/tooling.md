# Tooling rules (Makefile, CI, configs, version files)

- Version policy: latest stable at project start, re-checked at each milestone; never pre-releases. `package.json` uses caret ranges except `typescript: ~6.0.3` (ADR-0001) and the exact pair `vitest` / `@vitest/coverage-v8` `4.1.11` (the provider peers the exact vitest version; bump both in one commit; Vitest 5 waits for jest-dom #738, ADR-0004 amendment); `pyproject.toml` uses `>=x.y,<next-major`, 0.x tools bounded at the minor (`ruff>=0.16.5,<0.17`). Both lockfiles are committed.
- Frozen until the ADR revisit trigger fires: TypeScript stays 6.0.x, npm stays the bundled 11.x, Python stays 3.14 (`requires-python = ">=3.14,<3.15"`), the two npm `overrides` (`eslint-plugin-jsx-a11y -> eslint`, `openapi-typescript -> typescript`, ADR-0002) stay. Never `--legacy-peer-deps`. Every new dependency needs an ADR.
- `.node-version` = `24` and `.python-version` = `3.14` (root and `backend/`, because uv does not search beyond the project boundary). CI reads `node-version-file: .node-version` relative to the repository root.
- Makefile: `SHELL := /bin/bash`, `.SHELLFLAGS := -eu -o pipefail -c`, no `.ONESHELL`; backend commands are `uv run --directory backend ...` (never `--project`, never `cd`); Node commands go through `fnm exec --using=$(CURDIR)/.node-version`; npm through `npm --prefix frontend`; never a root `npx`.
- `--env-file $(CURDIR)/.env` is passed only on run targets (`dev-api`, later `data`, `up`); check, test and types targets never load `.env`, so `make check` is hermetic from a clean clone.
- `make check` mirrors CI and CI mirrors `make check`: any step added to one is added to the other in the same commit. The CI-only steps, each with its Makefile twin outside `make check`: the frontend job's `npm run build` plus the `__sky` grep and `node ../scripts/check_chunks.mjs dist` (plan Q1: brief l.421 lists `make check` without a build; `make build` carries the same grep and the same gate), the `e2e` job (`make e2e`), the `e2e` job's Lighthouse step (`make lighthouse`, plan D155) and the `audit` job (`make audit`, plan D151; the only job that also runs on the weekly schedule). The contract drift gate is `git ls-files --error-unmatch` then `git diff --exit-code` on `docs/openapi.json` and `frontend/src/api/schema.d.ts` (plain `git diff` ignores untracked files). `npm run test` is `vitest run --coverage` (the 100 % gate on `src/sky/math/**` and `src/state/url.ts` lives in `vite.config.ts`, no Makefile flag).
- Builds: `npm run build` (production; `make build` then runs `! grep -rl "__sky" frontend/dist/assets` and `node scripts/check_chunks.mjs frontend/dist`, which prints the eager gzip total against its budget, check (f)) and `npm run build:e2e` = `tsc -b && vite build --mode e2e` (`make build-e2e`, the only build with the debug hook and, since M6, the only build with source maps: `build.sourcemap: mode === 'e2e'` for the heap table of the `perf` project); `make e2e: build-e2e` runs `npm run e2e -- --project=chromium-desktop --project=chromium-mobile`. The CI frontend job runs the same grep and the same gate after `npm run build`.
- CI `e2e` job (`needs: [backend, frontend]`, `timeout-minutes: 30`): checkout@v7, setup-node@v7 with the npm cache, `astral-sh/setup-uv@20cfd1bf945f4377ade1205e4dbc17946fc9a30d # v10.0.1` (setup-uv publishes no floating major tag after v7, so it is the one action pinned to a full tag/SHA), `uv sync --locked`, `npm ci`, `actions/cache/restore@v6` of `data/` keyed on `data_files.toml` + `catalogs/*.py` + `data/caches.py`, `sky-data fetch --only de440s pck00011 moon_tf moon_bpc hipparcos hyg ngc ngc_addendum stellarium_modern stellarium_description d3_bounds` (never MPCORB or de441; `/health` then reports `degraded` with `missing: ["mpc"]`), `sky-data build-caches`, `actions/cache/save@v6` under `if: always()`, `actions/cache@v6` of `~/.cache/ms-playwright` keyed on the lockfile, `npm exec -- playwright install --with-deps chromium` (never a root `npx`), `npm run build:e2e`, the two-project run, `upload-artifact@v7` (`if: ${{ !cancelled() }}`, `if-no-files-found: ignore`) of `test-results` and `playwright-report`; then the Lighthouse step (plan D155): Playwright stops its web servers with the run, so the job restarts the API (`SKYAPI_AUTO_FETCH=false SKYAPI_EPHEMERIS=de440s.bsp uv run --directory backend fastapi run --host 127.0.0.1 --port 8000 &`) and `npm --prefix frontend run preview &` in the background, polls `/api/v1/health` with `curl -fsS` until it answers HTTP 200 (the CI data set answers `degraded`, never the literal `ready`; 503 while `starting`) and `/` on 4173 likewise, runs `node scripts/lighthouse.mjs` as a gate (six URLs at >= 0.9) and uploads `reports/lighthouse` with `if: ${{ !cancelled() }}`.
- Every `scripts/*.mjs` (`check_i18n`, `check_chunks`, `check_audit`, `lighthouse`, `render_icons`) is syntax-checked by the wildcard loop `for f in $(wildcard scripts/*.mjs); do $(NODE) --check $$f; done` (bash `-e` aborts on the first broken file; the CI frontend job runs the same loop as `for f in ../scripts/*.mjs; do node --check "$f"; done`) and formatted by a config-free prettier run over the directory (`SCRIPTS_PRETTIER` in the Makefile: `--no-config --print-width 100 --single-quote`, mirrored as CI steps); a new script needs no Makefile edit. ESLint is not used on `scripts/`: ESLint 10 refuses files outside its base path (`frontend/`). `scripts/*.py` are formatted and linted with the backend ruff config through the explicit `--config` form (`uv run --directory backend ruff format --check --config pyproject.toml ../scripts` and `ruff check --config pyproject.toml ../scripts`): ruff resolves configuration per file and the repository root has none.
- Coverage gate (D39, brief l.294): the pytest line of `make check` carries `--cov=skyapi.astro --cov=skyapi.catalogs --cov-report=term-missing:skip-covered`, followed by three `coverage report` lines (`src/skyapi/astro/*` >= 90, `src/skyapi/catalogs/*` >= 90, `quaternions.py` + `formats.py` = 100). CI mirrors all four lines.
- `THIRD_PARTY_NOTICES.md` and `frontend/src/data/credits.json` are generated together (`make notices` = `python -m skyapi.tools.render_notices --out <notices> --json <credits>`, backlog B-63), both listed in `GENERATED`, and gated like the contract files (`check-contract: types notices`, `git ls-files --error-unmatch`, `git diff --exit-code`); the CI backend job runs the same render and diff on both files. `credits.json` is also in `.prettierignore` (its formatting is the renderer's).
- `api_version` (`skyapi.api.API_VERSION`, `1.1.0` since the additive `constellation` field of `/sky/altaz`, backlog B-71) follows semver of the contract: a model or route change bumps it and regenerates `docs/openapi.json` and `schema.d.ts` with `make types` in the same commit.
- Private e2e builds `frontend/dist-*/` (`vite build --outDir dist-<x>`) are ignored by git (`dist-*/`), ESLint (`globalIgnores`) and prettier (`.prettierignore`): `eslint .` scans every directory under `frontend/`, so a leftover build would fail `npm run lint`.
- `lucide-react ^1.43.0` is the one dependency added at M4 (brief l.405 lists it, so no ADR; plan D91); `vite.config.ts` defines `__APP_VERSION__` from `package.json` imported with `{ type: 'json' }` (declared in `src/vite-env.d.ts`).
- CI restores the test kernels (`data/*.bsp data/*.tpc data/*.tf data/*.bpc`) with `actions/cache/restore@v6` before pytest and saves them with `actions/cache/save@v6` under `if: always()`, keyed on `backend/src/skyapi/data/data_files.toml`; on a miss the session fixture downloads them (de440s and three small NAIF kernels only, never de441 or MPCORB).
- `make data` is a run target (`PYRUN`, loads `.env`): `sky-data fetch` then `sky-data build-caches`. `make notices` is hermetic (`PY`).
- `frontend/package-lock.json` must contain the `linux-x64-gnu` optional binaries (`@rolldown/binding-linux-x64-gnu`, `@tailwindcss/oxide-linux-x64-gnu`, `lightningcss-linux-x64-gnu`): development is aarch64, CI is x86-64. Regenerate from a clean `node_modules` if one is missing. `lockfileVersion` is 3. `.npmrc` has `engine-strict=true`.
- Vite 8 vocabulary only: `build.rolldownOptions` (never `rollupOptions`), `output.codeSplitting` (never `manualChunks`), `oxc` (never `esbuild`). The `codeSplitting.groups` (plan D131, D143) are exactly `babylon-webgpu` (test `/node_modules[\\/]@babylonjs[\\/]core[\\/](Engines[\\/](webgpuEngine|WebGPU)|Audio)[\\/]/`, priority 20; reached only through the dynamic import in `sky/engine/createEngine.ts`; the group names no `ShadersWGSL` directory since M6, so Babylon's WGSL material shaders, which the XR graph makes reachable, fall into lazy chunks nothing requests: `babylon-webgpu` 66.2 kB gzip on Babylon 9.27.1 against 96.2 kB with the old alternative) and `babylon` (the rest of `@babylonjs/core`; `tags: ['$initial']`; priority 30), both with the default recursive dependency capture: never `includeDependenciesRecursively: false` (it yields a cyclic `webgpu`/`babylon-webgpu` pair that throws at evaluation) and no group for `sky/ar/**`, `ui/ar/**` or `sky/engine/xr/**` (dynamic-only imports become their own chunks; the line `eager .js gzip total: <n> kB of the 1500.0 kB budget (check (f))` is the record of the budget: 422.2 kB on the e2e build of the M6 tree) and (g) the literal `defaultPixelShader` (Babylon's StandardMaterial shader source) appearing 0 times in every eager chunk, in `babylon-webgpu-*.js` and in `webgpu-*.js` (it may live only in lazy chunks nothing requests). A missing source tree fails the gate rather than skipping the check. Re-run it (through `make build`) after a Babylon or Vite bump. Vitest 4: `test.projects` (never `workspace`), explicit `test.exclude`, `coverage.exclude` listing `**/*.test.ts` and `src/test/**`. Prettier Tailwind plugin key: `tailwindStylesheet: "./src/styles/app.css"`.

- CI: `actions/checkout@v7`, `actions/setup-node@v7`, `astral-sh/setup-uv@20cfd1bf945f4377ade1205e4dbc17946fc9a30d # v10.0.1` (no floating `v10` tag exists upstream), `actions/cache@v6` (later `upload-artifact@v7`, `docker/setup-buildx-action@v4`, `docker/build-push-action@v7`); `permissions: contents: read`; no `pull_request_target`; `SKYAPI_AUTO_FETCH=false` and `SKYAPI_EPHEMERIS=de440s.bsp` in the workflow env; CI never downloads de441 or MPCORB and never contacts Nominatim or Horizons. - `make audit` (network; never part of `make check`) and the CI `audit` job (no `needs` key, setup-node + setup-uv, no `npm ci`, no `uv sync`, `timeout-minutes: 10`) run the same four commands: `npm --prefix frontend audit --json --package-lock-only > <tmp>/npm-audit.json || true`, `uv export --quiet --directory backend --frozen --format requirements.txt --no-emit-project --no-hashes --all-groups -o <tmp>/requirements.txt`, `uv tool run pip-audit==2.10.1 -r <tmp>/requirements.txt --no-deps --strict --disable-pip --progress-spinner off -f json -o <tmp>/pip-audit.json || true` (`uv tool run` is what `uvx` aliases, so `UV ?= uv` still governs; `PIP_AUDIT := pip-audit==2.10.1` in the Makefile; never `-r -`, never `--ignore-vuln`, which filters before the JSON output), then `node scripts/check_audit.mjs --npm <json> --python <json>`; the Makefile recipe works in a `mktemp -d` directory removed by a `trap` on exit. `scripts/check_audit.mjs` (Node built-ins only; `--allowlist <file>` overrides the default `scripts/audit-allowlist.json` for the gate's own tests) fails on: (a) a file that is not a report of its tool (npm: `vulnerabilities` and `metadata`; pip-audit: a `dependencies` array), a report that audited nothing (npm `metadata.dependencies.total` 0 or absent, pip-audit an empty `dependencies` array), an npm report whose metadata counts vulnerabilities while no `via` array carries an advisory object, or a pip-audit `skip_reason`; (b) an advisory not allow-listed for its package (npm advisories are the objects of the `via` arrays identified by the GHSA id of their `url`, npm's JSON carries no CVE; pip-audit advisories match on `id` and every alias, PYSEC, CVE, GHSA); (c) an allow-list entry that is malformed, expired, added in the future, or whose `expires` lies more than 180 days after `added` (an entry is valid through `expires`, inclusive); (d) an entry matching no reported advisory (unused). The allow-list is `{ "npm": [], "python": [] }` with entries `{ id, package, reason, added, expires }` (ISO dates); ids and package names compare case-insensitively.
- `scripts/lighthouse.mjs` (`make lighthouse`, the CI e2e step; plan D155): Lighthouse is not a dependency; the script spawns `npm --prefix frontend exec --yes --prefer-offline --package=lighthouse@13.5.0 -- lighthouse ...` (an exact pin through `npm exec --package`, not a floating root `npx`; `--prefer-offline` serves the cached pin without a registry round trip and still fetches it on a cold cache) with `--only-categories=accessibility --output json --output html --quiet --max-wait-for-load 90000 --enable-error-reporting=false` (without it the CLI prompts for Sentry on a TTY) and the SwiftShader chrome flags of the Playwright projects plus `--user-data-dir=<mkdtemp>` as the LAST chrome flag (chrome-launcher on WSL takes its Windows branch and would hand Chromium a `C:\Users\...` profile path created in the cwd; the child's cwd is a temporary directory too; both removed in `finally` and, because `process.exit` pre-empts it, by the SIGINT/SIGTERM handler); `CHROME_PATH` defaults to `@playwright/test`'s `chromium.executablePath()`; `--extra-chrome-flags "..."` appends flags (a host-GPU run). The verdict of a run is its own: the run's report pair is removed before the CLI starts (a stale pair would otherwise score a failed launch), a non-zero exit code or the 5 min timeout fails the run whatever the report says, the CLI is spawned `detached` so a timeout SIGKILLs its process group and then, through `/proc` and the unique profile path, the Chrome that chrome-launcher detached in turn, and the profile directory is removed only once they are gone; SIGINT/SIGTERM do the same, remove the run's cwd and profile directories and exit 130/143; every argument error (an unknown option included: `parseArgs` runs inside a try/catch) prints one line plus the usage line and exits 2; `--only name,...` writes `summary-only.json` (with `only` listing the names), never the six-URL `summary.json` the CI artifact carries.
