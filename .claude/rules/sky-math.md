# Sky mathematics rules (pure modules, 100 % coverage)

- `frontend/src/sky/math/*` (`typed`, `vec3`, `quaternion`, `frames`, `interpolation`, `properMotion`, `refraction`, `time`, `stars`, `lines`, since M4 `apparent`, `dso`, `labels`, `atmosphere`, `minorBodies`, `picking`, and since M5 `cameraFov` and `orientation`), `frontend/src/state/url.ts`, `state/clock.ts`, `state/frames.ts`, `astro/quaternions.py` and `catalogs/formats.py` are pure and dependency-free: no Babylon, no React, no store, no I/O, no Skyfield, no globals (ESLint forbids the imports); the one sanctioned exception is a type-only import from the import-free leaf `state/types.ts` (`orientation.ts` takes `CompassLevel` and `HeadingSource` there so the kernel and `ar.heading.level` cannot drift apart), erased by `verbatimModuleSyntax`, nothing at runtime. `sky/math/**` and `state/url.ts` carry 100 % line, branch, function and statement coverage (brief l.294, plan D88); their tests load the shared fixtures under `backend/tests/fixtures/` through `src/test/fixtures.ts`.
- Numeric idiom (plan D71, D144): fixed tuples `Vec3 = [number, number, number]` and `Quat = [x, y, z, w]`; bulk storage in typed arrays read through `at(a, i)` (throws `RangeError` out of range) and `load3`/`load4`/`store3`; every kernel takes an `out` parameter and allocates nothing; angles between unit vectors through `atan2(|a x b|, a . b)`, never `acos`; no `?? 0` fallbacks (a dead branch would break the 100 % gate). Hot kernels read consecutive values through `load3`/`load4`, whose reads are their own (`a[offset]`, `a[offset + 1]`, ... with one combined `RangeError` guard naming the whole index range): those load sites see the two float families only (`Float32Array` catalog columns, `Float64Array` frame buffers), so the doubles reach `out` unboxed, while `at` is called with every typed-array kind of the application plus plain arrays, so its megamorphic keyed load boxes what it returns; `at` stays one tiny site (splitting it per receiver family measured no gain on the M6 heap protocol) and its residual rows are recorded with the heap table (backlog B-91). `length3` is a plain `Math.sqrt` of the summed squares, and `angleBetween3` follows the same rule for `|a x b|`: `Math.hypot` guards against an overflow of the squares that unit and au-scale vectors never approach, and its varargs handling allocated 0.9 MB over six seconds (`normalize3` runs per body per frame and per constellation endpoint per overlay tick); a change there is covered at the same fixture tolerances.
- The frontend never computes an astronomical position from first principles (brief l.41). Allowed client-side operations: rotate by the backend horizon quaternion, apply linear proper motion with backend vectors, interpolate backend samples, first-order annual aberration with the backend observer velocity on catalog directions (stars and deep-sky objects alike, l.41 (d); c = 173.1446 au/day), and the refraction formula on Earth validated against Skyfield within 1 arcmin above -1 degree. The constellation containing an object is the `constellation` field of `/sky/altaz` (plan D114, `api_version 1.1.0`): no client-side point-in-polygon test, no densification of the served boundary rings (their corners are J2000-precessed B1875 edges, so both would be wrong; they are drawn as chords, backlog B-61).
- One CPU direction twin (plan D94): `apparent.ts` (`enuFromApparentIcrf` = the horizon rotation plus the optional D73 refraction with the azimuth kept; `apparentCatalogEnu` = aberration plus that tail, the deep-sky rule; `apparentStarEnuAt` = `properMotion.ts::apparentStarAt` plus that tail, the star rule; `billboardBasis`, `screenAngle`) is the only place the shader pipeline is reproduced on the CPU, and `sky/engine/resolver.ts::SkyResolver` is its only engine-side consumer: labels, constellation lines, picking, follow, centring, the marker, the readout and the debug hook resolve ids through it. Never write a second kernel in a layer or in `debug/`.
- Refraction (plan D73, backlog B-50): the single forward formula is `refraction.ts::apparentAltitudeDeg(hTrue, factor)`, a Saemundsson seed followed by two Bennett corrections, scaled by `factor = (P / 1010) * (283 / (273 + T))` from `refractionFactor(elevM)`, zero below -1 and above 89.9 degrees. The star and deep-sky shader twins mirror it line by line (range guards included); the bodies and minor-body layers and the resolver call it through `apparent.ts`. Change one, change all, and re-run the fixture parity tests (measured 0.057 arcmin, asserted <= 1 arcmin).
- Quaternions use the Hamilton convention: `v_enu = q * v_icrf * q^-1`, stored `[x, y, z, w]`. Consecutive samples are sign-continuous (positive dot product) so slerp never takes the long way; interpolation renormalises directions.
- Skyfield's altaz matrix is left-handed north-east-up: `quaternions.py` swaps rows x and y (NEU -> ENU) before the matrix-to-quaternion conversion and is tested against `altaz()` azimuth (`atan2(E, N)`) and altitude (`asin(U)`).
- The ENU -> Babylon mapping (left-handed, Y-up: East -> +X, Up -> +Y, North -> +Z; azimuth from north through east, clockwise from above) exists only in `frames.ts`: `enuToBabylonMatrix()` is the permutation P (determinant -1) that every sky mesh carries as its frozen world matrix (ADR-0009), `cameraRotationFor(az, alt, roll = 0) = { x: -alt, y: az, z: -roll }`, `cameraBasis(..., roll = 0)` (forward, right, up in ENU) feeds the billboards and the background shader, and `screenToDirection`/`directionToScreen` (trailing `roll = 0`) are the pure projections; unit tests cover az=0 -> +Z, az=90 -> +X, alt=90 -> +Y. Roll (plan D119, amending D72: the camera rolls only in AR, `ar.roll`) is right-handed about the view axis in ENU, positive when the screen top leans to the user's right (`up = up0 cos r + right0 sin r`, `right = right0 cos r - up0 sin r`; with roll +90 looking north the zenith side of the field lands on the left edge); Babylon takes `rotation.z = -roll` because P is a reflection, and `camera.updateUpVectorFromRotation = true` is set at creation. `basisFromBabylonQuaternion(f, r, u, q)` (the XR rig's basis, pinned against `cameraRotationFor` through Babylon's `RotationYawPitchRoll` = Hamilton `qy qx qz`, transcribed into `frames.test.ts` because the math tests import no Babylon), `dragDeltaDeg(dx, fov, height) = -dx fov / height` and `wrapSignedDeg` ([-180, 180)) live here too. Shaders and layers contain no swizzle. `alt` is clamped to +-89.99 degrees, `fov` (vertical, degrees) to [1, 120]. `cameraFov.ts` (plan D123) is the AR camera field model: diagonal default 73 in [50, 110] (`clampCameraDiagonalFovDeg`, NaN -> default), `visibleVerticalFovDeg` with `tan(V/2) = tan(D/2) min(h, w H / W) / sqrt(w^2 + h^2)` through `clampFovDeg` (any unusable dimension -> the fallback) and `coverCropRect` (the part of the frame `object-fit: cover` shows).
- `orientation.ts` (plan D117, D118, D130; brief l.546) is the device-orientation -> camera pose twin of `frames.ts`, pure and allocation-free with module-level scratch vectors. Conventions: device frame `x` right, `y` top, `z` out of the screen (the rear camera looks along `-z`, the page top is `+y`); Earth frame = the ENU tuple; the W3C matrix `R = Rz(alpha) Rx(beta) Ry(gamma)` is `deviceQuaternion = qz(alpha) qx(beta) qy(gamma)` (Hamilton); `screen.orientation.angle` is counter-clockwise from natural and folds as `pageQuaternion = q qz(-angle)`; `viewFromPose` gives `alt = asin(f_U)`, `az = atan2(f_E, f_N)` in [0, 360) and `roll = atan2(u . right0, u . up0)` in (-180, 180] with the no-roll basis of `cameraBasis` (the sign of D119: positive when the screen top leans to the user's right), and inside the gimbal band `|alt| >= MAX_CAMERA_ALT_DEG` roll 0 and `az` = the heading of the screen top (nadir) or that heading + 180 (zenith), so `cameraBasis(az, alt, roll)` stays continuous across the threshold. `compassCorrectedQuaternion(out, qRel, heading, axis)` = `qz(axisHeadingDeg(qRel, axis) - heading) qRel` with `COMPASS_AXIS_TOP` (CoreLocation's default) or `COMPASS_AXIS_BACK` (plan R74), where `qRel` is the DEVICE quaternion before the screen fold (the axis is a device axis: `deviceQuaternion` -> `compassCorrectedQuaternion` -> `pageQuaternion`, the controller's order; the fixture's compass cases draw every screen angle so the other order fails); `smoothPose` slerps by `1 - exp(-dt / tau)` with `SMOOTHING_TAU_S = 0.08` (`dt <= 0` copies); `compassLevel(source, accuracyDeg)` is the closed table good 15 / fair 35 / poor, invalid below 0 or without a figure, manual, none; `applyYaw(out, yawDeg, q)` = `qy(yaw) q` about Babylon's world vertical, a constant derived from `frames.ts::enuToBabylon` on ENU Up rather than a restated `+Y` (the XR rig, `out` may alias `q`), `viewFromAxes(out, forward, up)` is the `(az, alt, roll)` rule on an ENU basis (`viewFromPose` calls it; the XR bridge feeds it `basisFromBabylonQuaternion`, so both modes publish one convention and `cameraBasis(az, alt, roll)` rebuilds the input), `yawCorrectionDeg` and `wrapSigned180Deg` wrap to (-180, 180] (the closed end opposite to `frames.ts::wrapSignedDeg`), `fovAspectFromProjection` reads `fov = 2 atan2(1, m[5])`, `aspect = m[5] / m[0]`; `STALE_SAMPLE_MS = 3000` is the controller's staleness bound. Fixture rule (plan D133): `orientation.test.ts` checks every group of `backend/tests/fixtures/device_orientation_cases.json` (the W3C worked examples, closed-form poses at 1e-9 degrees, 200 seeded round trips and 40 compass cases at 1e-7, gimbal rows) generated offline by `scripts/generate_fixtures.py orientation`, an independent plain-Python implementation of the spec matrix that self-checks its hand-derived expectations; regenerate it (no data directory needed) and commit it with any change to the conventions above, never copy its numbers into a test. Any comparison with Babylon's Float32 output uses 1e-6.
- Body samples are interpolated with cubic Hermite and Catmull-Rom tangents (one-sided at the ends, directions renormalised, NaN scalars propagated); the horizon and equinox quaternions are slerped on the CPU in float64 and uploaded as uniforms; no rotation accumulation on the GPU. Extrapolation beyond a window uses its two boundary samples. The minor-body block of `FrameEval` (`minorDir`, `minorDistAu`, `minorMag`, `minorPhase`, `minorDiamDeg`, `minorDrawn`) goes through the same kernels.
- Time: TT Julian Date (float64) is canonical; `tt_minus_utc_seconds` from the current frame converts to UTC; proleptic Gregorian with astronomical year numbering; our own Julian Date utilities, never moment/dayjs. `state/clock.ts` derives `tt` from the control block `{ mode, speed, ttAnchor, wallAnchorMs }`; the engine calls it with `Date.now()`.
- `state/frames.ts` is the pure fetch policy (plan D76): `buildRequest` (OBS-7 rounding, `step_s` clamp through `step_class`, the `minor` list of `SimInput`), `requestKey`, `decide` (fetch, prefetch at 70 %, snapshot mode at <= 4 Hz, swap, drop, extrapolate), `windowFromResponse` (shape check, echoed grid), `evaluate`; `shapeKey` (the request without `tt`) identifies in-flight and backing-off requests so a moving alignment bucket never re-issues them; `COVERAGE_GUARD_D` (1e-6 day), `clampInsideCoverage` and `boundedRequest` handle a 422 at a coverage bound (the API rounds `tt` to 1e-8 day, so the advertised bound itself is refused). Test both speed signs, snapshot mode, the 1e-8 day alignment tolerance and both coverage bounds with a fake clock.
- `state/url.ts`: named parameters per UX-2, defensive parsing (unknown or invalid values fall back to defaults), rounding (coordinates 0.01 deg, alt/az 0.01 deg, fov 0.1 deg, tt 1e-6 day, speed and maglim 0.1, the night level 0.01 with floor 0.3), stable serialization order, default-valued keys omitted except `body, lat, lon, elev, t, az, alt, fov, lang` (`lang` is always written since the M7 acceptance fix: a URL without it takes the language of `navigator.languages`, so its default belongs to the browser like the observer's, and omitting it lost an explicit English on a browser preferring French; OBS-8, acceptance l.574; never remove it from `ALWAYS_WRITTEN`); `night` is `0`, `1` or the decimal level (`true`/`false` still parsed).
- `stars.ts` owns the magnitude limit per field of view (`zoomFraction` exported), the pixel radius, the brightness and the B-V colour stops shared by the shaders and the resolver; `lines.ts` owns the great-circle, small-circle and azimuth-arc generators writing into preallocated `Float32Array`s and `rotatePointsInPlace`; `dso.ts` owns the deep-sky limits (`7 + 7 zoom(fov)` magnitudes, `fov * 60 / 300` arcmin, a manual `maglim + 1`), the symbol radius, the north tangent and on-screen position angle and the `dsoShape` packing; `atmosphere.ts` the sky brightness B over the twilights, the tint, the sky and ground colours and the star fade (`limit - 8 B`, `1 - 0.85 B`); `labels.ts` the greedy layout, the budget {0, 14, 36, 90} and the pool size 96; `minorBodies.ts` the antisolar tangent, the disc radius and `composeMinorRequest`; `picking.ts` the tap tolerance (24 css px scaled by the field), the cone pre-filter (plus 0.6 degree), the magnitude-sorted row limit and the tie rule (body > minor > DSO > star within 3 px).
- `formats.py` (SKYS v1): magic `SKYS`, `version u32`, `count u32`, `epoch_tt f64`, `flags u32`, then packed columns `dir f32[3n]`, `pm f32[3n]`, `mag i16[n]`, `bv i16[n]` (32767 unknown), `hip u32[n]`, little-endian, sorted by magnitude ascending; round-trip tested with hypothesis and mirrored byte-for-byte by `api/catalogs.ts::parseSkys` (zero-copy views at offsets 24, 24+12n, 24+24n, 24+26n, 24+28n).
- Shaders: GLSL for WebGL2 and WGSL for WebGPU, four pairs (`stars`, `bodies`, `dso`, `background`), each mirrored line by line with the pure module that defines its rule. Stars: `dir(t) = normalize(dir + pm * years)`, then aberration, the horizon rotation, optional refraction; deep-sky: the same without proper motion plus the `dso.ts` limits, radius and position angle; background: `atmosphere.ts` evaluated per pixel from the camera basis; bodies and minor bodies (classes 0..5) receive CPU-computed ENU directions. Every fragment applies `uNight = (on, level)` as `rgb = vec3(dot(rgb, luma), 0, 0) * level`; the star and deep-sky vertex shaders apply `uAtmosphere = B` as `limit - 8 B` and `brightness *= 1 - 0.85 B`. No point primitives (four vertices per star and per object, corner from the vertex index). Coverage alpha (plan D122): the star and deep-sky fragments write premultiplied colour with `alpha = max(r, g, b)` (every channel already in [0, 1], so `rgb <= alpha` holds) and `StarLayer`/`DsoLayer` blend with `ALPHA_PREMULTIPLIED_PORTERDUFF` (mode 8: rgb ONE / ONE_MINUS_SRC_ALPHA, alpha ONE / ONE_MINUS_SRC_ALPHA) in every mode, the defined premultiplied "over" on the transparent AR canvas, in the 2D export canvas and on the black sky (a lone disc is unchanged; crossovers become `rgb + (1 - a) dst` instead of `rgb + dst`); never `vec4(rgb, 1.0)` under `ALPHA_ADD` again (RGB > A over a transparent buffer is undefined compositing). Bodies (mode 7) and lines (mode 2) are unchanged. A constant or rule changed in a pure module changes in both twins in the same commit.
- Babylon imports (in `sky/engine/` only) use `@babylonjs/core/<module>` subpaths; `sky/math` imports nothing from Babylon.
- Fixture parity tolerances: stars <= 1 arcsec (propagation <= 0.1 arcsec; `apparent.ts` against the rotated Skyfield apparent directions on both refraction branches), bodies <= 1 arcmin for `step_s <= 3600` and `|speed| <= 3600` with a 1 arcsec regression bound on the Hermite interpolation, slerp <= 0.01 arcsec, refraction <= 1 arcmin on both fixture tables, the Sun of the Greenwich window within 1 arcsec of the Horizons row.
