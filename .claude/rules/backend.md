# Backend rules (FastAPI + Skyfield, `skyapi`)

- Routers (`api/v1/*.py`) validate, canonicalize, call `astro/` and serialize. They never import Skyfield (brief l.397).
- `astro/` owns every Skyfield object (`loader.py`) and exposes pure, typed functions that receive `SkyState` explicitly. No module-level mutable state anywhere except the state built in lifespan.
- Lifespan is the only startup hook (Starlette 1.x removed `on_event`). `lifespan.py` starts the bootstrap thread (`bootstrap.py`, ADR-0008) and yields the `LifespanState` TypedDict `{bootstrap, settings, limiter, frame_cache}`; routes reach it through `api/deps.py` (`SkyStateDep` raises `DataNotReadyError` 503 until the `SkyState` is published; `SettingsDep`, `BootstrapDep`, `FrameCacheDep`, `LimiterDep`), never `app.state`. Heavy imports (Skyfield, pandas) stay inside the bootstrap functions so `bootstrap.py`, `state.py` and `api/deps.py` stay light; `skyapi.main` itself imports the astro composites through the routers (about 0.5 s) but still reads no environment.
- `create_app(settings)` is the factory; `skyapi.main.app` is a lazily built module attribute (PEP 562 `__getattr__`) that exists only because fastapi-cli has no `--factory` (ADR-0003). Importing `skyapi.main` must stay free of environment reads and I/O. `FastAPI(...)` keeps `docs_url="/api/v1/docs"` (hidden by nginx in production, plan D150) and passes `swagger_ui_oauth2_redirect_url=None`: no OAuth flow exists and FastAPI's root-level `/docs/oauth2-redirect` page is an inline script the strict policy refuses, so it is not registered (a strict 404 problem instead; no contract change). `request.state` is a Starlette `State` with attribute access only (no subscript). Tests build their own app with explicit `Settings`.
- Nothing settings-dependent may enter the OpenAPI document (D27): `dump_openapi` and the snapshot test must produce byte-identical output regardless of environment.
- Compute path operations are plain `def` (thread pool, NumPy releases the GIL); never `async def` for CPU work (brief l.77).
- Every parameter has explicit bounds, a `description` and `examples`; errors are the `ApiError` subclasses of `middleware/problem.py` (400 `InvalidParameterError`, 404 `UnknownObjectError`, 422 `OutsideCoverageError(detail, range_tt)`, 429 `RateLimitedError`, 503 `DataNotReadyError`) rendered by its handlers as RFC 9457 `application/problem+json`; never `HTTPException`, never a bare `except`. Routes declare `responses=problem_responses(<statuses>)` (the `content` recipe; `Problem` is injected into `components.schemas` by `create_app`). Routers pre-validate so the plain `ValueError`s of `astro/` never escape.
- Logging: stdlib `logging` with a JSON formatter, request id, no query strings and no coordinates.
- Canonicalize with `api/canonical.py` before cache lookup and before computation; echo canonical values in the response; the canonical query dataclasses live in `astro/queries.py` because `astro/` never imports `api/`. Cache headers come from `middleware/caching.py` (`CACHE_CATALOG`, `CACHE_COMPUTE`, `NO_STORE`, `etag_header`, `not_modified`, `server_timing`). Middleware is pure ASGI, never `BaseHTTPMiddleware`; the stack order is `RequestContextMiddleware` > `SecurityHeadersMiddleware` > `CORSMiddleware` > `GZipMiddleware` > app (the last `add_middleware` call is the outermost layer; plan D63 amended by D149): the security headers sit outside CORS so preflights, which `CORSMiddleware` answers without calling the inner app, carry them too. `middleware/headers.py` appends, when absent, `X-Content-Type-Options: nosniff` and `API_POLICY` (`default-src 'none'; frame-ancestors 'none'; base-uri 'none'`) on every response and `DOCS_POLICY` on the Swagger page alone; Starlette's `ServerErrorMiddleware` is outside every user middleware, so `problem.py::unhandled_exception_handler` adds the same two headers itself through `security_headers()` beside `X-Request-Id` (never a third copy of the values). Advertised coverage bounds (`/meta.coverage.*`, `range_tt`) go through `astro/loader.py::ceil_to_grid` / `floor_to_grid`, which move a raw bound onto the API's 1e-8 day `tt` grid (`round(tt, COVERAGE_GRID_DECIMALS)`, the canonical form) inward and never outward, so a request at the advertised bound is served and one grid step beyond is 422 (backlog B-52); never `math.ceil(value * 1e8) / 1e8`, which is not exact on values already on the grid. Response floats are rounded before serialisation (D68) and ranges wrapped after rounding; frames serialise with `exclude_unset=True` (`samples: null` set explicitly, absent fields never set); a NaN only ever reaches a Pydantic model field typed `float | None`.
- pyright strict on `src/`: complete annotations, no untyped `Any` leaving a public function, `numpy.typing.NDArray` for arrays. ruff line length 100, rule sets E,F,W,I,UP,B,SIM,N,RUF,PT,ANN; E501 stays enabled, use `# noqa: E501` only on unbreakable URLs.
- Settings are read once from the environment with the `SKYAPI_` prefix; no `env_file` in `Settings` (the Makefile passes `--env-file` on run targets only).
- The container command (plan D171, D172; ADR-0003 and ADR-0008 amendments, ADR-0023; `.claude/rules/deploy.md`): `backend/Dockerfile` ends with the exec-form `CMD ["fastapi", "run", "--host", "0.0.0.0", "--port", "8000"]` without `--workers` (an exec-form CMD never expands a variable) and without an `ENTRYPOINT` (so `docker compose run --rm api sky-data fetch` replaces the command); `compose.yaml` passes `--workers ${SKYAPI_WORKERS:-1}`, outside compose uvicorn reads `WEB_CONCURRENCY`, `PORT` is never set (`fastapi run` reads it as its port) and `Settings.workers` stays informational; `FORWARDED_ALLOW_IPS` is set by compose to `web`'s fixed address on the compose network, `10.213.0.3` (never the whole network, whose gateway relays host connections, never `*`); the image sets `SKYAPI_DATA_DIR=/data`, keeps `/app/pyproject.toml` beside `/app/.venv` (fastapi-cli reads `[tool.fastapi] entrypoint` from the working directory) and runs as uid 1000 on a read-only root, so the process may write `DATA_DIR` only (the bootstrap's `manifest.json`, `cache/**`, `.bootstrap.lock` and `.part` files). The HEALTHCHECK is a `urllib.request` probe of `/api/v1/health` (200 healthy, 503 failing); the remedy strings of `bootstrap.py` are quoted by `docs/data.md` as printed (`... is missing from DATA_DIR and SKYAPI_AUTO_FETCH is false: run \`sky-data fetch\``) and asserted by `scripts/check_images.mjs` (f), so a wording change updates both.
- Dependency ranges are `>=x.y,<next-major`; 0.x tools are bounded at the minor; nothing added without an ADR.
- Typing of the untyped astronomy libraries (ADR-0006): `backend/typings/skyfield/**/*.pyi` and `typings/jplephem/*.pyi` are hand-written stubs covering exactly the surface `src/` uses, one `.pyi` per imported module, each declaration citing the Skyfield 1.55 source line; import from concrete modules (`skyfield.timelib`, `skyfield.jpllib`, ...), the only `skyfield.api` import is `load` for the builtin timescale; pandas through `pandas-stubs`; pyarrow never imported directly (Parquet goes through pandas). Ruff excludes `typings/`; pyright checks it.
- Skyfield never downloads anything: open `SpiceKernel(path)` and `open(path, "rb")` directly; `Loader.__call__`/`open`/`download` are absent from the stubs on purpose. Every `DATA_DIR` file comes from `sky-data` (`skyapi.data`).
- `astro/frames.py` is the one place where astronomy is computed outside Skyfield (the IAU rotation models of the text PCK, ADR-0007); `astro/loader.py` holds the single use of Skyfield private names (`_segment_list`, `build_frame(..., _segment=)`) for the multi-segment Moon PCK (issue #952). Nothing else may touch a Skyfield private name; implementing `VectorFunction._at` in a subclass (`astro/minor_bodies.py::StackedOrbits`, D69) is Skyfield's documented extension hook (vectorlib), not a private name in that sense.
- Committed factual data (`data_files.toml`, `licenses/*.txt`, `constellation_names.csv`) lives in `skyapi/data/` and is read through `importlib.resources` (ADR-0005); the one `committed` registry entry outside the package is `gazetteer`, whose `filename` is the repository path of the frontend presets module (B-57): `render_notices.committed_location` prints such paths as they are. `THIRD_PARTY_NOTICES.md` and `frontend/src/data/credits.json` are rendered from the registry by `skyapi.tools.render_notices --out ... --json ...` (`make notices`) and never hand-edited.
- `/sky/altaz` rows carry `constellation` (D114, `api_version` 1.1.0): `AstroState.constellation_at` is Skyfield's bundled `load_constellation_map()` (stub `typings/skyfield/constellationlib.pyi`), applied in `astro/horizon.py::altaz_reference` to the apparent position (scalar times only); the frontend never tests the boundary polygons itself (brief l.62).

## Skyfield pitfalls index (brief l.523-535)

- `rotation_at` returns a LEFT-handed north-east-up matrix (det -1): swap rows x and y to get ENU before the quaternion; test `atan2(E, N)` and `asin(U)` against `altaz()`.
- Both `rotation_at` methods take `Time` arrays: one `ts.tt_jd(array)` per frame, never a Python loop over samples.
- `altaz(temperature_C=..., pressure_mbar=...)` raises off Earth: request refraction only for Earth observers.
- Set `julian_calendar_cutoff = None` explicitly (proleptic Gregorian); `utc_iso()` raises on negative years, build ISO strings from `t.utc` with signed years.
- DE441 has two segments per target (Skyfield >= 1.51); the file is memory-mapped, never read into memory or context; de440s covers 1849-2150 only.
- `build_latlon_degrees` fails for non-spherical bodies: use `PlanetTopos.from_latlon_distance` with the IAU ellipsoid radius at that latitude; Moon frame from the `.tf` + `.bpc`; Skyfield #952 keeps only the last `.bpc` segment per body, select the segment by date.
- One `Star.from_dataframe` for the whole catalog; evaluate at J2000 for `dir` and `pm` (Hipparcos epoch is J1991.25); read `B-V` yourself from `hip_main.dat`.
- MPC: gunzip `MPCORB.DAT.gz` on download; `build-caches` parses it once with our chunked `pd.read_fwf` (Skyfield's single-call loader needs 3.6 GB, B-39) into Parquet and keeps Skyfield's column names so `mpcorb_orbit`/`comet_orbit` work; comets through `load_comets_dataframe_slow`, one solution per designation with `drop_duplicates` after a stable `reference` sort (never `groupby().last()`); use `GM_SUN_DE440_km3_s2` for every Kepler orbit.
- `FileResponse` + ETag for binary catalogs; `GZipMiddleware(minimum_size=1024)`; rate limiting is per worker process; no deprecated `ORJSONResponse`.
- `true_equator_and_equinox_of_date.rotation_at(t)` is a proper rotation; RA/Dec of date via `.radec(epoch=t)`; LST validated against `t.gast` + east longitude.
- The Sun is never an observer; observing from a body also requested as target is a 400; `bodies=all` excludes the observer's body.
- Star and DSO catalogs are built at `build-caches` time, versioned by content hash (the ETag), never rebuilt per request.
