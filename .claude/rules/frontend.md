# Frontend rules (React 19, TypeScript 6, Vite 8, Tailwind 4)

- TypeScript strict with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`, `erasableSyntaxOnly`: use `import type`, no enums, no namespaces, no parameter properties. ESM only. Typed-array reads are `number | undefined`: use `at()`/`load3()`/`load4()` from `sky/math/typed.ts` or a guard, never `!`, never `as number`.
- ESLint runs `strictTypeChecked` + `stylisticTypeChecked`: `!` non-null assertions and floating promises are errors. Guard instead (`if (!el) throw ...`), and `void` or `await` every promise (`void i18next.init(...)`). `signal.aborted` narrows to `false` across awaits: read it through a function (`const aborted = () => signal.aborted`).
- React 19: function components and hooks only; `ref` as a prop (no `forwardRef`); no `useEffect` for derived state; the React Compiler stays off. UI components (`ui/`) contain no astronomy math and never import `sky/math` (ESLint block F): numbers and dates go through `i18n/format.ts`, calendar work through `state/timeDisplay.ts`, the export instant through `state/snapshotTime.ts`. The store, the frame controller, the tickers and the engine factory are props of `App` and `SkyCanvas`, so tests inject fakes and Babylon never runs under jsdom (one sanctioned exception under the node environment, backlog B-93: `sky/engine/xr/XrBridge.test.ts` on Babylon's `NullEngine` through the test-only `createExperience` seam of `XrBridge.create`).
- Layout of `ui/` (plan D112, backlog B-64): `components/` (the primitives Button, IconButton, Switch, Slider, Select, TextField, Tabs, Dialog, Sheet, Banner, Badge, plus Toast and Banners), `shell/` (TopBar, PanelShell, SkipLink, FovPresets, NightControls, ExportButton, HintBanner, EngineContext, useMediaQuery), `observer/` (ObserverPanel, GeoBanner, GeoNotice, BodyPicker, CoordinateForm, PresetList, PlaceSearch), `time/` (TimePanel, TimeReadout, TransportBar, SpeedSelect, StepButtons, DateTimeEditor, CoverageBadges), `panels/` (DetailsPanel, LayersPanel, AboutDialog, VisibleObjects), `controls/` (SearchBox, ShareButton, LanguageToggle), `ar/` (plan D127: `ArButton` in the eager bundle, mounted by `TopBar`; the lazy `ArOverlay` with `TimeOffsetBadge` and `CompassIndicator`), `shortcuts.ts`, `SkyCanvas.tsx`, `BootStatus.tsx`. Every store-bound component (shell, observer, time, panels, controls, Toast, Banners, `SkyCanvas`, `BootStatus`) takes `{ store }` (plus optional test injections) and reads the store itself; the primitives under `components/` are store-free. `components/Toast.tsx` is the single home of transient messages (`ui.toast`, one permanent named `role="status"` region, `showToast(key)` over the closed `ToastKey` union); `components/Banners.tsx` is the single home of the degraded-state and coverage-stop banners (`frames.failing`, a stale catalog, `frames.coverageStop`, a failed engine, and `ar.error` as the dismissible warning alert "Augmented reality unavailable" with `t(\`ar.error.${code}\`)`, AR-5); the `frames.failing` alert is a post-boot signal, rendered only while `boot.phase === 'ready'`, because the frame controller publishes `failing` from the first retry (plan R70) and a failing FIRST frame belongs to the splash (`BootStatus`, `state/boot.ts`); the geolocation explanation is `observer/GeoBanner.tsx`. Never render the same fact twice.
- Store ownership (plan D80, D92): one zustand vanilla store (`state/store.ts`, `subscribeWithSelector`) shared by React (`useStore` from `zustand`, `useShallow` from `zustand/react/shallow` for object selectors) and the engine (selector subscriptions with `shallow`). Chrome state is the `ui` slice (`panel`, `sheet`, `dialog`, `stepUnit`, `shortcuts`, `hintDismissed`, `toast`, `lastSpeed`); `geo`, `geocoder`, `details`, `readout`, `labels.visible`, `minorBodies`, `bundle`, `centreRequest`, `follow` and `ar` (plan D115: `mode`, `capabilities`, `permission`, `error`, `heading`, `azOffsetDeg`, diagonal `cameraFovDeg`, `frame`, `roll`, `viewBefore`, `hintDismissed`, `xr`; never in the URL, backlog B-73) are the other session-only slices. Of the `ar` actions, `setArMode`, `failAr`, `setArPose` (one `set` writing `view.az/alt` and `ar.roll`, once per engine frame), `setArHeading`, `setArFrame` and `setArXr` are controller/engine-only; `requestAr` (off -> requesting on Earth only, AR-1; ends follow, collapses the sheet, closes the dialog), `setArPermission`, `exitAr`, `clearArError`, `setArOffset`/`nudgeArOffset` (wrapped to [-180, 180)), `setArCameraFov` (clamped) and `dismissArHint` are the UI's; `setObserver`/`applyUrl` leaving Earth exit AR in the same write. Never a second store, never React state for something another component or the engine reads. The engine owns time (`Date.now()` in `SkyEngine.tick`; `publishTt(tt, lstHours)` and `publishReadout` at <= 2 Hz, `setVisibleLabels` at <= 1 Hz on change, `setView` for follow (every frame from `tick`, through a preallocated `followPatch`: plan D139) and for centring (the overlay tick), `clearCentre` are engine-only calls; `stopAtBound` has exactly two callers, the engine's clamp branch while the clock runs (playing or live) and the frame controller's 422 branch); `stepTime` derives its base from `ttAt`, never from the mirror; the camera controller writes `view`; React never selects `view` at animation rate (`FovPresets` selects a derived index) and never drives the canvas. Slice types live in the import-free leaf `state/types.ts`; the store never canonicalises `sel`.
- Engine seam (plan D93): React reaches the engine API only through `SkyCanvas.onEngine` -> `shell/EngineContext.tsx` (`useEngine()`), for event-time calls (`snapshot`); everything the engine acts on over time flows through the store. The label overlay (`labelRoot`, the `aria-hidden` sibling of the canvas rendered by `SkyCanvas`) and the selection marker belong to the engine's `LabelLayer`: React never writes into it, and the engine imports no i18next (texts arrive through the `labelText` option, `i18n/labelText.ts`). Its twin `underlayRoot` (plan D121) is the `aria-hidden` sibling rendered BEFORE the canvas (which is `relative`, so positioned siblings paint in DOM order): `sky/ar/cameraVideo.ts` appends the `<video autoplay muted playsinline>` of the one `getUserMedia` stream per AR session to it (rear check from `getSettings().facingMode`, `undefined` accepted, `'user'` -> `noRearCamera`; stopped on exit, on `visibilitychange: hidden` and `pagehide` (a silent `exitAr`), and on track `ended` (`trackEnded`), except while `ar.mode === 'xr'` or `ar.xr.phase === 'entering'` (ARCore owns the camera in a session; the Play Services install flow hides the page), when the controller marks the camera lost and reacquires it on the first tick that finds the sensor mode idle again, a failed restart failing AR with the camera's code or `trackEnded` (plan R94); an end that precedes the handle, the page hidden during the camera prompt or while `play()` was pending, is replayed to the controller's `onEnded` listener, registered first, so AR is left and the engine disposes the controller before the sensors start; a page already hidden when the stream arrives never plays); React never writes into it either. The sensor-mode controller (`sky/ar/arController.ts`, plan D116) is hosted by the engine, never by React or `main.tsx`: `SkyEngine` subscribes to `ar.mode`, loads it with `await import('../ar/arController')` when the mode becomes `requesting` (an `ArHost { store, underlayRoot, preloadXr }`), ticks it after the other tickers (`update(tt, nowMs)`, one `setArPose` per tick, staleness on the engine clock) and disposes it on `off`; `sky/ar/**` is Babylon-free and nothing in the main graph imports it statically (types excepted). `SkyEngineApi.preloadXr()`, `enterXr(overlay)` and `exitXr()` are the AR event-time calls of the same seam (plan D128): `enterXr` requires the sensor mode with `xr.support === 'supported'` and an idle phase, marks `xr.phase` `entering`, awaits `import('./xr/XrBridge')` (a failed download is `failAr('xrFailed')`) and hands the overlay root to `sky/engine/xr/xrFlow.ts` (Babylon-free, tested with a fake bridge), which creates `XrBridge` once, enters and writes the outcome (`setArMode('xr')` + `active`, or `failAr(classifyXrFailure(error))` keeping the sensor mode, `AbortError` silent); `exitXr` ends the session; every session end (our control, the back gesture, the store leaving AR) returns to `sensor`, resets the phase and lets the engine re-apply its camera and `resize()` once; the bridge alone zeroes the rig positions, composes the yaw and writes `setArPose`/`setArXr({ aligned })`/`view.fov` in `tick`. `arTransparent()` tells the debug hook whether the scene clears transparent. The engine's third `setView` context (plan D123, beside follow and centring): while the sensor mode runs and `ar.frame` is known, `view.fov = visibleVerticalFovDeg(ar.cameraFovDeg, frame, canvas box, view.fov)` is written in the next tick after a frame, camera-field or size change (never from inside a store listener); the XR bridge owns `view.fov` in a session. While `ar.mode !== 'off'` (plan D124) the scene clears transparent (two preallocated `Color4`), the sky and ground quads are hidden with `options` untouched, the horizon culling of labels and picking is off, follow and centring skip their `setView`, the `shortcuts.ts` view keys are inert and Escape exits AR after the sheet; the snapshot draws the video first with `coverCropRect`; in XR the label root is hidden, the visible-label list emptied once, `pick()` returns null and `snapshot()` rejects. The details controller is an engine ticker (`tickers`), not a timer. `<html>` attributes (`data-mode`, `--night-brightness`, `lang`) are written by `state/domSync.ts` from store subscriptions, never by a component.
- AR-1 gate and permission (plan D125, D126; main bundle, backlog B-75): `state/arCapabilities.ts` is the gate's only home (`evaluateArCapabilities` from `isSecureContext`, `navigator.mediaDevices` present (the literal `getUserMedia` is reserved to the lazy camera chunk by the `check_chunks.mjs` literal gate, D131 (c)), `'DeviceOrientationEvent' in window`, `maxTouchPoints > 0 || matchMedia('(pointer: coarse)')`, then `enumerateDevices()` for a `videoinput` only once those hold; `startArCapabilityProbe(store)` runs from `main.tsx` after the store exists and again on `devicechange`; `arButtonVisible(s)` adds `observer.body === 'earth'`); hidden means not rendered, no message (l.579); `ondeviceorientationabsolute` and `requestPermission` are never discriminators (desktop Chromium has both). `state/arPermission.ts::requestOrientationPermission()` is called SYNCHRONOUSLY inside the AR button's click handler before `requestAr()` (WebKit refuses the static after an `await`; Chromium >= 152 has it too and answers the sensors permission state); the click handler (`ui/ar/ArButton.tsx`) writes `setArPermission('pending')` synchronously first, calls the helper, then `requestAr()`, all inside the handler (so a previous session's outcome is never reused and the controller waits for the fresh one), the outcome lands in `ar.permission` through `setArPermission` only while that tap is still the latest one (a `useRef` tap counter: the late promise of an earlier, exited tap never overwrites a fresh `pending`; a rejecting helper records `prompt`), and the controller waits while it reads `idle` or `pending` (`denied` -> `orientationDenied`; `granted`, `prompt`, `notRequired` continue; a `requesting` without a permission write waits for the overlay's cancel button).
- AR chrome (plan D127; `ui/ar/`): `App` loads `ArOverlay` with `lazy(() => import('./ui/ar/ArOverlay'))` under `Suspense fallback={null}` and renders it INSTEAD of `TopBar` while `ar.mode !== 'off'`, as the same `banner` landmark; nothing in the main graph may import `ui/ar/ArOverlay.tsx` statically (types excepted: a static import folds the chunk into the entry, which `scripts/check_chunks.mjs` fails). Its root `header#ar-overlay` (`AR_OVERLAY_ID`) is the WebXR DOM-overlay element handed to `engine.enterXr(root)`: a start-aligned column with no background of its own (the UA stretches the overlay root to the full screen inside a session), the panel surface on the inner row. Focus: the overlay focuses its exit control on mount through an effect (never `autoFocus`) and `App` gives the focus back to the AR button when the mode returns to `off` (`ArButton.tsx::focusArButton`, an effect on the mode transition, because the button remounts with the top bar); `IconButton` takes no `ref`, so both lookups go through ids (`ar-exit`, `ar-button`). The AR status regions are named (`ar.spec.ts` asserts them, `a11y.spec.ts` never sees AR): "Augmented reality status" (the visually hidden mode line), "Time offset from now" (`TimeOffsetBadge`, shown while `clock.mode !== 'live'`; it keeps a one-second `window.setInterval` for the wall clock because a paused mirror never moves and the react-hooks compiler rules `purity` and `refs` forbid `Date.now()` and `ref.current` during a render), "Compass" (`CompassIndicator`, one text per `ar.heading.level`, the iOS figure, the magnetic tooltip), the status banners "Starting augmented reality" (with Cancel, while `requesting`) and "Align the sky" (dismissible through `dismissArHint`; the waiting text `ar.hint.waiting` for a `none` level, the manual-north text `ar.hint.manualNorth` for `manual`, so the banner never contradicts the compass badge), and the alert "Augmented reality unavailable" in `Banners.tsx`. The row also holds the offset readout with its reset and, around the badge, the two 1° nudge `IconButton`s (`ChevronLeft` / `ChevronRight`, keys `ar.offset.left` / `ar.offset.right`, the non-drag twin of the calibration drag for WCAG 2.2 SC 2.5.7, plan D157 C5; right = `nudgeArOffset(-1)`, left = `+1`: "turn the sky" follows the sign of `frames.ts::dragDeltaDeg`, maintainer question 32), the camera-field `Slider` (`ar-fov`, 50..110, `formatDegrees(v, 0)`), the existing atmosphere `Switch` (`layers.atmosphere`, never a duplicate key), the WebXR `Button` while `xr.support === 'supported'` in the sensor mode and, in a session only, "Leave the immersive mode" plus `TransportBar` (the sheet strip carries it in the sensor mode). The engine calls of the overlay (`enterXr`, `exitXr`) are the D93 event-time calls through `useEngine()`; their rejections are ignored because the engine wrote the outcome to the store. Escape stays in `ui/shortcuts.ts`. The `ar` slice never reaches the URL (backlog B-73).
- Browser timers: `@types/node` is in the app project, so use `window.setTimeout` / `window.clearTimeout` / `window.setInterval` in browser code (a bare `setTimeout` types as `NodeJS.Timeout`).
- Debug hook guard: `debug/skyDebug.ts` is reached only through `await import('../debug/skyDebug')` inside the literal condition `if (import.meta.env.DEV || import.meta.env.MODE === 'e2e')` (plan D86); never import it statically, never reference `__sky` elsewhere in `src/` (the production build is grepped for the string). The `#engine=webgl2|webgpu` hash override is read under the same condition and never serialized; `ShareButton::shareUrl` builds the link from the serialised store, never from `location.href`.
- Every user-visible string goes through `t()` with a key in both `i18n/en.json` and `i18n/fr.json` (UX-1). `scripts/check_i18n.mjs` fails on missing or unused keys and on a dynamic key without a literal prefix: `t(\`constellations.${abbr}\`)`, `bodies.`, `warnings.`, `dsoTypes.`, `layers.`, `kinds.`, `lang.`, `cardinal.`, `observer.latitudeKind.`, `coords.error.`, `geo.`, `geocoder.`, `presets.`, `time.speedUnit.`, `time.step.`, and since M5 `ar.error.` (typed by `ArError`, `AR_ERROR_KEYS`) and `ar.compass.` (typed by `CompassLevel`, `COMPASS_LEVELS`) (the closed list at M5; a new prefix needs its own subtree in both JSON files); the `ar.offset.{years,days,hours,minutes}` plural keys carry `_one`/`_other` and, in French, `_many`; the dynamic keys are typed in `i18n/keys.ts` (`ConstellationAbbr`, `BodyKey`, `KindKey` with guards, `bodyName`, `constellationName`), and a key resolved by a switch keeps one literal `t()` per case (`Toast.tsx::toastText`). English `constellations.*` are the Latin names, the French ones the standard list; the label texts of the engine come from `i18n/labelText.ts`. Since M6 (plan D158) the checker also fails on a placeholder set that differs between languages, an incomplete plural family (`_one` + `_other` in every language), a plain space before `:`, `;`, `?`, `!` or `%` in a French value, leading/trailing or double spaces and `...` for `…`, and warns on a value identical in every language outside its allow-list and on a plain space between a placeholder and one of the unit words `s`, `min`, `h`, `m`, `km` (`UNIT_AFTER_PLACEHOLDER_RE`). Typography: U+00A0 (`\u00a0` in the JSON) before every French punctuation mark that takes a space (a finding) and, in both languages, between a number placeholder and those five unit words (`{{seconds}}\u00a0s`, `{{count}}\u00a0min/s`; the English `{{percent}}%` stays unspaced; a warning); the same spacing before any other unit word (`yr`, `d`, `MB`, `an`, ...) is a could the checker does not enforce, apostrophes straight; a test comparing such a string uses the same `\u00a0` (DOM Testing Library folds it on the node side only).
- Icons: `lucide-react` only (plan D91). The accessible name goes on the `<button>` (`IconButton` requires `label`, which becomes `aria-label` and `title`), never on the icon: an `aria-*`, `role` or `title` prop on a lucide icon removes its default `aria-hidden` and doubles the name.
- Tailwind CSS-first: configuration lives in `styles/app.css` (`@import "tailwindcss"`, `@theme`, `@custom-variant night`, base rules under `@layer base`). No `tailwind.config.js`; class names are complete literal strings, never concatenated (choose between whole strings in a helper); class order is enforced by prettier-plugin-tailwindcss. Tokens: the `sky-*` family is drawn over the sky and only night mode redefines it; the panel family follows `prefers-color-scheme` (panel surfaces only, backlog B-68). Night mode (plan D108, B-59) redefines the tokens under `[data-mode='night']` with `color-mix(in srgb, <red> calc(var(--night-brightness) * 100%), black)`; a translucent surface bakes its alpha into a switchable token (`--color-panel-bg`, `--color-field-bg`) and `bg-token/NN` is used on opaque tokens only; no CSS `filter` anywhere (not monochrome, a compositor pass per frame, a containing block for fixed elements that top-layer dialogs escape) and no post-process: the sky is tinted by the shaders' `uNight`.
- Accessibility (UX-4): keyboard-operable controls with the one `:focus-visible` token, ARIA names everywhere (`aria-label` on the canvas, the splash, the toast region and the panel; a `title` on every `Banner`, which names its region), state never by colour alone (`Switch` writes On/Off, `Badge` pairs icon and text), targets >= 24 css px (`pointer-coarse:` 44), the native `<dialog>` with `showModal()` for modals, `prefers-reduced-motion` respected (the base rule and the controller's inertia), the skip link first in the DOM; jsx-a11y must stay clean. WCAG 2.2 AA rules from the M6 audit (plan D157; Lighthouse 1.00, axe zero violations, `styles/tokens.test.ts` green): the `Switch` state word ("On"/"Off") is an `aria-hidden` sibling OUTSIDE the button, so the accessible name is the label alone (SC 2.5.3; axe counts `aria-hidden` text inside a control as visible text); a link alone in a `dd` (`AboutDialog::ExternalLink`) is `inline-block min-h-6 py-1` so its target reaches 24 px (SC 2.5.8); `TimeReadout` is two sibling `<dl>` elements, one `div` per group, never a `div` between `dl` and `dt` (SC 1.3.1); the whole phone sheet (handle, strip and body) is capped at `max-h-[70dvh]` in `PanelShell` with the body the shrinking part (partially obscured targets); the collapsed strip is `flex-wrap min-h-strip` and `TransportBar` `max-w-full flex-wrap`, never `overflow-x-auto` (SC 1.4.10 reflow at 320 px); a `focusin` in the header collapses the expanded sheet only when `matchesFocusVisible(target)` holds and `focusObscuredBySheet` finds the two boxes intersecting, never on a tap (SC 2.4.11; both exported from `PanelShell.tsx`, `focusVisible` injectable because jsdom never matches `:focus-visible`); the time editor's offending field carries `error`/`aria-invalid` with the invalid-date message and the form's `role="alert"` shows the range error only, rendered only with a coverage (`error === 'range' && years !== null`) (SC 3.3.1); `TextField` draws its border as `border-muted/80` in every scheme (`/60` was 2.27:1 light, 2.51:1 night against the 3:1 of SC 1.4.11; `tokens.test.ts` parses that alpha from the source, so the class and the test move together); the light `--color-warn` is `#885900` (4.58:1). Night dimming below level 1 is the recorded exception B-90; the AR nudge buttons are the non-drag alternative of SC 2.5.7. Single-key shortcuts live in `ui/shortcuts.ts` alone, bail on interactive targets and open dialogs, and stay switchable (`ui.shortcuts`, WCAG 2.2 SC 2.1.4).
- No storage APIs: no cookies, `localStorage`, `sessionStorage` or IndexedDB (OBS-8). The URL query string is the only persisted state (`state/url.ts` codec, `state/urlSync.ts` writer at <= 2 Hz with rounded floats, hash preserved); `ui.*`, `follow`, `geocoder.enabled`, `coverageStop` and the minor-body defaults stay in memory.
- Privacy rounding: latitude and longitude to 0.01 degrees before any API call (`api/client.ts::observerQuery`, OBS-7); the store keeps the typed or geolocated value unrounded and the panel previews the rounded one (`state/coords.ts::roundedObserverPreview`, built on `url.ts`, never on the fetch layer); the geocoder receives the typed text only, never a coordinate; the URL withholds the observer while a geolocation prompt is up.
- Nominatim (OBS-4, plan D97) lives only in `api/geocoder.ts`: one `fetch`, no retry, no cache, `format=jsonv2`, `limit=5`, `accept-language`, `email` when `/meta.geocoder.email` is set, `referrerPolicy: 'strict-origin-when-cross-origin'` (plus the referrer meta of `index.html`); the panel (`observer/PlaceSearch.tsx`) is submit-only, one request in flight, `>= max(min_interval_ms, 1000)` apart, shows the attribution with the OpenStreetMap copyright link and reads 403/429 as `blocked` with a message. Never route Nominatim through `api/client.ts` (it retries 429s).
- Only `import.meta.env.VITE_*` reaches the client; never mirror a `SKYAPI_*` value into a `VITE_*` variable. `__APP_VERSION__` is a Vite `define` (declared in `vite-env.d.ts`).
- The header values verbatim (plan D179, D186; ADR-0024; `.claude/rules/deploy.md`): `frontend/nginx/templates/00-headers.conf.template` carries the seven values of `frontend/security-headers.ts` byte for byte (with `${SKY_GEOCODER_ORIGIN}` where `cspHeader()` puts the geocoder origin) once at http level; a change to `cspHeader()`, `PERMISSIONS_POLICY` or `securityHeaders()` is mirrored in the template in the same commit, or `make check-delivery` (`scripts/check_nginx_headers.mjs`) fails; `vite.config.ts` stays the source of the dev and preview headers. `frontend/Dockerfile` builds the web image from `npm run build` (`build:e2e` only through `compose.e2e.yaml`; the production image is grepped for `__sky` during the build), copies `dist/` without `.vite/` and ships the `.gz` siblings its build stage writes for `gzip_static`.
- API types come from the generated `api/schema.d.ts` (never hand-edited); `api/client.ts` is the single fetch layer for `/api/v1` (typed `getJson`/`getBytes`, `ApiProblem`, `NetworkError`, retry with backoff, `pollHealth`, `getAltAz`, `getMinorDefaults`, `searchMinorBodies`); `api/rateGate.ts` is the one 429 gate the details controller and the minor-body search share; `api/catalogs.ts` loads the catalogs with `cache: 'no-cache'` and ETag comparison. `data/credits.json` is generated by `make notices` and read only through `data/credits.ts`.
- Babylon.js: import from `@babylonjs/core/<module>` subpaths only, and only under `src/sky/engine/` (ESLint enforces both); never the package root, `Legacy/legacy` or the UMD `babylonjs`. Side-effect imports live in `sky/engine/babylon.ts` (WebGL set), `sky/engine/webgpu.ts` (the lazy WebGPU chunk) and `sky/engine/xr/babylonXr.ts` (the lazy WebXR set, plan D128), one comment per import; `sky/engine/xr/**` is reached only through `await import('./xr/XrBridge')` in `SkyEngine` (type imports excepted), and every other XR module imports Babylon's XR classes from `babylonXr.ts`. Shaders are separate `.glsl`/`.wgsl` twins imported with `?raw`; never `glslangOptions`/`twgslOptions`.
- The render loop belongs to `SkyEngine` (`engine.runRenderLoop`): no allocation per frame, typed arrays and preallocated buffers (`FrameEval`, out parameters), React re-renders never touch the canvas; sky meshes keep ENU geometry under the frozen world matrix P from `sky/math/frames.ts` (ADR-0009); the rotating overlays, labels, marker and centring refresh at <= 10 Hz while follow writes `setView` every frame (plan D139: the frames between overlay ticks would otherwise render the followed object off centre); picking runs on a tap, never per frame; every object direction on the CPU comes from `sky/engine/resolver.ts`.
- Dates: never parse or build a calendar date with `Date` (negative years, years 0..99, brief l.526); TT Julian Date is canonical, `sky/math/time.ts` does the calendar arithmetic, `state/timeDisplay.ts` the display and editing (the zone offset through `getTimezoneOffset` at the instant, `Intl` for the zone name only), years are formatted with an explicit sign. A field that takes a sign (the editor's year, the latitude, the longitude, the elevation) carries `inputMode="text"`, never `numeric` or `decimal`: phone keypads for those two have no minus key (the M7 acceptance fix; the component tests assert the attribute).
