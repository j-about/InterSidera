# Frontend rules (React 19, TypeScript 6, Vite 8, Tailwind 4)

- TypeScript strict with `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `verbatimModuleSyntax`, `erasableSyntaxOnly`: use `import type`, no enums, no namespaces, no parameter properties. ESM only. Typed-array reads are `number | undefined`: use `at()`/`load3()`/`load4()` from `sky/math/typed.ts` or a guard, never `!`, never `as number`.
- ESLint runs `strictTypeChecked` + `stylisticTypeChecked`: `!` non-null assertions and floating promises are errors. Guard instead (`if (!el) throw ...`), and `void` or `await` every promise (`void i18next.init(...)`). `signal.aborted` narrows to `false` across awaits: read it through a function (`const aborted = () => signal.aborted`).
- React 19: function components and hooks only; `ref` as a prop (no `forwardRef`); no `useEffect` for derived state; the React Compiler stays off. UI components (`ui/`) contain no astronomy math and never import `sky/math` (ESLint block F): numbers and dates go through `i18n/format.ts`, calendar work through `state/timeDisplay.ts`, the export instant through `state/snapshotTime.ts`. The store, the frame controller, the tickers and the engine factory are props of `App` and `SkyCanvas`, so tests inject fakes and Babylon never runs under jsdom.
- Layout of `ui/` (plan D112, backlog B-64): `components/` (the primitives Button, IconButton, Switch, Slider, Select, TextField, Tabs, Dialog, Sheet, Banner, Badge, plus Toast and Banners), `shell/` (TopBar, PanelShell, SkipLink, FovPresets, NightControls, ExportButton, HintBanner, EngineContext, useMediaQuery), `observer/` (ObserverPanel, GeoBanner, GeoNotice, BodyPicker, CoordinateForm, PresetList, PlaceSearch), `time/` (TimePanel, TimeReadout, TransportBar, SpeedSelect, StepButtons, DateTimeEditor, CoverageBadges), `panels/` (DetailsPanel, LayersPanel, AboutDialog, VisibleObjects), `controls/` (SearchBox, ShareButton, LanguageToggle), `shortcuts.ts`, `SkyCanvas.tsx`, `BootStatus.tsx`. Every store-bound component (shell, observer, time, panels, controls, Toast, Banners, `SkyCanvas`, `BootStatus`) takes `{ store }` (plus optional test injections) and reads the store itself; the primitives under `components/` are store-free. `components/Toast.tsx` is the single home of transient messages (`ui.toast`, one permanent named `role="status"` region, `showToast(key)` over the closed `ToastKey` union); `components/Banners.tsx` is the single home of the degraded-state and coverage-stop banners (`frames.failing`, a stale catalog, `frames.coverageStop`, a failed engine); the geolocation explanation is `observer/GeoBanner.tsx`. Never render the same fact twice.
- Store ownership (plan D80, D92): one zustand vanilla store (`state/store.ts`, `subscribeWithSelector`) shared by React (`useStore` from `zustand`, `useShallow` from `zustand/react/shallow` for object selectors) and the engine (selector subscriptions with `shallow`). Chrome state is the `ui` slice (`panel`, `sheet`, `dialog`, `stepUnit`, `shortcuts`, `hintDismissed`, `toast`, `lastSpeed`); `geo`, `geocoder`, `details`, `readout`, `labels.visible`, `minorBodies`, `bundle`, `centreRequest` and `follow` are the other session-only slices. Never a second store, never React state for something another component or the engine reads. The engine owns time (`Date.now()` in `SkyEngine.tick`; `publishTt(tt, lstHours)` and `publishReadout` at <= 2 Hz, `setVisibleLabels` at <= 1 Hz on change, `setView` for follow and centring, `clearCentre` are engine-only calls; `stopAtBound` has exactly two callers, the engine's clamp branch while the clock runs (playing or live) and the frame controller's 422 branch); `stepTime` derives its base from `ttAt`, never from the mirror; the camera controller writes `view`; React never selects `view` at animation rate (`FovPresets` selects a derived index) and never drives the canvas. Slice types live in the import-free leaf `state/types.ts`; the store never canonicalises `sel`.
- Engine seam (plan D93): React reaches the engine API only through `SkyCanvas.onEngine` -> `shell/EngineContext.tsx` (`useEngine()`), for event-time calls (`snapshot`); everything the engine acts on over time flows through the store. The label overlay (`labelRoot`, the `aria-hidden` sibling of the canvas rendered by `SkyCanvas`) and the selection marker belong to the engine's `LabelLayer`: React never writes into it, and the engine imports no i18next (texts arrive through the `labelText` option, `i18n/labelText.ts`). The details controller is an engine ticker (`tickers`), not a timer. `<html>` attributes (`data-mode`, `--night-brightness`, `lang`) are written by `state/domSync.ts` from store subscriptions, never by a component.
- Browser timers: `@types/node` is in the app project, so use `window.setTimeout` / `window.clearTimeout` / `window.setInterval` in browser code (a bare `setTimeout` types as `NodeJS.Timeout`).
- Debug hook guard: `debug/skyDebug.ts` is reached only through `await import('../debug/skyDebug')` inside the literal condition `if (import.meta.env.DEV || import.meta.env.MODE === 'e2e')` (plan D86); never import it statically, never reference `__sky` elsewhere in `src/` (the production build is grepped for the string). The `#engine=webgl2|webgpu` hash override is read under the same condition and never serialized; `ShareButton::shareUrl` builds the link from the serialised store, never from `location.href`.
- Every user-visible string goes through `t()` with a key in both `i18n/en.json` and `i18n/fr.json` (UX-1). `scripts/check_i18n.mjs` fails on missing or unused keys and on a dynamic key without a literal prefix: `t(\`constellations.${abbr}\`)`, `bodies.`, `warnings.`, `dsoTypes.`, `layers.`, `kinds.`, `lang.`, `cardinal.`, `observer.latitudeKind.`, `coords.error.`, `geo.`, `geocoder.`, `presets.`, `time.speedUnit.`, `time.step.` (the closed list at M4; a new prefix needs its own subtree in both JSON files); the dynamic keys are typed in `i18n/keys.ts` (`ConstellationAbbr`, `BodyKey`, `KindKey` with guards, `bodyName`, `constellationName`), and a key resolved by a switch keeps one literal `t()` per case (`Toast.tsx::toastText`). English `constellations.*` are the Latin names, the French ones the standard list; the label texts of the engine come from `i18n/labelText.ts`.
- Icons: `lucide-react` only (plan D91). The accessible name goes on the `<button>` (`IconButton` requires `label`, which becomes `aria-label` and `title`), never on the icon: an `aria-*`, `role` or `title` prop on a lucide icon removes its default `aria-hidden` and doubles the name.
- Tailwind CSS-first: configuration lives in `styles/app.css` (`@import "tailwindcss"`, `@theme`, `@custom-variant night`, base rules under `@layer base`). No `tailwind.config.js`; class names are complete literal strings, never concatenated (choose between whole strings in a helper); class order is enforced by prettier-plugin-tailwindcss. Tokens: the `sky-*` family is drawn over the sky and only night mode redefines it; the panel family follows `prefers-color-scheme` (panel surfaces only, backlog B-68). Night mode (plan D108, B-59) redefines the tokens under `[data-mode='night']` with `color-mix(in srgb, <red> calc(var(--night-brightness) * 100%), black)`; a translucent surface bakes its alpha into a switchable token (`--color-panel-bg`, `--color-field-bg`) and `bg-token/NN` is used on opaque tokens only; no CSS `filter` anywhere (not monochrome, a compositor pass per frame, a containing block for fixed elements that top-layer dialogs escape) and no post-process: the sky is tinted by the shaders' `uNight`.
- Accessibility (UX-4): keyboard-operable controls with the one `:focus-visible` token, ARIA names everywhere (`aria-label` on the canvas, the splash, the toast region and the panel; a `title` on every `Banner`, which names its region), state never by colour alone (`Switch` writes On/Off, `Badge` pairs icon and text), targets >= 24 css px (`pointer-coarse:` 44), the native `<dialog>` with `showModal()` for modals, `prefers-reduced-motion` respected (the base rule and the controller's inertia), the skip link first in the DOM; jsx-a11y must stay clean. Single-key shortcuts live in `ui/shortcuts.ts` alone, bail on interactive targets and open dialogs, and stay switchable (`ui.shortcuts`, WCAG 2.2 SC 2.1.4).
- No storage APIs: no cookies, `localStorage`, `sessionStorage` or IndexedDB (OBS-8). The URL query string is the only persisted state (`state/url.ts` codec, `state/urlSync.ts` writer at <= 2 Hz with rounded floats, hash preserved); `ui.*`, `follow`, `geocoder.enabled`, `coverageStop` and the minor-body defaults stay in memory.
- Privacy rounding: latitude and longitude to 0.01 degrees before any API call (`api/client.ts::observerQuery`, OBS-7); the store keeps the typed or geolocated value unrounded and the panel previews the rounded one (`state/coords.ts::roundedObserverPreview`, built on `url.ts`, never on the fetch layer); the geocoder receives the typed text only, never a coordinate; the URL withholds the observer while a geolocation prompt is up.
- Nominatim (OBS-4, plan D97) lives only in `api/geocoder.ts`: one `fetch`, no retry, no cache, `format=jsonv2`, `limit=5`, `accept-language`, `email` when `/meta.geocoder.email` is set, `referrerPolicy: 'strict-origin-when-cross-origin'` (plus the referrer meta of `index.html`); the panel (`observer/PlaceSearch.tsx`) is submit-only, one request in flight, `>= max(min_interval_ms, 1000)` apart, shows the attribution with the OpenStreetMap copyright link and reads 403/429 as `blocked` with a message. Never route Nominatim through `api/client.ts` (it retries 429s).
- Only `import.meta.env.VITE_*` reaches the client; never mirror a `SKYAPI_*` value into a `VITE_*` variable. `__APP_VERSION__` is a Vite `define` (declared in `vite-env.d.ts`).
- API types come from the generated `api/schema.d.ts` (never hand-edited); `api/client.ts` is the single fetch layer for `/api/v1` (typed `getJson`/`getBytes`, `ApiProblem`, `NetworkError`, retry with backoff, `pollHealth`, `getAltAz`, `getMinorDefaults`, `searchMinorBodies`); `api/rateGate.ts` is the one 429 gate the details controller and the minor-body search share; `api/catalogs.ts` loads the catalogs with `cache: 'no-cache'` and ETag comparison. `data/credits.json` is generated by `make notices` and read only through `data/credits.ts`.
- Babylon.js: import from `@babylonjs/core/<module>` subpaths only, and only under `src/sky/engine/` (ESLint enforces both); never the package root, `Legacy/legacy` or the UMD `babylonjs`. Side-effect imports live in `sky/engine/babylon.ts` (WebGL set) and `sky/engine/webgpu.ts` (lazy chunk), one comment per import. Shaders are separate `.glsl`/`.wgsl` twins imported with `?raw`; never `glslangOptions`/`twgslOptions`.
- The render loop belongs to `SkyEngine` (`engine.runRenderLoop`): no allocation per frame, typed arrays and preallocated buffers (`FrameEval`, out parameters), React re-renders never touch the canvas; sky meshes keep ENU geometry under the frozen world matrix P from `sky/math/frames.ts` (ADR-0009); the rotating overlays, labels, marker, follow and centring refresh at <= 10 Hz; picking runs on a tap, never per frame; every object direction on the CPU comes from `sky/engine/resolver.ts`.
- Dates: never parse or build a calendar date with `Date` (negative years, years 0..99, brief l.526); TT Julian Date is canonical, `sky/math/time.ts` does the calendar arithmetic, `state/timeDisplay.ts` the display and editing (the zone offset through `getTimezoneOffset` at the instant, `Intl` for the zone name only), years are formatted with an explicit sign.
